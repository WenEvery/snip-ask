## 5 本地结果与根因（FAILED）

### 5.1 0.5B + 产品 `translate_minimal.md`（术语 26.7%、格式 76.6%、有效 29.2%）

**根因 A：语言变量用 BCP-47 码（`zh-CHS`/`en`）时 0.5B 不翻译。** 同一提示词只把语言码替换为「中文/英文」
（`local-tiny-minimal-names` 诊断臂），译文有效率从 **29.2% → 66.7%**，术语 26.7% → 46.7%；但格式率不变（76.6%）。
逐例证据：`zh-en-02-multiline` 输出仅首行 `设置已保存。`（5 token 即 EOS）；`zh-en-12-long` 原样复述中文。

**根因 B：0.5B 对术语表与格式指令遵循弱。** 典型：`zh-en-09-term-heavy` 输出仍为中文原文；
`zh-en-01-plain` 直接把术语行当答案输出 `框选 AI => SnipAsk`；占位符多数能保留（3/3），但列表/空行不稳定
（`bullets_min` 1/2、`blank_lines_min` 0/2）。

### 5.2 0.5B + 产品长提示词 `translate.md`（术语 0%、有效 20.8%）

完全复现 S-05 结论：0.5B 用长提示词**复述原文/只输出首行**，术语 0/15。例：`zh-en-02-multiline` 输出
`设置已保存。重新启动应用后生效。如需帮助请查看文档。`（原文，未翻译）。→ 与 S-05 一致：极小模型不能用长提示词。

### 5.3 末尾追加格式守卫句是**有害**的（术语 26.7%、格式 70.2%）

在 `{text}` 之后追加「保留原文的换行、空行……」会把守卫句本身当正文翻译/复述（如输出末尾出现英文版守卫句），
格式率反而从 76.6% 降到 70.2%。**格式约束必须放在正文之前，不能追加在正文后。**

### 5.4 1.5B + 产品 `translate_minimal.md`（术语 100%、格式 68.1%）—— 唯一接近达标的本地配置

- **术语 15/15 = 100%、译文有效 24/24 = 100%**（1.5B 能正确理解 `zh-CHS`/`en` 语言码并按术语表翻译）；
- **格式 32/47 = 68.1%**：失败几乎全部来自 `lines_exact`（2/16）——模型**把「术语表（可为空；命中时按指定译法）：」
  这一行连同术语内容一起复述进译文**，导致每条输出比原文多 1 行。其余格式项基本通过：
  `contains 23/23`、`bullets 2/2`、`numbered 2/2`、`code_fences 2/2`、`blank_lines 1/2`。
- 代表失败样例（`zh-en-02-multiline`）：
  > `Term List (may be empty; applied when matched):`（多出的行）
  > `Settings saved.`
  > `Effective after restarting the application.`
  > `For assistance, refer to the documentation.`

**这是一个可定位、可修复的提示词结构缺陷**：`translate_minimal.md` 把「术语表」单独成行且位于正文之前，
模型把它当成待翻译内容的一部分。

### 5.5 处置复核候选（v2 / v3）：改善但未达 100%

| 候选 | 设计 | 1.5B 结果 | 结论 |
| --- | --- | --- | --- |
| v2 | 语言名称 + 术语并入指令 + `<<< >>>` 包裹正文 + 前置格式约束 | 术语 60.0%、格式 89.4%、有效 79.2%、整例 10/24 | 格式改善但**术语回退**；模型还会把 `<<<`/`>>>` 复述进输出（`zh-en-03/04/10`），未采用 |
| **v3** | 只修结构：术语并入第一条指令句、保留语言码、无分隔符/无守卫句 | **术语 80.0%、格式 87.2%、有效 91.7%、整例 16/24** | 本地最优，但仍有 3 条术语未命中（`接口`/`引导`/`结果窗` 被译成其他说法/保留英文）与 4 条换行合并 → 未达 100% |

v3 失败样例（`en-zh-12-long`）：`……所有操作均在 Result Window 中显示……`（术语 `结果窗` 未命中）；
`zh-en-02-multiline`：模型把前两行合并为一行（`lines_exact` 失败）。

**结论：本地 0.5B/1.5B + 现有/候选精简提示词都无法稳定达到「术语 100% + 格式 100%」。**
这符合小参数模型的能力边界，需要在产品层做「结构化后处理 + 校验重试」或明确降级承诺（§9）。

## 7 结果是否标注所用后端（代码事实）

**结论：产品契约已有「后端」标注，但粒度不足；基准脚本侧完整标注。**

| 证据 | 位置 | 事实 |
| --- | --- | --- |
| 任务结算携带实际引擎 | `src-tauri/src/services/llm_gateway.rs:58-67` | `TaskOutcome { usage, latency_ms, engine: EngineId, sources }`——结算时返回**实际使用的引擎** |
| 事件载荷携带引擎 | `src-tauri/src/contract/types.rs:361-388` | `task:started` 与 `task:done` 均含 `engine` 字段 |
| 历史库落库 | `src-tauri/src/services/history_repo.rs:117-160` | `record_task(..., engine: Option<&str>, ...)` 写入 `tasks.engine` 列 |
| 结果窗展示 | `src/windows/result/ResultHeader.tsx:24`、`ResultWindow.tsx:79,297` | 结果头部渲染 engine chip；底部显示「引擎 {done.engine}」 |
| 路由决定引擎与提示词 | `src-tauri/src/services/action_router.rs:84-112,159-172` | 云端→`provider_id`（如 `deepseek`）、本地→`"local"`；`translate_prompt_key()` 已按模型 id 把极小模型路由到 `translate_minimal` |
| 粒度缺口 | 同上 + `domain/task.rs:59`、`contract/config.rs:500` | `engine` 只到「供应商/本地」级别，**不含模型名与提示词变体**；内存 `TaskRecord` 无 engine；`TranslatePrefs.backend` 只是配置 |
| 真实网关未接入 | `services/translator.rs:35-57`（`SkeletonTranslator`）、`llm_gateway.rs:226` | 翻译仍为骨架占位（`TODO(real)`），`SkeletonLlmGateway` 返回 `engine="skeleton"` → 接入前结果窗显示 `skeleton` |

**建议**：`TaskDonePayload` 增加 `model` 与 `promptKey`（或 `backendLabel`）字段并写入历史库，使结果/历史能显示
「云端 deepseek-flash / 本地 Qwen2.5-0.5B（精简提示词）」而非仅 `deepseek`/`local`/`skeleton`。

## 8 结论与阈值对比

| 阈值 | 要求 | 云端 | 本地（最优） | 判定 |
| --- | --- | --- | --- | --- |
| 术语命中率 | 100% | **100%**（15/15） | 100%（15/15，1.5B minimal）但格式不达标 | 云端 DONE / 本地 FAILED |
| 格式保留率 | 100% | **100%**（47/47） | **68.1%**（1.5B minimal；v3 87.2%） | 云端 DONE / 本地 FAILED |
| 结果标注所用后端 | 标注 | `engine` 字段已贯穿事件/历史/UI（§7） | 同左，但缺模型/提示词粒度；真实网关接入前为 `skeleton` | **部分满足** |

**S-14 总结论：FAILED（本地一致性未达标）**；云端路径满足验收阈值。若产品接受「云端默认 + 本地显式降级提示」，
则需把 S-14 的验收口径改为「云端 100% + 本地标注降级」，并将本地一致性列为已知限制。

## 9 处置建议

1. **云端保持 `translate.md`**：本批 24 条术语/格式双 100%，可直接作为默认翻译路径。
2. **本地 1.5B 提示词结构修复（优先落地，成本低）**：把 `translate_minimal.md` 的
   「术语表（可为空；命中时按指定译法）：{glossary}」从**独立正文行**并入第一条指令句，避免被复述
   （v3 实测：格式 68.1% → 87.2%，整例 10/24 → 16/24；但术语 100% → 80%，需同时保留术语表原文）。
   建议在 `prompt_engine` 层给极小模型做**结构化渲染**（如 `<glossary>`/`<text>` 标签 + 明确「只翻译 text 标签内容」），
   而不是纯文本拼接。
3. **本地一致性靠「后处理 + 校验」兜底**（小模型无法 100% 可靠）：
   - 术语：译后扫描术语表，命中译文若缺失则**强制替换/回填**（术语 usually 是专名，替换安全）；
   - 格式：按原文行结构逐段翻译（逐段调用或要求「逐行对齐输出」）+ 译后行数校验，不一致则重试/回退云端；
   - URL/邮箱/占位符：正则抽取原文中这些片段，译后逐一校验并在缺失时回填。
4. **产品降级承诺**：本地翻译结果必须标注「本地译文（可能不保证格式/术语）」并提供「用云端重试」入口；
   不建议把 0.5B 作为默认翻译后端（S-05 结论一致）。
5. **后端标注补全**：按 §7 建议在 `task:done` 与历史库增加 `model` / `promptKey`。
6. **验收口径澄清**：S-14 原始阈值（术语 100% + 格式 100%）对本地小模型不现实；建议拆为
   「云端 100%」+「本地：术语/格式 ≥95% 且 100% 标注后端与降级」两档（与 S-05 的档位口径一致）。
