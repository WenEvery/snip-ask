## 2 被测口径

- **链路**（4 阶段）：①视觉识别（图片→文字/结论）→ ②生成检索词 → ③Search（quick 1 次、deep 2–3 次）→ ④摘要（结论 + 来源）。
- **提示词**：`resources/prompts/image_search.md`（版本 1，sha256 `03a119ed…3aad`）正文按阶段拆分（阶段①识别+检索词；阶段④结论+来源）。
- **模型接口**：OpenAI 兼容 chat/completions，vision 消息用 base64 data URL；检索服务 `SNIPASK_BENCH_SEARCH_PROVIDER` 选择 `tavily` / `serper`。
- **判定阈值**：快速模式 **≤10s**；深度模式 **≤25s**（P95，端到端）。
- **口径说明**：本轮为 **PARTIAL** 测量（视觉/摘要真实调用，Search 用 mock），结果标注
  `PARTIAL_REAL_VISION_MOCK_SEARCH`，**不构成 S-06 验收结论**；真实验收仍缺 Search Key。

## 3 能力探测（DeepSeek，真实 HTTP 响应）

`python scripts/spikes/s05_s06/probe_s06_negative.py`（Key 仅运行时环境变量传入，响应体落盘不含鉴权头）：

| 探测 | 结果 | 证据 |
| --- | --- | --- |
| `GET /models` | 200 | 可用模型：`deepseek-flash`（`input_modalities=["text","image"]`）、`deepseek-v4-pro`（`["text"]`） |
| 图片消息 → `deepseek-flash` | **200，识别成功** | 回复原文：「框选AI的AI服务设置页，包含DeepSeek供应商的API配置项。」（推理内容中正确列出窗口标题「框选AI - 浏览器预览·骨架模式」、侧栏「设置/首次启动」、主区域「设置→AI服务」等，见原始 JSON `reasoning_content`） |
| 图片消息 → `deepseek-v4-pro` | 200 但**看不到图片** | 回复：「无法查看图片，请重新上传或提供文字内容。」（`prompt_tokens=102`，未计入图片 token，说明图片被忽略） |
| `POST /search` | **404** | 无响应体 |
| `GET /search` | **404** | 无响应体 |
| `POST /v1/search` | **404** | 无响应体 |
| `POST /search/completions` | **404** | 无响应体 |

**结论（与任务预设不同，以实测为准）**：

1. DeepSeek **不是**「完全不支持视觉」：`deepseek-flash` 接受 OpenAI 兼容图片消息，并能正确识别真实截图内容，
   **可以承担 S-06 的①视觉识别腿**（需产品侧确认图片上传隐私开关、费用与稳定版模型名）。
2. DeepSeek **没有任何 Search API 端点**（全部 404），即 S-06 的③检索腿无法用该 Key 完成；
   没有检索结果就无法满足产品「带来源结论」要求。
3. 因此 **S-06 仍 BLOCKED**：最小 Key 组合 = `DeepSeek Key（已有，作 vision 模型）+ 1 个搜索 API Key（Tavily/Serper/Bing 等）`。
   不需要额外视觉 Key，**只差搜索 Key**（若换用 OpenAI/Qwen-VL 作 vision，则需 vision Key + search Key 两个）。

## 6 最小 Key 组合与 15 分钟复跑清单

**最小 Key 组合（只差 1 个）**：DeepSeek Key（已有）+ 搜索 API Key（Tavily 或 Serper）。

| 时间 | 操作 |
| --- | --- |
| 0–2 min | 注册任一搜索 API（Tavily / Serper）拿到 Key；无需再找视觉 Key（用 DeepSeek 即可）。 |
| 2–3 min | 设置环境变量（见下），**不要**再把 Key 写入任何文件。 |
| 3–5 min | 冒烟：quick 2 次 + 检查 JSON 里 `vision_output`/`sources` 是否为真实 URL；若 DeepSeek 视觉偶发空内容，调大 `max_tokens` 或改用支持 vision 的模型。 |
| 5–8 min | quick 20 次（预计 2–3 分钟）。 |
| 8–14 min | deep 20 次（预计 3–6 分钟）。 |
| 14–15 min | 汇总并回填本文 §5（真实 P50/P95、搜索服务名、失败率）；同步更新 `summary_s05_s06.json`。 |

```powershell
# 视觉腿：复用已提供的 DeepSeek Key（运行时环境变量，勿写文件）
$env:SNIPASK_BENCH_VISION_BASE_URL = "https://api.deepseek.com"
$env:SNIPASK_BENCH_VISION_MODEL    = "deepseek-flash"
$env:SNIPASK_BENCH_VISION_API_KEY  = "<DeepSeek Key>"
$env:SNIPASK_BENCH_VISION_EXTRA_JSON = '{"thinking":{"type":"disabled"}}'  # 降低首字延时（可选）
# 检索腿：只缺这个
$env:SNIPASK_BENCH_SEARCH_PROVIDER = "tavily"        # 或 serper
$env:SNIPASK_BENCH_SEARCH_API_KEY  = "<搜索 API Key>"

python scripts/spikes/s05_s06/bench_image_search.py --modes quick,deep --runs 20
# 若只用 mock search 估算视觉腿：--allow-mock-search（标注 PARTIAL，不得作为验收结论）
```
