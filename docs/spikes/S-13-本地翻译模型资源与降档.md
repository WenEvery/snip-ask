## 结论

**IN PROGRESS**（本轮新增证据明确，但两项验收仍未闭合：**8GB 机型降档提示产品缺失** + **内存不足 OOM 行为未能在本机复现**）。

本轮新增：

1. **本机复核（15.78 GiB / i7-12650H / 纯 CPU，与本机 S-05 同款 llama.cpp 后端）**：
   极小档 0.5B 常驻 WorkingSet **520.8 MB**、冷加载 **1.96s**；1.5B 候选 **1715.3 MB / 3.39s**；
   普通档 1.8B **2102.4 MB / 5.68s**（与 S-05 的 0.51–0.55 GiB / 1.70 GiB / 2.05–2.10 GiB 一致；
   加载耗时含进程启动与 /health 轮询开销，见「说明」）。
2. **8GB 场景模拟（Windows Job Object 进程内存上限）**：`SetInformationJobObject` 成功、
   `AssignProcessToJobObject` 成功（`jobAssigned=true`），但**限额在本机未被内核强制执行**：
   给 llama-server 设 **200 MB** 上限、0.5B 模型仍加载成功（Private **660 MB** > 200 MB 仍存活）；
   6 GB / 8 GB / 2.5 GB / 1.5 GB / 1 GB / 512 MB 上限全部「正常加载」。
   → 该手段在本机**无法复现真实 OOM**，故「内存不足不崩溃 / 可返回错误」本轮**未能实测**（见「遗留 L-2」）。
3. **降档判定表**（按 `resources/models.manifest.json` 的 `minRamMB`，口径：允许上限 = 系统内存 × 50%）：
   8GB 机型 → 极小档 1024MB ✅、HY-MT 1.8B 4096MB ⚠️（允许但提示内存偏紧）、qwen3-4b 8192MB ❌（降档/禁止）；
   16GB 机型 → 极小档 ✅、HY-MT ✅、qwen3-4b ❌（minRamMB=8192 > 8072MB 预算，建议标注「需 16GB 以上专用」）。
4. **前端降档提示现状（静态 + 实机截图）**：引导第 3 步/设置模型库只展示**静态** `需内存 {minRamMB} MB`
   与三档固定文案；源码检索 `src/` **没有任何** `navigator.deviceMemory` / 运行时内存比较，
   即 **8GB 机型不会得到动态降档或切云端提示** → 产品缺口确认（本轮不改前端代码，只给建议）。

## 处置

- 常驻内存/加载耗时：复用 S-05 数据 + 本轮复核一致，可写入实现边界（0.5B ≈0.52GiB、1.5B ≈1.7GiB、1.8B ≈2.1GiB）；
- **建议（产品/前端，需另立任务，本轮不改代码）**：
  1. 设置页/引导页读取 `navigator.deviceMemory`（或后端上报 `Win32_ComputerSystem` 物理内存），
     与模型 `minRamMB` 比较，8GB 机型默认推荐极小档并提示「1.8B 在本机约需 2.1GB 常驻，可能影响其它应用」；
  2. 内存不足时的降级链：本地模型启动失败/超时 → 明确提示「本地模型内存不足，已切换到云端/可重试」，
     并在 `translator` 回退链里接入（当前 `translate.backend=local` 失败后是否回退云端需产品确认）；
  3. llama-server 启动失败（非零退出码/健康检查超时）必须在应用层转换为可操作错误，而不是 UI 卡住。
- **OOM 复现手段的替代建议**：Job Object 在本机不生效，可改用
  ① 在 8GB 实机（真实低内存）验证；② 用 `--load-mode`/超小 `-c` 参数人为放大内存占用；
  ③ 在 CI 用 `Windows Job Object` 的 32 位进程或 `SetProcessWorkingSetSizeEx` 辅助验证——需另立 spike。

## 说明（测量口径差异）

- 本轮「冷加载」= `Process.Start` → `/health` 首次 200，包含 llama-server 进程初始化 + 250ms 轮询粒度；
  S-05 的 1.34–1.44s 为更细粒度打点且可能命中系统文件缓存，故本轮 0.5B/1.5B 加载值偏高（1.96/3.39s）；
  两者**量级一致**，不改变「加载 < 8s 阈值另计」的结论；常驻内存为进程稳定后 2s 采样，与 S-05 一致（±1%）。
- 每档测量后均确认 `Get-Process llama-server` 残留 = 0；`--no-mmap` 在 llama.cpp 2.28.2 已标记 DEPRECATED
  （建议后续用 `--load-mode`），本轮仅用于尝试触发 OOM。
