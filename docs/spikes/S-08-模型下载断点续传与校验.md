## 3 实现说明

### 3.1 分层与可测性

真实下载核心是**与 Tauri 无关的纯函数**（`model_manager.rs`）：

```rust
pub async fn download_with_resume<F>(
    client: &reqwest::Client, urls: &[String], dest: &Path,
    expected_size: u64, expected_sha256: &str,
    cancel: &AtomicBool, retry: &RetryPolicy, on_progress: F,
) -> Result<DownloadOutcome, DownloadError>
where F: FnMut(DownloadProgress);
```

`ModelManager` 只负责：状态机（queued → downloading → verifying → installed/failed/cancelled）、
`download:progress` 节流（≤200 ms，loaded 事件侧钳制单调）、`download:state` 推送、`.installed` 标记写入。
因此集成测试可直接用本地 `TcpListener` HTTP server 验证，不需要 `AppHandle`。

### 3.2 行为要点

- **临时文件**：`<models_dir>/<id>/<file>.partial`，大小/哈希全部通过后 `rename` 为最终文件；
  `.installed` 只由 manager 在成功后写（空文件，兼容既有 `scan_installed`），`.partial` **不计入** installed。
- **断点续传**：`.partial` 存在 → 发 `Range: bytes=<len>-`；206 校验 `Content-Range` 起点，续写；
  服务端 200（忽略 Range）→ 丢弃断点从头写；416 且断点 ≥ 期望大小 → 对现有文件算哈希走校验。
- **重试与镜像回退**：单 URL 独立重试（默认 3 次，200 ms 起 ×2 指数退避，封顶 2 s）；
  5xx/408/429/网络错误重试；404 与其他 4xx 立即切换下一个镜像；全部失败 → `failed`（保留 `.partial` 供下次续传）。
- **流式 SHA256**：首块起逐块 `update`；续传时先把已有前缀**流式重读**喂给 hasher（进程被杀后 hasher 状态丢失，
  重读是恢复正确性的关键），因此无需下载完成后再全文件二次扫描。
- **校验失败处置**：大小/SHA256 不符 → 删除 `.partial` → **整轮重下一次**（最多 2 轮）→ 仍失败则 `failed`。
- **取消**：`download:cancel` 置 `AtomicBool`，chunk/重试/哈希读前后检查；返回 `Cancelled` 时**保留 `.partial`**，
  状态 `cancelled`，下次下载自动续传。
- **HTTP 客户端**：UA=`snip-ask/<version>`、connect timeout 15 s、整体 timeout 60 min；
  实测 ModelScope/Aliyun CDN **对无 User-Agent 请求返回 403**，UA 必须设置（见 §6.3）。
- **骨架模式**：`ModelManager` 新增 `skeleton_mode: Arc<AtomicBool>`（默认 `true`）与
  `set_skeleton_mode(bool)`；为 `true` 时走原骨架下载（每 100 ms 4%、空 `.installed`），代码逐字保留。

## 6 关键发现

### 6.1 模型清单未校验，且 URL/文件名/大小/SHA256 与官方仓库不一致（重要）

清单头 `"verified": false`，三个模型的 `sha256` 均为 64 个 0；进一步用 ModelScope 文件列表 API 核对，
发现**文件名与大小也不正确**，清单 URL 全部 404（原始数据：`.verify/spikes/S-08/modelscope_api_*.json`）：

| 模型 | 清单 URL 中的文件 | 清单 sizeBytes | 官方实际文件 | 实际大小 | 实际 SHA256 |
| --- | --- | --- | --- | --- | --- |
| `hy-mt-1.8b-q4` | `hy-mt-1.5-1.8b-q4_k_m.gguf`（404） | 1 258 291 200 | `HY-MT1.5-1.8B-Q4_K_M.gguf` | 1 133 080 512 | `4383ac0c…cc477c7` |
| `qwen3-4b-q4` | `qwen3-4b-q4_k_m.gguf`（404） | 2 684 354 560 | `Qwen3-4B-Q4_K_M.gguf` | 2 497 280 256 | `7485fe6f…34fdf5` |
| `opus-mt-zh-en` | `ct2-int8.zip`（404） | 314 572 800 | 仓库无 ct2-int8.zip（仅有 `pytorch_model.bin` 312 087 009 / `tf_model.h5` / `rust_model.ot`） | — | — |

影响：在清单被修正前，**真实下载路径会对清单 URL 直接 404**；即使换成正确 URL，也会因 `sizeBytes` 不符而
被大小校验 fail-closed（这是刻意设计：宁可不装也不装错）。**修清单属于 `resources/models.manifest.json`
（不在本任务写入范围），需另行安排**（建议同时补 `verified=true`、大小、SHA256）。
另：HuggingFace 主源在本机不可达，`urls[0]` 的 HF 文件名同样是小写旧名，接线真实下载时需按官方仓库校正。

### 6.2 镜像回退必要性

HuggingFace 8 s 超时不可达；ModelScope 302 到 `cdn-lfs-cn-1.modelscope.cn` 后支持 Range。
说明清单「HF 主源 + ModelScope 镜像」的顺序在当前网络下**必须依赖回退**，S-08 的回退实现与测试正好覆盖。

### 6.3 无 User-Agent 会被 403（已修复在客户端）

对照实验（`.verify/spikes/S-08/uatest_*.headers.txt`）：`UA=snip-ask/0.1.0` → 206；
**无 User-Agent → 403**；`Accept` 头不影响。生产客户端 `build_http_client()` 已设置
`User-Agent: snip-ask/<version>`；测试客户端同样设置，否则真实网络联调会 403。

## 8 遗留与风险

1. **清单未校验（最高优先）**：`resources/models.manifest.json` 的 URL 文件名/大小/SHA256 与官方不一致，
   真实下载在修正清单前必然 404 或大小校验失败。需清单 owner 修正并用真实文件回填 SHA256（可参考 §6.1 数据与
   `X-Linked-ETag`）；修正后建议将 `verified` 置 true 并在 CI 校验。
2. **生产接线（已由 Lead 完成）**：`ModelManager::set_skeleton_mode(bool)` 已就绪（默认 true 保持骨架行为）；
   Lead 已在 `AppState::initialize` 读取 `advanced.skeletonMode` 后注入
   （`models.set_skeleton_mode(loaded.config.advanced.skeleton_mode)`，在 `loaded.config` move 前取值），
   并在 `app::state` 单测中断言 `state.is_skeleton() == state.models.is_skeleton_mode()`（全仓测试通过）。
   接线后：默认配置仍走骨架下载（契约 §12，S-07 依赖），仅当用户把 `skeletonMode` 设为 false 时启用真实下载。
3. **断点一致性校验未做**：续传只用本地长度 + 服务端 Range，未校验远端文件是否已更新（建议后续加
   `If-Range: <ETag>` 或比对 `X-Linked-ETag`/`Last-Modified`；ModelScope CDN 已返回二者，具备接入条件）。
4. `advanced.proxy` 代理配置尚未接入下载客户端（`TODO(real)`）；企业代理环境下真实下载可能不可用。
