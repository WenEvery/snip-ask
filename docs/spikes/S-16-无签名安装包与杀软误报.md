## 4 验证步骤

1. **静态签名/扫描**：`Get-AuthenticodeSignature` + `Get-FileHash`；`MpCmdRun -Scan -ScanType 3 -File <file> -DisableRemediation`
   分别扫描 setup 与主 exe（`-DisableRemediation` 关闭处置动作，避免扫描时隔离/删除待验证产物；真实用户场景下若命中 Defender 会处置，结论在 §5.2 说明）；前后读取 `Get-MpThreatDetection` 计数；
2. **MOTW**：复制 setup 到 `.verify`，用 `Set-Content -Stream Zone.Identifier` 写入 `ZoneId=3`（模拟“从网络下载”），
   `Get-Item -Stream *` 与 `Get-Content -Stream` 回读确认；用该副本静默安装一次观察是否被阻断（随后卸载清理）；
3. **真实安装**：`Start-Process setup.exe -ArgumentList /S -Wait`（currentUser 默认目录，影响最小化：仅用户目录 + 用户级快捷方式）；
   安装前后快照注册表卸载项、安装目录、开始菜单/桌面快捷方式、HKCU Run、应用数据目录；
4. **启动**：启动已安装版，检查日志「框选 AI 初始化完成」、EnumWindows 窗口（主窗/结果窗/托盘/热键/单实例）、
   进程存活与内存；尝试 `WM_CLOSE` 关闭（托盘应用行为），必要时强制结束进程树；
5. **卸载**：`uninstall.exe /S`，轮询卸载项与主 exe 消失；卸载后快照对比残留（安装目录/注册表/快捷方式/Run/应用数据/WebView2）；
6. **旁证**：在 applab 便携实例运行时启动已安装版 → 作为第二实例立即退出（单实例设计，非启动失败）。

## 6 关键发现

### 6.1 默认安装目录与本地数据目录重合（真实风险，建议改）

- `tauri.conf.json`：`bundle.windows.nsis.installMode = "currentUser"`；生成的 NSIS 模板（`src-tauri/target/release/nsis/x64/installer.nsi` 第 539–540 行）：
  `StrCpy $INSTDIR "$LOCALAPPDATA\${PRODUCTNAME}"` → 默认安装目录 **`%LOCALAPPDATA%\SnipAsk`**；
- 而应用本地数据目录（`src-tauri/src/platform/paths.rs`）在安装态同样是 **`%LOCALAPPDATA%\SnipAsk`**（`models/cache/runtime`），
  `%APPDATA%\SnipAsk` 存配置/日志/历史；
- 后果：
  1. 安装目录与应用数据目录混用（可共存但不干净，用户/杀软/备份工具难以区分程序与数据）；
  2. 卸载器 `RMDir "$INSTDIR"`（非递归）在有数据时失败，**安装目录残留**（本次实测即如此）；
  3. 若未来数据目录用同名子目录（如 `%LOCALAPPDATA%\SnipAsk\uninstall.exe` 误删风险等），存在进一步耦合风险；
- 建议（需产品/构建改动，不在本次允许改动范围内）：NSIS `$INSTDIR` 改为 `%LOCALAPPDATA%\Programs\SnipAsk`
  （或 `ProgramFiles` + perMachine，但 currentUser 更符合免提权定位），并在 `tauri.conf.json`/自定义 NSIS 模板中固化；
  同步更新本文与 S-18 记录。

### 6.2 卸载残留策略

- NSIS 卸载器**只删除自己安装的文件**（主 exe、卸载器）+ 非递归 `RMDir`；`%APPDATA%\SnipAsk`、`%LOCALAPPDATA%\SnipAsk` 中的数据不删；
- WebView2 用户数据 `%LOCALAPPDATA%\com.snipask.app` 仅当用户勾选“删除应用数据”（`$DeleteAppDataCheckboxState=1`）时才删；
  静默卸载默认**不删**；
- 结论：当前卸载**不会损坏用户数据**（好），但会留下目录与 WebView2 缓存（约占空间、体感“卸载不干净”）。
  建议产品决策：卸载 UI 提供默认勾选的“同时删除本地数据/缓存”，并明确提示；静默卸载保持不删（安全）。

### 6.3 未签名说明与签名建议

- `SECURITY.md` §已知限制已有：「无代码签名证书时 Windows SmartScreen 可能拦截安装包」——满足 S-16「未签名时给出说明」的最低要求；
- 建议增强（本次不允许改其它仓库文件，给出可粘贴文案与落点）：
  - 落点：`README.md`「下载/安装」节 + 发布页说明；
  - 文案：「当前 0.1.x 安装包**尚未做代码签名**。从网络下载后首次运行，Windows SmartScreen 可能提示“Windows 已保护你的电脑”；

## 9 复跑命令（Windows PowerShell 5.1）

```powershell
# 0) 前置：确认没有其它 snip-ask 实例（applab 便携实例也会抢占单实例）
node scripts/spikes/applab/applab.mjs status
Get-Process -Name snip-ask -ErrorAction SilentlyContinue

# 1) 签名 / Defender 扫描 / MOTW 证据（只读 + 生成 MOTW 副本，不修改系统）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/spikes/s10_s16_s18/s16_scan_signature.ps1

# 2) 真实安装 / 启动 / 卸载 / 残留（会真实安装与卸载；默认 currentUser 用户目录）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/spikes/s10_s16_s18/s16_install_test.ps1
#   如需装到临时目录（避免与 %LOCALAPPDATA%\SnipAsk 应用数据重合）：
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/spikes/s10_s16_s18/s16_install_test.ps1 -InstallDir "$env:TEMP\snipask-s16"

# 3) 手工复核（本次实测同样以这些命令取证）
Get-AuthenticodeSignature src-tauri/target/release/bundle/nsis/SnipAsk_0.1.0_x64-setup.exe | Format-List Status
& 'C:\Program Files\Windows Defender\MpCmdRun.exe' -Scan -ScanType 3 -File (Resolve-Path 'src-tauri/target/release/bundle/nsis/SnipAsk_0.1.0_x64-setup.exe').Path -DisableRemediation
Get-Item .verify/spikes/S-16-S-18/s16/motw/SnipAsk_0.1.0_x64-setup.exe -Stream *
Get-Content .verify/spikes/S-16-S-18/s16/motw/SnipAsk_0.1.0_x64-setup.exe -Stream Zone.Identifier
```

> 脚本说明：`s16_install_test.ps1` **默认先装带 MOTW 副本、失败再装原包**，本次实测为避免重复安装/卸载，

> 两条路径的证据分别为 `install_evidence.json`/`launch_measure.json`/`uninstall_evidence.json` 与 `motw_install_test.json`。
> 脚本在无人值守环境可能因 SmartScreen 提示挂起安装器：脚本会在检测到安装成功后终止挂起的安装器进程并记录（避免卡死）。
