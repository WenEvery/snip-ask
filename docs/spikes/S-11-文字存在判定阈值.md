## 1 目标与验收阈值

清单要求：收集 100 张含少量文字/图标/纹理的截图，跑 det 后按「面积 / 置信度 / 行数」阈值判定「有文字」，
误判（无文字判为有文字）**≤5%**、有文字漏判 **≤5%**，且**阈值可配置**。

本轮把「有文字」定义成可执行的纯逻辑判定：

```text
pass(box) = det_score >= min_conf
            且 box_area_px >= min_area
            且 (可选) box_area_px <= max_area
            且 (可选) box_height_px <= max_box_height
hasText  = count(pass) >= min_lines
```

- 面积/行高都取**还原到原图物理像素**后的轴对齐框（`w×h`，高=`y` 方向边长），与 `ocr_service.rs::filter_boxes`
  的 `bbox` 语义一致；
- `det_score` 是 PP-OCRv4 DB 输出的框置信度（RapidOCR 的 `TextDetector.__call__` 会丢弃它，本脚本直接调用其
  `preprocess/infer/DBPostProcess` 保留分数，不重写预处理；测量时 `box_thresh=0.05` 让低分框进入统计）；
- 产品当前 `presence()` 等价于「`box_thresh=textThreshold=0.6` 的框数 ≥1」，没有任何面积/行数/行高阈值。

### 2.1 真实渲染截图（100 张，S-11 取其中 50 张）

- 用 **headless Edge** 渲染自建 HTML 页面：`网页 / 聊天 / 文档 / 代码 / 深色模式` 各 **20 张**，中英混排，
  尺寸覆盖 2560×1440（50 张）、1920×1080（20）、2880×1620（10）、3440×1440（10）、1920×1200（10）。
- 每类最后 2 张是**低文本量页**（稀疏设计）：网页 sparse 页只保留 3 行 known 文本（上方是图标密集的功能卡
  装饰，无文字），其余类别的稀疏页只保留 3–8 行文本（如聊天 sparse 仅 5 行消息、深色 sparse 仅 8 行设置项），
  用于检验漏判；S-11 的 50 张真实样本 = 每类 8 张常规 + 2 张稀疏。
- 页面为**单列自上而下绝对定位**（DOM 顺序 == 视觉 y 顺序），每行文本都是页面里真实可见的 `.tr` 元素，
  构造真值就是这些行的文本。渲染时**同一次 Edge 调用**内执行页面 JS 做三重校验并写入 `<title>`：

| 校验 | 做法 | 结果 |
| --- | --- | --- |
| 文本一致 | `body.innerText` 去空白后与嵌入真值字符串逐字符比较 | **100/100 通过**（`inner_match=true`） |
| 无裁切/隐藏 | 每个 `.tr` 的 `getBoundingClientRect()` 必须完全落在视口内；`scrollWidth/Height ≤ 视口` | **0 个 bad rect、100/100 通过** |
| 尺寸一致 | 截图按 JS 报告的 `innerWidth/innerHeight` 裁剪 | 100/100 一致（视口尺寸 == 目标分辨率） |

> 说明：页面里没有任何 `overflow:hidden`、`text-overflow:ellipsis`、`display:none` 或脚本动态改写文本，
> 因此「DOM 可见文本 == 截图文本」不依赖人工目测；此外人工抽检 10 张（每类 2 张）与真值逐行核对一致。

## 3 方法

1. **S-11 阶段 A（det）**：对 100 张图逐张跑整屏 det（生产像素预算口径）；保留每个框的 `x/y/w/h`、轴对齐面积
   `area`、DB 置信度 `score`。det 耗时仅作记录（本任务不验收时延）：100 张共 **79.4s**（含合成噪声图较多框的后处理）。
2. **S-11 阶段 B（sweep）**：在缓存框上做三族阈值网格扫描，共 **2276 组**：
   - 家族 A（清单原义：面积只设下限）：`conf × min_area × lines`，966 组；
   - 家族 B（面积区间）：`conf × min_area × max_area × lines`，960 组；
   - 家族 C（面积下限 + 行高上限）：`conf × min_area × max_box_height × lines`，350 组。
3. **指标**：`误判率 = FP / 50`（50 张无文字图）、`漏判率 = FN / 50`（50 张有文字图）、`accuracy=(TP+TN)/100`。
4. **推荐选择原则**（写进脚本，避免只看单一指标）：满足误判≤5%、漏判≤5% 的候选中按
   ①漏判更低 ②置信度=产品默认 0.6 ③行数=1（单行页面不漏） ④行高上限更大 ⑤面积下限在 300–500 px²
   ⑥误判更低 ⑦参数更少 排序取第一。
5. **基线**：产品现状口径 `det_score≥0.6`、面积 0、行数 1（即当前 `presence()` 语义）。

## 4 结果

### 4.1 头条数字（100 张 = 50 正 / 50 负）

| 判定口径 | 阈值 | TP | FP | TN | FN | 误判率 | 漏判率 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| **产品现状**（仅置信度） | `det≥0.6` | 50 | 19 | 31 | 0 | **38.0%** | 0.0% | **不达标** |
| 清单三阈值原义（只设面积下限，最佳） | `det≥0.6, area≥1000, lines≥3` | 50 | 9 | 41 | 0 | **18.0%** | 0.0% | **不达标** |
| 备选（纯三阈值，面积区间） | `det≥0.65, 1000≤area≤5000, lines≥1` | 50 | 1 | 49 | 0 | **2.0%** | 0.0% | 达标（大字号页风险，见 §4.4） |
| **推荐（面积下限 + 行高上限）** | **`det≥0.6, area≥400, h≤70, lines≥1`** | 50 | 1 | 49 | 0 | **2.0%** | **0.0%** | **达标** |
| 更保守（推荐阈值收紧面积） | `det≥0.6, area≥1000, h≤70, lines≥1` | 50 | 0 | 50 | 0 | **0.0%** | 0.0% | 达标（小字页风险，见 §4.4） |

- 推荐组合的混淆矩阵：`[[TP=50, FN=0], [FP=1, TN=49]]`，整体准确率 **99%**（99/100）。
- `area` 单位为**原图像素²**（100% 缩放口径；真机高 DPI 需按 `scale_factor²` 归一化，见 §6）。
- **为什么不直接推荐更保守的 `area≥1000`（0%/0%）**：真实小字（13–14px 单行）框面积可能 <1000px²，
  会把召回余量压得过小（本语料 50/50 仍全中，但换更小字号/更低对比度场景风险更高）；
  `area≥400` 在保持 2% 误判（仍在 5% 内）的同时保留小字召回余量，作为默认更稳。
- S-11 结论：**只靠置信度会误判 38%**；**只加面积下限（清单三阈值原义）最多只能压到 18%**；
  必须再加「单个文字行框**高度上限**」（或把面积改为区间）才能达标。

### 4.2 为什么「面积下限」压不住误判

失败样本的几何统计（det 保留 ≥0.6 的框）：

- 正样本（真实文本行）框高：P1=10px、P50=21.2px、P99=38.3px、max=46.3px；面积 P50=4911px²、P99=24312px²；
- 误判的合成负样本框：大面积、高置信、**接近方形**——`synth_shapes_*` 的框高 72–1600px、面积 4.7k–2.4Mpx²，
  置信度 0.73–0.91；`synth_icons_*` 框高 84–498px、置信度 0.8–0.89。
- 即：误判不是「小碎片」，而是**大块几何/图标区域**；面积只设下限无法过滤，反而「行高上限」（≤70px）
  与文本行高度（≤~46px，留 24px 余量）能一刀切干净。置信度 0.75 以上开始漏判真实小字（见 §4.3 曲线）。

### 4.5 失败样本（推荐组合下唯一误判）

`synth_shapes_05`（深色底随机线段，2560×1440）：det 给出 9 个框，其中 1 个框

  只需识别少量框），用 rec 置信度/字符集再确认；这列为遗留（§7），不影响本轮 ≤5% 验收。

## 5 与 S-02/S-03 的关系

- 本验证的 det 输入与生产/`S-02-S-03-OCR时延基准.md` 完全同口径（`scale = min(3200/max(w,h), sqrt(3.0Mpx/(w·h)))`，
  不放大）；det 模型、线程、预处理均相同。
- 因此推荐阈值（面积/行高/行数）是**纯后处理比较**，不引入额外推理；按 S-02/S-03 的时延结论，
  整屏路径仍只需一次 det（P95 743–794ms），新增阈值不改变时延量级。

## 6 产品配置建议（本轮不改 Rust）

**现状（只读参考 `src-tauri/src/services/ocr_service.rs`）**：`presence()` = `filter_boxes(...).is_empty()`
的取反，`filter_boxes` 只按 `min_confidence`（配置 `ocr.textThreshold=0.6`）过滤，没有面积/行数/行高；
`scan_screen` 的整屏判定就是 `!boxes.is_empty()`。

**最小改动方案**（建议后续小步落地，均不影响推理时延）：

1. `config.json` 增加 4 个键（默认值取本轮推荐，面积/行高按 100% 缩放口径）：
   ```jsonc
   "ocr": {
     "textThreshold": 0.6,              // 保留：置信度下限（= 本轮 min_conf）
     "presence": {
       "minAreaPx2": 400,               // 单行框面积下限（px²，100% 缩放）
       "maxBoxHeightPx": 70,            // 单行框高度上限（px，100% 缩放）
       "minLines": 1                    // 判为有文字所需的最少行数
     }
   }
   ```
2. `filter_boxes` 增加面积/行高两个比较（纯逻辑 O(n)，无 OFF 语义变化）；`presence` 增加行数判断；
   新增 `presence()` 的单测覆盖「大块几何 → 无文字」「小线段 → 无文字/边界」「单行文本 → 有文字」。
3. **DPI 归一化**：截图坐标是物理像素，而面积/行高阈值按 100% 缩放口径配置；运行时用冻结帧所在显示器的
   `scale_factor` 换算（面积 ÷ `sf²`、行高 ÷ `sf` 后再比较），避免 150%/200% 缩放下阈值失效。
   若不引入归一化，等价做法是把判定放到「det 输入坐标」上（det 输入已被像素预算压到 ≤3.0Mpx），
   但需重新标定阈值；本轮语料为 100% 缩放渲染，两种口径在本机等价。
4. **兜底**：保留清单 §3 提到的「强制文本模式」开关——用户可无视判定直接触发识别；
   并对「通过阈值但框数 ≤2」的边界情形做一次 rec 复核（列为遗留，建议 P2 前完成）。
5. **不推荐**把 `max_area`（面积上限）作为默认配置：备选组合 `1000≤area≤5000` 虽也达标（2%），
   但会漏掉「大字号/单条标题」页面（本轮 `h≤70` 同区间内所有真实页都有小字行，故未暴露）；面积上限只
   作为低配兜底档位。
6. **阈值可配置性已验证**：脚本支持 `--min-area/--min-confidence/--min-lines/--max-box-height/--max-area`，
   `judge` 子命令可对任意组合复算，例如：
   `run_ocr_eval.py judge --min-area 1000 --min-confidence 0.6 --max-box-height 70 --min-lines 1` → 误判 0%、漏判 0%。

## 7 结论、处置与遗留

**结论：DONE（脚本口径）**。在 100 张语料上，推荐阈值组合
`det_score≥0.6 + 单行框面积≥400px² + 单行框高≤70px + 行数≥1` 达到误判 **2%（1/50）**、漏判 **0%（0/50）**，
满足 ≤5%/≤5%；且阈值全部脚本参数化，可复算任意组合。

**处置**：达标 → 建议按 §6 落产品配置（面积/行高/行数配置化 + DPI 归一化），落库前在真机混合 DPI
（150%/200%）与更多真实窗口截图（含 Win11 系统窗口、图标密集桌面）上复核；本轮不改 Rust 以避免构建冲突。

**遗留**：

1. **面积/行高/行数配置化 + DPI 归一化**（产品代码，待实施；最小改动方案见 §6）。
2. **边界情形 rec 复核**：推荐组合下仍有 1 张「27×35 小线段」被误判（2%），几何/置信度不可分；
   建议对「通过阈值但框数 ≤2」的判定补一次 rec 确认，预期可消掉该类误判（待实现/复测）。
3. **真实截图覆盖**：50 张真实样本是 headless Edge 自建页面的真实渲染（100% 缩放），未覆盖 Win11 系统窗口、
   混合 DPI 真机 150%/200% 物理像素、真实应用图标密集页；语料可继续扩充（尤其「只有单行文字」的页面，
   用于验证 `min_lines=1` 的漏判边界）。
4. **det 分数获取实现**：产品引擎接入时，`detect()` 需把 DB 框置信度填入 `OcrBox.confidence`
   （当前 trait 只有坐标与文本语义；接入 `TODO(real)` 时一并确认），否则 `min_confidence` 过滤无意义。
