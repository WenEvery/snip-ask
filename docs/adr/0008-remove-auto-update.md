# ADR-0008：彻底移除自动更新

| 项目 | 内容 |
| --- | --- |
| 状态 | 已接受（Accepted） |
| 日期 | 2026-11-06 |
| 关联需求 | v1.0.0 用户决策「去除自动更新」：删除 updater、`advanced.updateChannel`、更新 UI 与全部更新相关文档 |
| 关联文档 | [接口契约](../接口契约.md) §4.1（schema v5）/ §7（事件 15）/ §16 修订记录 5；[自定义指南](../自定义指南.md) §1 |
| 证据 | `.verify/plan/spec-v1.md` §0.3；契约迁移 `src-tauri/src/contract/config.rs`（v4→v5 删除 `updateChannel`）；事件表 `src-tauri/src/contract/events.rs`（15 个，无 `update:status`） |

## 背景

立项阶段的概要设计曾规划 `tauri-plugin-updater` 签名更新通道（`advanced.updateChannel: stable|preview`、
`update:status` 事件、设置页更新通道 UI）。v0.1.0 实际未接入该插件，但契约与文档里一直保留「更新」概念。

v1.0.0 的发布事实与产品约束：

1. **无服务端、无账号、BYOK**：项目方没有服务器，也没有发布基础设施；更新通道需要一个稳定的托管与
   签名密钥流程，成本与维护负担与「轻量开源工具」定位不匹配；
2. **安装包未签名**：没有代码签名证书，Tauri updater 要求的签名更新链无法可靠落地（签名校验是前提）；
3. **用户明确要求鼓励自定义**：用户可以直接改源码、换模型、改提示词；「自动更新」与「自己掌控版本」冲突，
   覆盖安装新包反而更符合「保留我的配置与定制」的预期；
4. **减少网络面**：去掉更新检查后，应用在空闲时不再有任何「主动联网查版本」的行为，隐私口径更干净。

## 决策

1. **彻底删除自动更新能力**：
   - 不引入 `tauri-plugin-updater`，不保留 `updater_service` 实现与任何更新 HTTP 请求；
   - 删除配置字段 `advanced.updateChannel` 与 `UpdateChannel` 类型；**配置 Schema v4 → v5 迁移主动移除旧键**；
   - 删除事件 `update:status`（事件总数 16 → **15**）；
   - 删除设置页更新通道/检查更新 UI；设置页「自定义与关于」只展示版本、版本类型（slim/full/dev）
     与目录入口，并明确写「本软件不自动更新」。
2. **升级方式改为显式操作**（写入《自定义指南》与 README）：
   - 下载新版安装包 → 覆盖安装（保留 `%APPDATA%` 配置/提示词/历史与 Windows 凭据，配置按 schema 迁移链升级）；
   - 或自行源码构建（Apache-2.0，允许修改与分发，保留 `LICENSE`/`NOTICE` 并标注改动）。
3. **文档口径统一**：README / CHANGELOG / 契约 / 开发指南 / 技术验证清单不再出现「更新通道」作为现行能力；
   历史研究文档（可行性研究报告、概要设计说明书）**保留原方案作为历史基线**，由本 ADR 与 CHANGELOG 标注已移除。

## 理由

- **与产品定位一致**：单机、BYOK、无服务端；没有托管更新的必要基础设施。
- **消除签名依赖**：未签名安装包 + 自动更新是安全隐患（无法校验来源），移除反而降低风险面。
- **减少网络与遥测面**：不检查更新、不联网查询版本，符合「不联网也能用」的承诺。
- **降低维护成本**：不需要维护更新元数据、通道、回滚与签名密钥；发布 = 归档安装包 + SHA256。

## 备选方案与未采用原因

| 备选 | 未采用原因 |
| --- | --- |
| 保留「仅检查版本」的轻量更新提示 | 仍需联网与托管元数据；用户决策是彻底移除，且与「无遥测/少网络」口径冲突 |
| 用 GitHub Releases API 做版本提示 | 引入运行时网络依赖与 GitHub 可达性假设；断网/镜像环境体验差；仍需手动下载 |
| 保留 updater 但默认关闭 | 代码、依赖、配置字段与攻击面仍在，违背「彻底移除」的决策 |
| 应用内「打开下载页」按钮 | 属于联网/引导行为，非必需；安装包与 docs 已提供升级说明 |

## 后果

- **正面**：攻击面与网络面变小；契约少 1 配置字段、少 1 事件；发布流程简单（归档 + SHA256）；
  用户对版本与定制有完全控制权。
- **代价 / 风险**：
  - **用户必须手动升级**，不会自动获得安全修复；需在 README/CHANGELOG 醒目说明；
  - 旧版本可能长期滞留（尤其离线用户）——通过 CHANGELOG 与「已知限制」提示；
  - 降级不兼容：旧版程序不识别 schema 5 配置，回滚前需备份（已在自定义指南 §11 说明）。
- **后续**：若未来具备签名与托管能力，重新引入自动更新应作为**新 ADR** 提出，而不是恢复旧字段。
