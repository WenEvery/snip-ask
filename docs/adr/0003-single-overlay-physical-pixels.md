## 背景

Windows 多显示器场景下，各屏分辨率与 DPI 缩放可以不同（如 4K@150% + 1080p@100%），
虚拟桌面原点可能为负。框选交互要求：**冻结整个桌面成一张快照**、在快照上拖选、
选区结果精确映射回屏幕像素，并支持混合 DPI 双屏下误差 ≤ 2px（Go 前提条件之一）。

三种可选坐标/窗口模型：

1. **逻辑坐标 + 每屏一个覆盖窗口**：每屏窗口独立，跨屏拖选需要在窗口间同步；DPI 边界跳变易错。
2. **逻辑坐标 + 单窗口**：缩放下逻辑坐标与物理像素存在取整差异，2px 误差难以保证。
3. **物理像素 + 单窗口**：窗口铺满虚拟桌面矩形，坐标即屏幕像素，无换算损失。

## 决策

1. **一个 overlay 窗口**覆盖整个虚拟桌面矩形（物理像素，可为负坐标），无边框、透明、置顶、
   不显示在任务栏；Rust 依据 `VirtualDesktop { rect, dpr }` 按需创建并复用。
2. **全流程使用物理像素**：`rectPhys` 以虚拟桌面左上角为原点；前端 CSS 像素 = 物理像素 / `dpr`，
   仅用于渲染；前端**不得**把逻辑坐标换算后回传。
3. **冻结快照**：捕获时只截一次虚拟桌面，overlay 上绘制该快照 + 选框层；背景透明，选区外可见
   原桌面，视觉上等价于「冻结」。
4. **坐标换算为纯函数**：`platform::coords` / `domain::rect` 提供逻辑↔物理、屏幕↔桌面坐标换算，
   带单元测试；`PerMonitorV2` DPI 感知清单固定。
5. **会话内一致性**：冻结时固定 `dpr` 与桌面矩形；会话中途分辨率/缩放变化视为失败，
   提示重新框选（`SA-1002` 或重新 `capture_freeze`）。

## 理由与备选

- **误差可控**：物理像素直接对应截图与屏幕，混合 DPI 下无浮点/取整累积，2px 阈值可验证
  （spike S-01）。
- **交互一致**：单窗口拖选天然跨屏，不存在窗口拼接缝与焦点切换。
- **与快照一致**：快照本身是物理像素位图，选框坐标与像素一一对应，OCR 与图像裁剪直接复用。
- **备选「每屏一个窗口」**：跨屏拖选需多窗口协同与焦点管理，窗口间 1px 缝隙常见，放弃。
- **备选「逻辑坐标」**：Win32 与 WebView 的 DPI 虚拟化规则叠加后难以保证误差，放弃。
- **备选「Rust 原生绘制覆盖层」**：可省略 WebView，但选框/菜单/放大镜 UI 全部重写，与 Web 技术栈决策冲突，放弃。

## 后果

- overlay 窗口尺寸等于虚拟桌面总矩形：4K 双屏下是很大的透明窗口，需关注 WebView 合成开销；
  验收时纳入内存/帧率观察（S-10）。
- 快照在 Rust 侧为位图，overlay 通过 `FrozenFrameMeta`（`width/height/dataUrl`）获取展示信息，
  骨架模式下 `dataUrl = null`（前端渲染占位背景）。
- 会话期间显示器热插拔/缩放变化必须显式处理，不能静默使用旧 `dpr`。
- 全屏独占与 DRM 内容可能截黑，属系统限制，需降级提示（S-09），不做绕过。
- 前端所有涉及位置的逻辑（选择框、菜单定位、放大镜采样）统一按物理像素推导，测试覆盖换算。
