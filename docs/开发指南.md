## 1 环境准备（Windows 逐步）

### 1.1 安装 Node.js 与 pnpm

1. 安装 Node.js **≥ 20**（推荐 22 LTS）：<https://nodejs.org/zh-cn>，安装时勾选「Add to PATH」。
2. 启用 pnpm（二选一）：
   - 推荐：`corepack enable`，再执行 `corepack prepare pnpm@latest --activate`；
   - 或：`npm install -g pnpm@latest`。
3. 验证：

   ```powershell
   node --version    # v20.x 或更高
   pnpm --version    # 9.x 或更高（CI 使用 11）
   ```

### 1.2 安装 Rust 工具链（桌面版必需）

> 只用浏览器 mock 预览前端（`pnpm dev:web`）时**不需要** Rust；要跑 `pnpm dev` / `pnpm build`
> 或本地执行 `cargo` 检查时才需要。

1. 安装 Rustup：<https://rustup.rs/>（默认 `stable-x86_64-pc-windows-msvc`，Rust ≥ 1.77）。
2. 安装 **Visual Studio Build Tools 2022**：<https://visualstudio.microsoft.com/visual-cpp-build-tools/>
   - 勾选工作负载「**使用 C++ 的桌面开发**」；
   - 右侧「安装详细信息」确认包含 **MSVC v143 生成工具** 与 **Windows 10/11 SDK**；
   - 该工作负载提供 Rust 链接所需的 `link.exe`。
3. 验证（新开一个终端）：

   ```powershell
   rustc --version
   cargo --version
   rustup component add rustfmt clippy   # 本地跑 verify 需要
   ```

### 1.3 安装 WebView2 Runtime

- Windows 11 自带；
- Windows 10 若缺失，安装 Evergreen Runtime：<https://developer.microsoft.com/microsoft-edge/webview2/>。

### 1.4 获取仓库并安装依赖

```powershell
git clone <仓库地址> 框选ai
cd 框选ai
pnpm install
```

> **注意**：仓库路径可能包含中文。Node/pnpm/Rust 均支持，但部分旧工具（如 PowerShell 5.1 读取
> 无 BOM 的 UTF-8 脚本）可能出问题；仓库内 `.ps1` 脚本以 **UTF-8 with BOM + LF** 保存，
> 修改脚本时请保持该编码。

## 2 常用命令

| 目标 | 命令 | 说明 |
| --- | --- | --- |
| 安装依赖 | `pnpm install` | 仅前端依赖；Rust 依赖由 cargo 在首次构建时拉取 |
| 浏览器预览 | `pnpm dev:web` | Vite 固定端口 1420，mock 后端，无需 Rust |
| 桌面联调 | `pnpm dev` | `tauri dev`：Vite + Rust 后端，需要 Rust/MSVC |
| 类型检查 | `pnpm typecheck` | `tsc --noEmit` |
| Web 构建 | `pnpm build:web` | `tsc --noEmit && vite build` → `dist/` |
| 桌面构建 | `pnpm build` | `tauri build`（NSIS 安装包 → `src-tauri/target/release/bundle/nsis/`） |
| 格式化 | `pnpm format` / `pnpm format:check` | Prettier 全仓库格式化 / 检查 |
| Rust 格式 | `cargo fmt --manifest-path src-tauri/Cargo.toml` | 格式化（CI 用 `--check`） |
| Rust 静态检查 | `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings` | 警告即失败 |
| Rust 单测 | `cargo test --manifest-path src-tauri/Cargo.toml` | `domain` 纯逻辑 + 契约序列化测试 |
| 一键校验 | `powershell -ExecutionPolicy Bypass -File scripts\verify.ps1` | 本地等价 CI，输出 PASS/SKIP/FAIL |
| 开发启动 | `powershell -ExecutionPolicy Bypass -File scripts\dev.ps1` | 自动检测工具链并选择 `dev` / `dev:web` |
| 构建 | `powershell -ExecutionPolicy Bypass -File scripts\build.ps1` | 有 Rust 构建安装包，无 Rust 只构建 Web |
| 重新生成图标 | `python scripts\gen-icons.py` | 需 Pillow；生成并校验 `src-tauri/icons/` |

浏览器预览的三个入口：

- <http://localhost:1420/>：主窗口（设置页 + 首启引导）；
- <http://localhost:1420/?window=overlay>：冻结层 + 选框 + 动作菜单；
- <http://localhost:1420/?window=result>：结果窗（流式输出、来源、追问）。

## 4 契约变更流程

`docs/接口契约.md` 是前后端边界的**唯一事实来源**。任何跨端形状变化都必须按以下顺序进行：

1. **先改契约**：修改 `docs/接口契约.md` 对应章节（§4 配置 / §6 命令 / §7 事件 / §8 错误码 /
   §13 前端契约文件 / §15 Rust 约定），写清参数、返回、错误码、事件副作用。
2. **同步 TS 契约**：更新 `src/shared/contract/types.ts`、`names.ts`（`COMMANDS`/`EVENTS`）、
   `defaults.ts`（仅当默认配置变化）。
3. **同步 Rust 契约**：更新 `src-tauri/src/contract/{types,config,errors,events}.rs`，保持
   `#[serde(rename_all = "camelCase")]`、`Option` 序列化为 `null` 等 §15 约定。
4. **递增契约版本**（破坏性变更才递增）：`src-tauri/src/contract/mod.rs` 中的
   `IPC_CONTRACT_VERSION`（当前 `1`）→ `Stats.contractVersion` 自动跟随；同时在契约文末
   「修订记录」新增一行（版本 / 日期 / 说明）。
5. **同步 mock**：`src/shared/ipc/mock.ts` 的行为要与契约 §12「骨架模式」一致，保证无 Rust
   环境也能完整走 UI 流程。
6. **更新日志**：在 `CHANGELOG.md` 的 `[Unreleased]` 下补充说明。
7. **验证**：`pnpm typecheck` → `pnpm build:web` → `scripts\verify.ps1`（有 Rust 时）。

> 新增可选字段：前端必须容忍未知字段，Rust 侧加 `#[serde(default)]`。
> 删除命令/事件需两个版本弃用期，并在设置页/托盘提示。

### 4.1 新增一条命令的 checklist

- [ ] 契约 §6 命令表新增一行（编号、`invoke` 参数 camelCase、返回类型、主要错误码、副作用/事件）；
- [ ] `src/shared/contract/names.ts` 的 `COMMANDS` 增加常量，`CommandName` 联合类型自动覆盖；
- [ ] `src/shared/ipc/tauri.ts`、`src/shared/ipc/mock.ts` 增加同名实现（mock 按 §12 行为）；
- [ ] `src-tauri/src/commands/<domain>.rs` 增加 `pub async fn`，参数 snake_case、返回 `Result<T, AppError>`；
- [ ] `src-tauri/src/commands/mod.rs` 的 `tauri::generate_handler![...]` 注册；
- [ ] 领域/服务层实现（纯逻辑放 `domain`，能力编排放 `services`，外部能力用 trait 注入）；
- [ ] 若新增事件：`events/mod.rs` 增强类型助手 + 契约 §7 事件表；前端 `useIpcEvent` 订阅；
- [ ] 需要额外 Tauri 权限时更新 `src-tauri/capabilities/default.json`；
- [ ] `domain` 新增纯逻辑补单元测试；跑 `cargo test`；
- [ ] `CHANGELOG.md` + 契约修订记录（若版本递增）。

## 5 mock 模式说明

浏览器没有 Tauri 运行时，`src/shared/ipc/index.ts` 的 `isTauri()` 返回 `false` 时自动使用
`src/shared/ipc/mock.ts`：

- 命令返回契约 §12 的确定性占位数据（例如 OCR 400ms 后 `done`、流式回答每块 25–40ms）；
- 配置读写落 `localStorage["snipask.mock.config"]`（仅 mock 例外，业务数据不落 localStorage）；
- `window_show` / `window_hide` 为 no-op，但会派发本地自定义事件供页面自测；
- 事件通过同一套 `ipc.on(EventName, handler)` 订阅，前端代码无需区分 mock 与真实后端。

mock 只用于 UI 联调与手动验收，**不放在生产路径**；真实后端行为以 Rust 实现为准。

## 6 日志与数据目录

| 类别 | 位置 | 说明 |
| --- | --- | --- |
| 配置 | `%APPDATA%\SnipAsk\config.json` | Schema v3，原子写 + `config.json.bak`，不含密钥 |
| 引导状态 | `%APPDATA%\SnipAsk\onboarding.json` | 与配置文件分离，含草稿 |
| 提示词覆盖 | `%APPDATA%\SnipAsk\prompts\*.md` | 用户覆盖同名内置提示词（用户 > 内置） |
| 日志 | `%APPDATA%\SnipAsk\logs\` | 按日滚动，默认 `info`，禁止记录密钥/OCR 原文/完整查询串 |
| 历史与用量 | `%APPDATA%\SnipAsk\history.db` | SQLite（`migrations/001_init.sql`） |
| 模型 | `%LOCALAPPDATA%\SnipAsk\models\<id>\` | 下载目标，`.installed` 标记 |
| 缓存 | `%LOCALAPPDATA%\SnipAsk\cache\` | 截图临时文件，可清 |
| 运行时 | `%LOCALAPPDATA%\SnipAsk\runtime\` | 本地引擎端口/日志 |
| 便携版 | 程序目录存在 `portable.flag` | 数据写入程序目录旁 `data\` |

日志级别通过环境变量控制（tracing `EnvFilter` 语法）：

```powershell
$env:RUST_LOG = "info"                      # 默认
$env:RUST_LOG = "snip_ask_lib=debug,info"   # 只看本 crate 的 debug
pnpm dev
```

日志初始化早于配置加载失败分支，配置损坏时也能看到启动错误。

## 7 调试

### 7.1 前端

- **WebView2 DevTools**：`pnpm dev` 的调试构建默认启用 DevTools，在窗口内右键选择「检查」；
- **浏览器 mock**：`pnpm dev:web` 后直接用 Chrome/Edge DevTools 调试，支持 React 组件树与网络面板
  （注意 mock 不产生真实网络请求）；
- **overlay / result 单独调试**：`?window=overlay`、`?window=result`，避免每次触发热键；
- **事件联调**：在 DevTools Console 里监听 mock 事件（mock 会在 `window` 上派发调试用自定义事件）。

### 7.2 Rust 后端

```powershell
$env:RUST_LOG = "debug"
pnpm dev
```

- 启动顺序、热键注册、会话状态机、事件发送均打 `tracing` 日志；
- 只看某个模块：`$env:RUST_LOG = "snip_ask_lib::app::hotkeys=debug"`；
- 独立跑纯逻辑测试：`cargo test --manifest-path src-tauri/Cargo.toml domain::`；
- 契约序列化回归：`cargo test --manifest-path src-tauri/Cargo.toml contract`。

### 7.3 骨架模式

`advanced.skeletonMode` 默认 `true`。想验证真实实现进度时，可临时把它改成 `false`
（设置页「高级」或直接改 `config.json`），此时未实现的 `TODO(real)` 分支会返回
`SA-9001 SkeletonNotImplemented` 或对应错误码——这是预期的脚手架行为。

## 8 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `cargo` 不是内部或外部命令 | 未安装 Rust 工具链 | 装 rustup，或先只用 `pnpm dev:web` 预览前端；CI 会跑 Rust 检查 |
| `error: linker 'link.exe' not found` | 缺 MSVC 生成工具 | 装 VS Build Tools 2022，「使用 C++ 的桌面开发」+ Windows SDK |
| `pnpm dev` 提示 1420 端口被占用 | 已有 Vite/tauri dev 在跑 | `netstat -ano \| findstr :1420` 找到 PID 后 `taskkill /PID <pid> /F`，或先关旧进程 |
| 按 `Ctrl+Q` 没反应 / 被其他应用占用 | 全局热键被 QQ/微信/输入法等抢占 | 设置页改键或暂停热键；`hotkey_probe` 命令可探测冲突（骨架模式为占位判定） |
| `pnpm install` 失败或很慢 | 网络/镜像/Node 版本不匹配；pnpm 11 下 esbuild 构建脚本被安全策略拦截 | 确认 Node ≥ 20；配置国内镜像 `pnpm config set registry https://registry.npmmirror.com`；pnpm 11 需在根 `pnpm-workspace.yaml` 的 `allowBuilds` 中允许 `esbuild`（旧版 `package.json` 的 `pnpm.onlyBuiltDependencies` 已不读取） |
| 启动白屏 | Vite 未就绪或 `devUrl` 不一致 | 确认 1420 由 Vite 占用；查看 `tauri.conf.json` 的 `build.devUrl` 与终端日志 |
| WebView2 缺失（`0x80004005` 类错误） | 系统未装 WebView2 | 安装 Evergreen Runtime 后重试 |
| 安装包偏大 | 误把模型/大资源打进包 | 模型不入包（按需下载）；检查 `bundle.resources` 与 `resources/` 仅含文本 |
| 无管理员权限能否运行 | 用户级安装/注册表 HKCU | 可以，无需提权；开机自启用当前用户注册项 |
| 杀软误报 | 未签名 exe + 全局热键 | 开源可审计；后续申请代码签名并提交误报申诉 |
| PowerShell 脚本中文乱码/解析报错 | Windows PowerShell 5.1 读取无 BOM 的 UTF-8 | 脚本保持 **UTF-8 with BOM**；或改用 PowerShell 7（`pwsh`） |
| `scripts\verify.ps1` 出现 SKIP | 本机无 Rust 工具链 | 属预期；Rust 检查在 CI（windows-latest）执行 |
| 图标不更新 | 未重新生成或未提交 | `python scripts\gen-icons.py` 后提交 `src-tauri/icons/` 全部文件 |
| release 版窗口一片白/提示「localhost 拒绝连接」 | 直接 `cargo build --release` 未启用 Tauri `custom-protocol` feature，应用仍去连 `devUrl` | 发布用 `pnpm build`（tauri build 会自动启用该 feature）；或手动 `cargo build --release --features custom-protocol` |
| 事件发不出去 / 前端收不到（日志 `only alphanumeric, '-', '/', ':', '_' permitted for event names`） | Tauri 2 不允许事件名含 `.` | 事件名统一用 `域:动作`（如 `overlay:ready`），见契约 §1/§7；不要写回点分形式 |
| overlay 窗口尺寸异常、选框越界 | `WebviewWindowBuilder::{inner_size, position}` 收的是**逻辑像素**，不能用主显示器物理尺寸 | 用 `app::windows::overlay_geometry()` 按 `dpr` 换算（`物理尺寸 / scale_factor`） |
| overlay 一直在「等待冻结帧」 | 冷启动时 `overlay:ready` 早于 WebView 加载完成而丢失 | 已由「`capture_freeze` 幂等补发 + `Builder::on_page_load` 补发 + 前端挂载后主动拉取」三重兜底；若仍出现，检查 `capture_freeze` 是否被改回非幂等 |

## 9 代码风格

### 9.1 格式与静态检查

- **Rust**：`cargo fmt`（`src-tauri/rustfmt.toml`：`max_width = 100`、`edition = "2021"`）；
  `cargo clippy --all-targets -- -D warnings`，警告视为错误；CI 强制。
- **TypeScript**：`strict` + `noUnusedLocals` + `noUnusedParameters` + `noFallthroughCasesInSwitch`；
  路径别名 `@/*` → `src/*`；不允许 `any` 逃逸（必要时写显式类型）。
- **Prettier**（`.prettierrc.json`）：`semi: true`、双引号、`trailingComma: "all"`、`printWidth: 100`、
  `endOfLine: "lf"`、`tabWidth: 2`。提交前 `pnpm format`。
- **EditorConfig**：UTF-8、LF、末尾换行、去行尾空白；`.md` 允许行尾双空格（软换行）。

### 9.2 命名与文件组织

| 类型 | 约定 | 示例 |
| --- | --- | --- |
| React 组件文件 | PascalCase `.tsx`，默认导出组件 | `ResultWindow.tsx`、`ActionMenu.tsx` |
| hook | `useXxx.ts`，具名导出 | `useIpcEvent.ts` |
| 工具/纯函数 | camelCase `.ts` | `throttle.ts`、`format.ts` |
| 契约常量 | UPPER_SNAKE | `COMMANDS`、`EVENTS`、`IPC_CONTRACT_VERSION` |
| Rust 模块/文件 | snake_case `.rs` | `capture_service.rs`、`llm_gateway.rs` |
| Rust 类型 | PascalCase；错误枚举变体 PascalCase | `AppError`、`ErrorCode::CaptureFailed` |
| 目录 | 小写 | `windows/overlay/`、`services/` |

### 9.3 单一职责与规模

- 单文件 **≤ 300 行**，超出拆子组件/子模块；
- `commands` 只做「参数校验 → 调用 service → 返回」，不写业务逻辑；
- `domain` 不依赖 Tauri/IO/`std::process`，全部可单测；
- `platform` 是唯一允许 `unsafe` 与 Win32 调用的目录，对外暴露 trait；
- CSS 用原生 CSS + token（`--sa-*`），不引入运行时 CSS-in-JS；不硬编码颜色/间距/字号。

### 9.4 提交前自查

```powershell
pnpm typecheck
pnpm format:check
powershell -ExecutionPolicy Bypass -File scripts\verify.ps1
```

有 Rust 环境时再确认 `cargo fmt --check`、`clippy`、`cargo test` 全绿；没有 Rust 时至少保证
Web 两项通过，并在 PR 描述中注明「Rust 检查依赖 CI」。
