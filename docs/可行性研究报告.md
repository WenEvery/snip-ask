## 0. 结论摘要（TL;DR）

**总体结论：可行（Go）。** 产品定位收敛为「轻量快速、托盘常驻、可开机自启、高度自定义的框选解答 / 翻译 / 搜索工具」；技术路线全部有成熟、开源、可商用的组件支撑；运行成本可低至每次约 0.2–1 分钱（人民币），且可由用户自带 API Key 消化；单人全职约 6–7 周可完成 MVP、11–12 周发布 v1.0（业余投入约 6–7 个月）。

| 可行性维度 | 结论 | 关键依据 |
| --- | --- | --- |
| 技术可行性 | ✅ 可行 | Tauri 2、Windows 截图 API、RapidOCR/ONNX、OpenAI 兼容多模态 API、DeepSeek 搜索 API、本地翻译模型（HY-MT/TranslateGemma/OPUS-MT）均为成熟方案 |
| 经济可行性 | ✅ 可行 | BYOK 模式使项目方零服务器成本；单次调用成本约 ¥0.001–0.01（翻译接近免费，搜索/深度模式更高） |
| 操作可行性 | ✅ 可行 | `Ctrl+Q` → 框选 → 选动作，三步交互；有文字/无文字自动适配动作 |
| 产品形态 | ✅ 贴合 | 托盘常驻 + 开机自启（可选）+ 单实例；主安装包 ≤ 25MB，模型按需下载；用完即走，不打断当前工作 |
| 进度可行性 | ✅ 可控 | MVP 约 32 人日；v1.0 约 57 人日（±30%） |
| 风险水平 | ⚠️ 中等可控 | 主要风险：混合 DPI 多屏、`Ctrl+Q` 全局占用、图片搜索质量、全屏游戏/DRM、热键冲突、隐私告知 |

**推荐方案要点：**

1. **框架**：Tauri 2（Rust 后端 + WebView2 前端），安装包最小、跨平台潜力最大。
2. **框选**：把整个虚拟桌面冻结成一张快照，覆盖所有显示器的透明选框层，基于物理像素做坐标换算；**冻结后立即在后台启动整屏 OCR 预扫描**，用户拖拽选框时检测同步进行。
3. **捕获**：GDI BitBlt 作为通用兜底，Windows Graphics Capture（WGC）作为增强路径。
4. **OCR**：RapidOCR（PP-OCR 系列 ONNX 模型），本地离线、中文效果好；两段式推理（整屏检测 → 选区识别）。
5. **云端**：统一走 OpenAI 兼容协议，默认 DeepSeek 视觉模型；**AI 能力分「快速 / 深度」两档**，按动作和场景切换。
6. **搜索**：框选后菜单分「文本搜索」与「图片搜索」——文本搜索可在系统浏览器与 AI 搜索（DeepSeek Search API）间配置；图片搜索把整图交给视觉模型识别后联网检索并给出带来源的答案。
7. **翻译**：默认云端大模型（DeepSeek flash）或专用翻译模型（Qwen-MT）；可选本地翻译小模型（HY-MT1.5-1.8B/7B、TranslateGemma 4B）实现离线与隐私；质量、速度按快速/深度分档，术语与格式可定制。
8. **开源协议**：建议 Apache-2.0，配 `NOTICE` 文件声明第三方组件；不做服务端、不托管用户数据。
9. **首启引导**：安装完成或首次启动进入 6 步向导——AI URL 与 Key、翻译方式（云端或本地模型实时下载）、各功能快/深、外观与热键、隐私；3 分钟内完成，可跳过、可重开。
10. **产品形态**：托盘常驻、单实例、可选开机自启；主安装包轻（≤ 25MB，模型按需下载）；动作菜单、提示词、快捷键、主题、模型绑定均可自定义，配置支持导入/导出/重置。

**Go 的前提条件（技术验证阶段必须确认）：**

- 混合 DPI 双屏下框选坐标误差 ≤ 2px；
- 整屏后台 OCR 文字检测 ≤ 1.2s（4K 双屏），选区 OCR ≤ 800ms；
- `Ctrl+Q` 全局热键可注册，冲突检测与改键引导可用；
- 翻译链路验证：云端 200 字 ≤ 1.5s；本地 HY-MT1.5-1.8B（Q4，i5/16GB 或同级）200 字 ≤ 8s（不含首次加载）；
- 图片搜索链路（视觉识别 → 检索 → 摘要）快速模式 ≤ 10s；
- 首启引导在无网络/无 Key 时也能完成并进入受限模式；本地模型下载支持断点续传与校验。

**主要风险提示：** 全屏独占游戏与 DRM 内容会截出黑屏；`Ctrl+Q` 注册为全局热键后会占用其他应用的同一快捷键；视觉模型存在幻觉与识别错误，图片搜索必须标注来源与不确定性；用户截图可能含敏感信息，必须明确上传提示与关闭开关；本地翻译模型需额外下载 1–8GB 模型并占用 3–16GB 内存，低配机器上速度有限；无代码签名会有 SmartScreen 拦截。

## 1. 项目背景与目标

### 1.1 要解决的问题

日常在电脑上看到不懂的内容时，现有操作链路是断裂的：

1. 截图（`Win + Shift + S` 或第三方工具）→ 2. 另存或粘贴到某个应用 → 3. 用 OCR 提取文字 → 4. 复制到搜索引擎 / 翻译网站 / 对话框 → 5. 看结果。

五步里至少切三次窗口，且「搜索、翻译、解答」三个需求分散在不同工具中。框选 AI 把这五步压缩成一个动作：**框选即问，一次热键直达结果**。

### 1.2 产品定位

| 维度 | 定位 |
| --- | --- |
| 是什么 | 一款轻量快速、托盘常驻、可开机自启、高度自定义的「框选即问」桌面工具（解答 / 翻译 / 搜索） |
| 不是什么 | 不做长截图、录屏、复杂标注、以贴图为主的工具（避免与 Snipaste/Snow Shot 正面竞争） |
| 核心差异 | 框选即问三动作（解答 / 翻译 / 搜索）+ 文本/图片双搜索 + 快/深双档 + 本地/云端翻译 + 高度自定义 + 开源（Apache-2.0） |
| 目标用户 | 学生（外文文献、作业题）、程序员（报错、文档）、办公人群（合同、邮件、表格）、外语阅读者、游戏/视频截图用户 |
| 成功标准 | 养成「看到不懂就 `Ctrl+Q`」的习惯；单次任务 5 秒内完成；托盘长驻、几乎无感；用户无需打开其他工具 |

**产品原则（v1.4 定稿）：**

- **轻**：主安装包 ≤ 25MB；翻译/OCR 模型不预装、按需下载；不引入 Electron 级开销。
- **快**：冷启动 ≤ 1.5s（常驻时召出 ≤ 200ms）；热键 → 选框 ≤ 250ms；用完即走。
- **稳**：托盘常驻 + 单实例；空闲 CPU < 0.5%、内存 ≤ 120MB；崩溃自恢复。
- **自定义**：动作菜单、提示词、8+ 快捷键、主题外观、模型绑定、配置导入/导出均可改（见 2.5）。
- **开**：Apache-2.0 开源；BYOK、无服务端、不收集截图；可二次开发。
- **可选离线**：本地 OCR + 本地翻译模型，断网仍可完成识别与翻译。

## 2. 功能需求

### 2.1 核心用户流程（v1.2 更新）

```text
[全局热键 Ctrl+Q]
      │
      ▼
[冻结整个虚拟桌面快照] ──► 立即启动后台 OCR 预扫描（检测文字 / 预热模型）
      │
      ▼  拖拽 / 方向键微调 / 回车确认（OCR 在后台并行）
[选区完成]
      │
      ├─ 检测到文字（文本动作可用）：
      │     ├─ 文本搜索 ──► 浏览器搜索（Bing/Google/百度…）
      │     │              或 AI 搜索（DeepSeek Search API → 摘要 + 来源）
      │     ├─ 翻译     ──► 云端大模型 / 本地翻译小模型（离线可选）
      │     └─ 解答     ──► 文字/原图 → 快速/深度模式 → 流式回答
      │
      ├─ 未检测到文字（图像动作优先）：
      │     ├─ 图片搜索 ──► 视觉模型识别 → 生成检索词 → 联网搜索 → 带来源答案
      │     ├─ 图片翻译 ──► 多模态模型 / 本地翻译模型（后续）
      │     └─ 看图解答 ──► 快速/深度模式 → 流式回答
      │
      └─ 复制文字 / 重选 / ESC 取消
```

### 2.4 首次启动引导（Onboarding，v1.3 新增）

目标：用户装完软件后无需查文档，**3–5 分钟内完成「能用」的最小配置**；所有步骤可跳过、可重开，配置随时可在设置页修改。

#### 2.4.1 触发与入口

- 安装器（NSIS/WiX）完成后勾选「立即运行」自动启动应用并进入向导；绿色便携版首次运行同样触发。
- 首次运行检测 `onboarding.completed == false` 进入；完成或跳过后写入标记；升级安装不重复触发（仅提示新增功能）。
- 托盘菜单与设置页提供「重新运行引导」；重开时预填现有配置，并给「保留 / 重置」选择。
- 引导界面复用主界面主题与语言设置。

#### 2.4.2 六步结构

| 步骤 | 标题 | 主要内容 | 必填 | 可跳过 |
| --- | --- | --- | --- | --- |
| 1 | 欢迎与语言 | 中/英 UI 语言、快捷键说明、隐私摘要 | 语言 | 否 |
| 2 | AI 服务 | Base URL、API Key、模型、测试连接；预设 DeepSeek / OpenAI / 通义 / Ollama / 自定义 | 是（可跳过） | 是 |
| 3 | 翻译方式 | 云端（复用 AI 服务 / 单独 Qwen-MT Key）或本地（小模型 / 质量模型，实时下载） | 是（可跳过） | 是 |
| 4 | AI 模式 | 文本搜索、图片搜索、翻译、解答 各自 快速/深度；一键全快/全深 | 否 | 是 |
| 5 | 外观与行为 | 主题、字号、结果窗位置/置顶、开机自启、热键（含冲突检测） | 否 | 是 |
| 6 | 隐私与完成 | 上传截图开关、隐私声明同意、数据目录、更新通道；摘要 + 示例试问 | 隐私同意 | 否（不同意则进入受限模式） |

#### 2.4.3 各步骤细节

**第 1 步 · 欢迎与语言**
- 语言切换即时预览；说明 `Ctrl+Q` 会占用系统级快捷键；展示「搜索 / 翻译 / 解答」三大动作。
- 提供「跳过引导」入口，确认后进入受限模式（仅本地 OCR + 浏览器搜索）。

**第 2 步 · AI 服务**
- 供应商预设：DeepSeek、OpenAI、通义千问、Ollama（`http://127.0.0.1:11434/v1`）、自定义 OpenAI 兼容。
- 字段：Base URL、API Key、模型名。
- 「测试连接」：发一次最小请求（`/models` 或 1-token 对话），显示延迟与模型名；失败映射 401/402/429/超时/DNS，给出可操作提示。
- Key 仅存 Windows Credential Manager，输入框掩码显示；支持「稍后配置」进入受限模式（AI 动作禁用并提示）。

**第 3 步 · 翻译方式**
- 卡片选择：云端（推荐，复用第 2 步 Key；也可单独填 Qwen-MT Key）或本地（离线/隐私）。
- 本地档位：轻量档（Bergamot/OPUS-MT 类，约 100–300MB）、质量档（HY-MT1.5-1.8B，约 1.2GB，建议 16GB 内存）；展示语言、体积、内存、许可、预计速度。
- 选中后显示磁盘需求（含 20% 余量）与下载按钮；实时进度（已下载/总大小、速度、剩余时间）、暂停/继续/取消；下载完成自动 SHA256 校验并试翻一句。
- 检测本机已装 Ollama：可直接复用其模型，不重复下载。

**第 4 步 · AI 模式**
- 四行（文本搜索 / 图片搜索 / 翻译 / 解答）× 快/深 选择；每项标注预计时延与相对成本。
- 一键「全部快速 / 全部深度」；默认：搜索快、翻译快、解答快；深度仅对需要质量的功能开启，避免默认就烧额度。

**第 5 步 · 外观与行为**
- 主题：跟随系统 / 浅色 / 深色（实时预览）；字号：小 / 中 / 大。
- 结果窗：跟随选区 / 固定右下、置顶开关。
- 开机自启、启动时最小化到托盘。
- 热键录制框：按下新组合键即捕获，检测冲突，一键回退默认 `Ctrl+Q`。

**第 6 步 · 隐私与完成**
- 「允许把截图发送给视觉模型」开关（图片搜索/看图解答需要；关闭时这些动作禁用并说明）。
- 隐私声明与开源许可同意勾选（必须）；数据目录（默认 `%APPDATA%`）；更新通道（稳定/预览）。
- 完成页：配置摘要（AI 服务、翻译方式、模式、外观）+「框选示例」按钮（框选一句示例文字，走一次翻译或解答）+ 快捷键说明。

#### 2.4.4 本地模型实时下载

- 下载源：HuggingFace / ModelScope（国内镜像）可切换；断点续传（HTTP Range），失败自动重试 3 次并回退镜像。
- 校验：SHA256 + 文件大小；校验失败删除重下。
- 磁盘与内存：下载前检查可用空间（模型大小 + 20%）与可用内存，不足时提示降档或仅云端。
- 体验：下载在后台继续，关闭向导不中断；下次启动若发现未完成下载，询问是否继续。
- 目录：模型与用户数据分离（`%LOCALAPPDATA%\框选AI\models`），可在设置中迁移/清理。

#### 2.4.5 异常与边界

- 无网络：第 2/3 步提示「可先跳过，联网后再配置」，引导仍可完成。
- Key 无效/额度不足：测试连接失败，允许保存并继续（主界面会提示）。
- 下载中断/磁盘不足：给出明确原因与处理建议。
- 重复运行向导：预填现有配置，不覆盖，除非用户选择「重置」。
- 无管理员权限：安装器按用户级安装，引导不要求提权。
- 代理/内网：Base URL 支持自定义，代理设置放 P1。
- 离线安装包变体：可预置轻量翻译模型，安装后开箱即用（P2）。

#### 2.4.6 验收标准

1. 首次启动 ≤ 3 分钟（不含本地模型下载）完成最小配置；
2. 无网络 / Key 错误时仍可完成引导并进入受限模式；
3. 本地模型下载断点续传 + 校验可用，中断恢复成功率 100%；
4. 任一步可返回修改；跳过后可在设置页补齐；
5. 配置持久化，重启生效且不丢失；密钥不以明文落盘；
6. 引导默认不采集任何遥测/个人信息。

#### 2.4.7 实现与工作量

- 前端：Tauri 多步表单状态机（步骤、校验、前后导航、跳过）。
- 后端：配置 store + Credential Manager；下载器（`reqwest` + Range + `sha2` + 镜像回退）；连接测试；模型热加载/引擎重启。
- 工作量：约 7 人日（向导 UI 3、连接测试 1、下载管理 2、配置持久化与重开 1）；其中新增部分（约 5 人日）已计入 4.1 的「设置页与引导」与「本地模型下载与校验」。

## 3. 技术可行性

### 3.1 总体架构（v1.3 更新）

```text
┌──────────────────────────────────────────────────────────────┐
│                       Tauri 2 应用进程                        │
│                                                              │
│  Rust 后端                             WebView2 前端          │
│  ┌────────────────┐                   ┌──────────────────┐  │
│  │ 热键 Ctrl+Q/托盘 │                   │ 冻结层 + 选框层   │  │
│  │ 捕获与冻结      │◄── 事件/命令 ────►│ 自适应动作菜单    │  │
│  │ 坐标换算        │                   │ 结果窗(流式)      │  │
│  │ 前置 OCR 预扫描  │                   │ 快速/深度切换     │  │
│  │ OCR 引擎        │                   │ 设置页           │  │
│  │ LLM 网关        │                   └──────────────────┘  │
│  │ 搜索网关        │                                         │
│  │ 翻译引擎(云/本地) │                                         │
│  │ 引导向导/下载器  │                                         │
│  │ 凭据存储        │──► Windows Credential Manager          │
│  └────────────────┘──► RapidOCR/ONNX + llama.cpp（本地推理）│
│        │                                                     │
└────────┼─────────────────────────────────────────────────────┘
         │ HTTPS（BYOK：OpenAI 兼容协议 / Qwen-MT / DeepSeek Search API）
         ▼
   云端：DeepSeek（视觉+搜索+抓取）、Qwen-MT（翻译）、OpenAI/通义/GLM（可选）；本地：翻译小模型（llama.cpp）
```

**设计原则：**

- **前端只做展示与交互**，所有捕获、OCR、网络、密钥操作在 Rust 侧完成，减少攻击面与延迟。
- **双通道**：文本优先走 OCR → 文本提示词（快、便宜）；图片/图表/界面走原图 → 视觉模型。
- **双搜索**：文本搜索与图片搜索共用「结果渲染 + 来源展示」组件，但走不同的检索链路。
- **快速/深度**：同一套提示词与工具链，用参数（thinking、输出长度、搜索轮数、抓取条数）分档，而不是维护两套代码。
- **供应商无关**：LLM 网关统一适配 OpenAI 兼容协议；搜索网关适配 DeepSeek Search/Fetch；翻译网关适配云端模型与本地模型。
- **无服务端**：全部本地运行，开源项目不需要运维成本。

### 3.2 关键技术方案

#### 3.2.1 全局热键（v1.1 更新）

- 方案：`tauri-plugin-global-shortcut`（底层 `RegisterHotKey`），或直接调用 Win32 `RegisterHotKey` 以获得更细粒度控制。
- 默认 `Ctrl+Q`，可自定义。注意：
  - **全局热键会抢占该组合键**：注册后其他应用收不到 `Ctrl+Q`（例如 Firefox 的退出、部分编辑器的快捷键）。这是默认键位的固有代价，必须在首启引导中说明，并提供「改键」入口。
  - 注册失败（被其他程序占用）时要立即提示，并给出一键换键建议（如 `Ctrl+Shift+Q`、`Alt+Q`）。
  - 不注入键盘钩子（避免杀软误报），仅用系统热键。
  - 提供「暂停/恢复」开关（托盘菜单），方便用户临时把 `Ctrl+Q` 还给其他应用。

#### 3.2.2 冻结、前置 OCR 与框选（v1.1 新增核心流程）

- 用 `BitBlt` 截取**整个虚拟桌面**（`GetSystemMetrics(SM_XVIRTUALSCREEN / SM_CYVIRTUALSCREEN)`），得到物理像素级快照作为冻结背景；透明置顶窗口（`WS_EX_LAYERED | WS_EX_TOPMOST`，`NOACTIVATE`）覆盖所有显示器，用户在其上拖拽。
- **冻结完成即启动后台 OCR 预扫描**（单实例 worker）：
  1. 对快照做文字检测（det）：按长边降采样到约 2560–3200px 后推理，降低 4K/双屏的耗时；
  2. 同时预热 ONNX 会话（模型加载通常占首次调用的主要耗时）；
  3. 用户拖拽选区期间预扫描并行进行，鼠标抬起时若已完成，直接按选区过滤检测框，判定「选区内是否有文字」。
- **两段式 OCR**：
  - 预扫描：整屏 det，快速回答「有没有文字、大致在哪」；
  - 选区识别：对选区原图做 det + rec，得到准确文字、置信度与行框；选区小，通常 ≤ 800ms。
- **文字存在判定**：选区内检测框数量 ≥ 1、累计面积占比与平均置信度超过阈值（例如 ≥ 30% 行框置信度 > 0.8），判定为「有文字」；否则走「无文字」分支。阈值要可配置，避免误判。
- 选中即用：预扫描已命中的文本行可直接作为结果初值，用户可编辑后再搜索/翻译；未命中或预扫描未完成时，抬起鼠标后立即对选区补跑识别，期间菜单先显示「识别中」占位。
- 多显示器：一次覆盖虚拟桌面（而不是每个显示器一个窗口），处理坐标负值与混合缩放；坐标全程使用物理像素，前端 CSS 像素按 DPR 换算。
- 放大镜：从快照按光标位置取 2–4 倍区域绘制到小窗，提升小目标框选精度。
- 线程与取消：OCR worker 串行执行；用户重新框选时，旧任务带 session id 作废，避免结果错位。

#### 3.2.3 屏幕捕获

参考开源项目 Magpie 的捕获方式对比，各方式特性如下（详见参考资料）：

| 方式 | 优点 | 局限 | 建议 |
| --- | --- | --- | --- |
| GDI `BitBlt` | 简单、兼容广、忽略 DPI 虚拟化、可捕获跨屏窗口 | 不捕获 DirectComposition/UWP 内容、全屏游戏可能黑屏 | **默认兜底** |
| Windows Graphics Capture | 兼容性与流畅度最好，官方推荐 | 需要 Win10 1903+；部分场景不支持窗口捕获 | **主路径**（可选开关） |
| Desktop Duplication | 性能好，适合全屏/游戏 | 要求 Win10 2004+，API 复杂 | P2 可选 |
| DWM 共享表面 | 捕获跨屏与 DPI 虚拟化 | 性能不稳定，不推荐 | 不采用 |

结论：**BitBlt 先做、WGC 增强**。对绝大多数办公/网页/聊天场景两者都可用；游戏与 DRM 场景作为已知限制写入 FAQ。

#### 3.2.4 本地 OCR 集成

| 方案 | 中文效果 | 速度（CPU，1080p 选区） | 体积 | 许可证 | 结论 |
| --- | --- | --- | --- | --- | --- |
| Windows 系统 OCR（`Windows.Media.Ocr`） | 中等，依赖语言包，无版面结构 | 快（<200ms） | 0（系统内置） | 系统组件 | 可作为兜底，不建议主用 |
| RapidOCR（ONNX Runtime + PP-OCR） | 好，支持中英混排、表格/公式版面模型 | 约 200–500ms | 模型约 15–25MB，运行时约 10–15MB | Apache-2.0 | **推荐主用** |
| Tesseract | 中文弱，需额外训练数据 | 较慢 | 中等 | Apache-2.0 | 不采用 |
| 云端 OCR API | 最好 | 依赖网络、按次计费 | 0 | 供应商条款 | 不必要（已有视觉模型） |

实现要点：

- 图像预处理：选区放大 2 倍（小字号）、灰度化、自适应二值化、去噪；深色背景反色。
- 两段式推理：整屏只做 det（用于文字检测），选区做 det + rec（用于准确文字），降低全屏 OCR 开销。
- 输出结构：文本行 + 置信度 + 边界框；低置信度文本高亮，允许用户修正后再用。
- 模型管理：默认随包分发或首次运行下载；设置页可切换精度/速度档位（PP-OCRv4 vs v5，或轻量模型）。
- 表格/公式：P1 引入 PP-Structure 版面分析；P2 引入公式识别把公式转 LaTeX。

#### 3.2.5 云端大模型网关

- 统一走 **OpenAI 兼容协议**（`/v1/chat/completions`），支持流式 SSE；工具调用走 OpenAI 兼容的 `tools`，或直接调用 DeepSeek Search/Fetch API。
- 默认模型：`deepseek-flash`（按 DeepSeek 官方文档支持 Vision，1M 上下文，价格见 4.2）；可切换 `deepseek-v4-pro`（不支持视觉，仅文本）、OpenAI、通义千问、智谱、Moonshot，以及本地 Ollama（OpenAI 兼容端点）。
- 翻译另有专用路由：Qwen-MT（OpenAI 兼容，`translation_options` 指定源/目标语言）或本地翻译模型（见 3.2.8）。
- 能力：
  - 文本问答：OCR 文本 + 系统提示词（文本搜索/翻译/解答三种角色）。
  - 视觉问答：原图 base64 或 URL + 多轮追问上下文。
  - 联网搜索：调用 DeepSeek Search API（`/v1/tools/search`），需要时再调 Fetch API（`/v1/tools/fetch`）把网页转 Markdown 后精读。
  - 超时/重试/限流：指数退避，失败给可操作提示。
  - 费用估算：按 token 用量 × 单价实时显示。
- **思考模式开关**：DeepSeek 支持 thinking / non-thinking 两种模式，快速模式关闭思考、深度模式开启；该开关同样适用于其他兼容供应商（不支持的供应商忽略该参数）。
- 安全：密钥仅存 Windows Credential Manager，不写配置文件、不入日志；网络请求固定 HTTPS；支持自定义 Base URL（企业代理/自建网关）。

#### 3.2.6 快速 / 深度模式（v1.1 新增）

同一入口提供两档，设置页给默认档，动作菜单里可对本次请求即时切换（例如按钮旁的小切换、或按住 Shift 点击）。

| 维度 | 快速模式 | 深度模式 |
| --- | --- | --- |
| 思考模式 | 关闭 thinking | 开启 thinking |
| 模型 | `deepseek-flash`（有视觉） | `deepseek-flash` 视觉 + 可选 `deepseek-v4-pro`（纯文本任务，质量更高） |
| 提示词 | 短、约束格式、要求直接给结论 | 结构化、允许推理过程、要求给依据与来源 |
| 搜索深度 | 0–1 次搜索（可选） | 2–3 次检索 + Fetch 前 3 篇正文 |
| 输出长度 | ≤ 300 字 | ≤ 1,500 字 |
| 典型时延 | 1–3s | 5–25s |
| 相对成本 | 1x | 约 3–10x（含搜索/抓取调用） |
| 适用 | 翻译、单词/报错速查、界面文字解释 | 复杂截图理解、图表分析、需要多源交叉验证的问题 |

实现注意：

- 两档共用提示词模板，仅通过参数与工具白名单区分，避免双份维护；
- 深度模式需要明确「预算上限」（搜索次数、抓取篇数、token 上限），防止一次操作烧掉大量额度；
- 快速模式对翻译默认关闭思考（云端通用模型用非思考模式；专用翻译模型无思考参数，忽略即可）。

#### 3.2.7 搜索：文本搜索与图片搜索（v1.1 重构）

**A. 文本搜索（框选/OCR 得到文字之后）**

- 设置项 `search.mode`：
  - `browser`（默认）：生成搜索词，`ShellExecute` 打开系统默认浏览器；搜索引擎可选 Google / Bing / 百度 / DuckDuckGo / 自定义 URL 模板。
  - `ai`：调用 AI 搜索（DeepSeek Search API + 摘要生成），在结果窗内输出「结论 + 来源链接」，可继续追问。深度模式下追加 Fetch API 抓取前几篇正文。
- 文本搜索可选「先编辑再搜」：OCR 文本可修改，避免识别错误带偏搜索。

**B. 图片搜索（框选后走图像路径）**

分两层能力：

1. **AI 图片搜索（P0，推荐主路径）**：把整张选区图交给视觉模型 →
   - 识别图中内容（物体、界面、文字、图表、场景）；
   - 生成 1–3 个检索词（可带 `site:`、`lang:`、`after:` 等 DeepSeek 支持的查询运算符）；
   - 调 Search API 取摘要（`summary`/`snippet`），深度模式再 Fetch 正文；
   - 汇总为「识别结果 + 搜索结论 + 来源」三段式答案，明确标注不确定之处。
2. **反查图片（P2，可选增强）**：以图搜图，用于识别商品、地标、作品来源：
   - Google Lens：无官方 API，社区常用 SerpApi 封装（非官方抓取、按次付费，支持上传图片），稳定性受第三方服务影响；
   - TinEye：付费 API，擅长精确匹配与版权溯源；
   - Yandex 反向图搜：多为非官方封装，不推荐作为正式依赖；
   - **Bing Visual Search 已随 Microsoft Bing Search API 系列于 2025-08-11 退役**，不能作为依赖；
   - 开源项目（如 VectorGallery 等基于 CLIP 的向量检索）只解决「本地图库检索」，不覆盖公网搜索，不适合直接复用。

**C. 结果一致性**：两类搜索共用结果窗与来源列表；图片搜索必须展示「AI 识别为 X」与「检索来源」，不能把识别结论伪装成事实。

#### 3.2.8 翻译：云端大模型 + 本地翻译小模型（v1.2 重构）

需求方向：翻译不再依赖有道等专用翻译 API，改为两条路径——**云端大模型（含专用翻译模型）**与**本地翻译小模型**，二者共用「翻译」动作入口，用户可在设置中选「自动 / 云端 / 本地」。

**C. 集成方式**

- **GGUF + llama.cpp/Ollama**：HY-MT1.5 与 Qwen3 系列有官方/社区 GGUF；用 llama.cpp 或 Ollama 起本地 OpenAI 兼容端点，Rust 侧当「本地 LLM」调用并流式输出。推荐打包 llama.cpp 服务（约几 MB）+ 首次使用按需下载模型，控制安装包体积。
- **CTranslate2 / ONNX**：NLLB、OPUS-MT 可通过 CTranslate2（Rust 侧 `ct2rs` 绑定）或 ONNX Runtime 直接推理，CPU 延迟低（短句 <1s），不支持流式，作为「低配快翻」档。
- **模型管理**：模型不随安装包分发；下载前显示体积/内存/许可，支持校验、删除、切换；启动时检测可用内存，不足时提示降档。
- 本地推理默认关闭，设置页提供「离线翻译」开关；下载失败或内存不足时回退云端/轻量模型。

**D. 推荐策略（默认配置）**

| 场景 | 默认 | 说明 |
| --- | --- | --- |
| 联网、快速 | 云端 Qwen-MT-Lite 或 DeepSeek flash（短提示） | 200 字 ≤ 1.5s，成本约 ¥0.0006–0.0014 |
| 联网、深度 | 云端 DeepSeek flash（上下文 + 术语 + 格式还原） | 质量优先，可解释、可追问 |
| 离线/隐私 | HY-MT1.5-1.8B（GGUF，Q4） | 200 字 CPU 约 3–8s；首次加载模型另计 |
| 低配兜底 | OPUS-MT / HY-MT1.5-1.8B 轻量档 | 内存 <8GB 时推荐 OPUS-MT |
| 图片翻译（P2） | 多模态 LLM 或 TranslateGemma（图像翻译） | 识别 + 翻译一体 |

**E. 时延与资源参考**

- 云端 200 字：1–1.5s（网络良好）；Qwen-MT-Lite 约 0.8–1.5s。
- 本地 HY-MT1.5-1.8B Q4：CPU 约 3–8s（200 字），GPU 约 1–2s；内存/显存占用约 3–4GB。
- 本地 7B / TranslateGemma 12B：CPU 20s 以上，建议 GPU（6–8GB VRAM 起）。
- OPUS-MT/NLLB-600M：CPU 短句 <1s，长句 1–3s。

**F. 许可与合规**

- 优先集成许可宽松/可商用的模型：HY-MT1.5（混元社区许可，商用需遵守条款）、TranslateGemma（Gemma Terms）、Qwen3（Apache-2.0）、OPUS-MT（CC-BY-4.0）。
- NLLB-200 为 CC-BY-NC 4.0（非商用）：仅在非商业场景可选，UI 明确标注，不作为默认。
- 本地模型模式下翻译内容不出本机；云端模式下会发往用户自选供应商，需在隐私声明中说明。

**G. 流式与一致性**

- 云端与本地 LLM 均支持流式；专用翻译模型（Qwen-MT）走 OpenAI 兼容接口，也可流式。
- 统一术语表（`术语 → 译法`）注入提示词；格式还原（换行、列表、代码）由提示词 + 结果窗 Markdown 渲染共同保证。
- 失败回退链：本地模型失败 → 云端 → 提示用户。

#### 3.2.9 结果窗

- 独立置顶窗口（`WS_EX_TOPMOST`，`NOACTIVATE` 模式避免抢焦点），WebView2 渲染 Markdown，流式更新。
- 交互：复制、重答、追问、重新框选、放大字号、切换模型、**切换快速/深度**。
- 搜索类结果展示来源列表（标题 + 链接 + 站点）；图片搜索额外展示「AI 识别标签」。
- 结果窗与选区错位问题：默认出现在选区下方/右侧，屏幕边缘自动翻转。

#### 3.2.10 配置、密钥与更新

- 设置存储：`tauri-plugin-store`（JSON），敏感字段单独走 Credential Manager（`windows` crate 的 `CredWrite`/`CredRead`，或 `keyring` crate）。
- 需要保存的密钥：LLM API Key（可多供应商）、DeepSeek Search 使用同一 Key、可选的 Qwen-MT Key。
- 设置项：热键、搜索引擎/搜索模式、默认快速/深度、目标语言、术语表、开机自启、暂停热键、隐私开关。
- 自动更新：`tauri-plugin-updater` + 签名密钥；开源发布通过 GitHub Releases。
- 单实例：`tauri-plugin-single-instance`，重复启动时唤起已有实例。
- 引导与安装器联动（v1.3）：记录 `onboarding.completed` 与 `onboarding.version`；Tauri bundler 的 NSIS 勾选「完成后运行」；便携版通过 `portable` 标记识别，同样触发引导。
- 配置 Schema 版本化：升级时迁移字段，未知字段保留；重开向导时预填现有配置，用户可选「保留/重置」。
- 下载器（v1.3）：`reqwest` + HTTP Range 断点续传 + `sha2` 校验；支持 HuggingFace/ModelScope 镜像回退；进度通过 Tauri event 推送前端；模型目录可迁移/清理。
- 本地推理引擎：优先复用本机 Ollama（检测 `127.0.0.1:11434`）；否则启动自带 llama.cpp 服务；切换/下载模型后热重启推理进程，不重启应用。

### 3.3 技术选型对比

> 评分为主观评估（5 分制，越高越好），针对「Windows 单平台优先、轻量、开源」这一目标加权。

| 维度（权重） | Tauri 2 + Rust | C# WinUI 3 / WPF | Electron | Python + Qt |
| --- | --- | --- | --- | --- |
| 安装包体积（20%） | 5 | 3 | 1 | 1 |
| 内存占用（15%） | 4 | 5 | 2 | 3 |
| Windows 原生能力（15%） | 4 | 5 | 3 | 3 |
| 开发效率（15%） | 3 | 4 | 5 | 5 |
| 生态与插件（10%） | 4 | 4 | 5 | 3 |
| 学习成本（10%） | 2 | 3 | 4 | 4 |
| 跨平台潜力（10%） | 5 | 2 | 5 | 4 |
| 打包/签名/更新（5%） | 4 | 3 | 4 | 2 |
| **加权得分** | **~3.9** | **~3.9** | **~3.3** | **~3.1** |

**结论与建议：**

- **首选 Tauri 2**：安装包最小（空应用约 3–5MB，复用系统 WebView2），Rust 侧做 Win32 捕获/热键/OCR 推理，前端用 React/Vite 渲染流式 Markdown；后续跨平台成本最低。
- **C# 是可接受的替代**：如果你的 Windows/桌面经验主要在 .NET，WinUI 3 + .NET 8（AOT 后约 20–40MB）在原生集成、调试、UI 构建上更顺手，加权得分与 Tauri 基本持平。
- **不推荐 Electron**：安装包与内存开销与「轻量」目标冲突；**不推荐 Python**：打包体积大、杀软误报率高、GUI 与原生捕获体验一般。
- 关键判断标准不是框架，而是**交互与流程**：框架决策失误的代价远小于交互设计失误。

### 3.4 技术难点与应对（v1.3 更新）

| 难点 | 说明 | 应对 |
| --- | --- | --- |
| 混合 DPI 多屏 | 1080p/4K、不同缩放比例下的坐标错位 | 全流程使用物理像素；`PerMonitorV2` 清单；spike 阶段先验证 |
| 前置 OCR 性能 | 4K 双屏整屏 OCR 若全量识别，可能 2–5s 且占用 CPU | 整屏只做 det + 降采样；选区再做 det+rec；后台线程 + 可取消 |
| 文字检测误判 | 少量文字/图标/纹理可能误判为「有文字」 | 面积/置信度/行数阈值可调；无文字时图像动作仍可用；支持手动强制文本模式 |
| `Ctrl+Q` 全局占用 | 注册后其他应用收不到该组合键 | 首启说明 + 一键改键 + 暂停热键开关 |
| 图片搜索质量 | 视觉识别错误会导致检索方向跑偏 | 先输出识别结果供用户确认；检索词可编辑；答案标注来源与不确定性 |
| 本地翻译模型资源 | 模型 1–8GB、内存/显存占用、CPU 推理较慢 | 默认云端；本地按需下载 + 内存检测 + 轻量档（1.8B/OPUS-MT）；首次加载给提示 |
| 翻译一致性 | 云端模型与本地模型译文风格/术语不一致 | 统一术语表；结果标注后端；允许固定某一后端 |
| 全屏游戏 / DRM 黑屏 | BitBlt 与 WGC 均可能截黑 | 文档说明限制；提供 WGC 开关；不做破解 |
| 热键冲突 | 与 QQ/微信/输入法/编辑器冲突 | 可换键 + 冲突检测 + 默认避开常用键 |
| 杀软误报 | 无签名 exe、键盘热键易被误判 | 申请代码签名证书（可选）；提交误报申诉 |
| Rust 门槛 | 单人开发学习成本 | 用现成 crate/插件；Win32 代码隔离成 `platform` 模块；spike 先跑通最小闭环 |
| 视觉模型幻觉 | 解答可能编造，图片搜索可能误认 | 低温度、要求「不确定就说明」、结果标注 AI 生成、展示来源 |

| 网络与额度 | 用户无网/欠费/模型额度耗尽 | 离线 OCR 仍可用；明确错误提示；云端与本地模型互为兜底；支持本地 Ollama |

### 3.6 技术可行性结论

**可行。** 全部关键能力都有成熟方案：Tauri 2 提供框架与打包，Win32/WGC 提供捕获，RapidOCR/ONNX 提供本地识别，OpenAI 兼容协议与 DeepSeek Search/Fetch 提供多模态与联网语义能力，云端与本地翻译模型提供多档翻译能力。真正的工程挑战是**交互与兼容性细节**（DPI、多屏、热键、前置 OCR 性能、图片搜索可信度、引导与模型下载体验），而这些都可以在 1–2 周技术验证内被确认或证伪。

### 5.4 差异化定位

1. **动作导向，而非工具导向**：把「解答 / 翻译 / 搜索」做成框选后的第一等公民；冻结后先检测文字，有字走文本动作、无字自动切图片动作。
2. **轻量快速 + 托盘形态**：主安装包 ≤ 25MB、冷启动 ≤ 1.5s、空闲内存 ≤ 120MB；托盘常驻、可开机自启、用完即走，区别于 Electron 级工具。
3. **双搜索 + 双档 AI**：文本搜索可走浏览器或 AI 搜索；图片搜索把整图交给视觉模型联网；快速/深度对应「快问快答」与「认真查证」。
4. **高度自定义**：动作菜单、提示词、8+ 快捷键、主题外观、模型绑定、配置导入导出（见 2.5）。
5. **开源 + BYOK + Apache-2.0**：无服务端、不收集截图；相比 OCR-Assistant 的 CC BY-NC，许可更利于采用与二次开发。
6. **可选离线**：本地 OCR + 本地翻译模型，断网仍可识别与翻译。

**不做什么**（避免正面竞争）：长截图拼接、录屏、贴图置顶、复杂标注、批量图片处理——这些是 Snow Shot/Snipaste 的强项。

### 5.5 目标用户与价值主张

- **学生**：框选外文论文/题目 → 翻译 + 讲解，替代「复制到翻译网站再复制回来」。
- **程序员**：框选报错/文档 → 搜索 + 解释 + 修复建议。
- **办公族**：框选合同条款/邮件/表格 → 翻译 + 要点提取。
- **外语阅读者**：任意应用中的外文 → 即时翻译，不打断阅读。
- **游戏/视频用户**：框选画面内容 → 图片搜索 + 识别（受限场景，作为附加价值）。

## 6. 法律、合规与伦理

### 6.1 开源许可证

| 选项 | 特点 | 适用 |
| --- | --- | --- |
| **Apache-2.0（推荐）** | 宽松、含专利授权、商业友好、易被社区采纳 | 想最大化采用率、允许他人二次开发 |
| MIT | 最宽松、最简短 | 同上，但无专利条款 |
| GPL-3.0 | 强 copyleft，衍生作品必须开源 | 希望生态强制开源（Snow Shot 即 GPL-3.0） |
| MPL-2.0 | 文件级 copyleft，折中 | 平衡开放与商业使用 |

**建议 Apache-2.0**，理由：依赖组件（Tauri、ONNX Runtime、RapidOCR/PP-OCR 模型、`windows` crate）大多为 MIT/Apache-2.0，兼容性最好；且不排斥未来商业化。

### 6.2 数据与隐私（v1.1 补充）

- 默认**不上传**任何截图；只有用户主动点击「文本搜索（AI）/ 图片搜索 / 翻译 / 解答」且触发云端请求时才上传对应文本或图像（首次上传时弹一次告知）。
- 本地翻译模型模式下，翻译内容不出本机；云端翻译与 LLM 共用同一上传告知。
- 提供「仅本地 OCR」模式，完全禁用云端；图片搜索上线前要求勾选「允许上传截图」。
- 不采集遥测、不记录 API Key、日志默认不落盘。
- 历史记录默认仅本地存储，可一键清空。
- 隐私声明写在 README 与首启引导中，明确说明：数据会发往用户自选的 LLM/搜索/翻译供应商。

### 6.3 第三方内容与版权

- 工具只做本地识别与用户主动发起的请求，不提供批量抓取、DRM 破解、内容再分发能力。
- 用户对截图内容的合法性负责；文档中提示「请勿用于侵犯版权或泄露他人隐私的场景」。
- 图片搜索会生成检索词并访问公网，需避免抓取受版权或访问限制保护的内容。

### 6.4 API 服务条款（v1.1 补充）

- **BYOK 模式**：用户直接与 LLM、DeepSeek 搜索、云端翻译服务等供应商建立服务关系，需遵守其条款（不得转售、不得用于违法内容等）；项目方不代理、不转售 API。
- **翻译**：云端翻译走用户自选的 LLM/Qwen-MT 供应商条款；本地模型需遵守其模型许可（HY-MT 混元社区许可、Gemma Terms；CC-BY-NC 模型仅限非商业用途），并在 NOTICE 中声明。
- **搜索与图片搜索**：DeepSeek Search/Fetch 按请求计费，须遵守其使用政策；Google Lens 无官方 API，经 SerpApi 等第三方调用时，需自行评估第三方条款、稳定性与合规风险（含 Google 服务条款），不作为默认依赖。
- 若未来做「内置额度」代理服务，则需要企业资质、内容审核与成本控制，属于另一个量级的项目，当前不建议。

### 6.5 商标与命名

- 产品名需做商标检索；避免使用「Snipaste」「微信」「DeepSeek」等他人商标作为名称或暗示官方关联。
- 默认模型名、翻译服务名称仅作为配置项展示。

### 7.2 MVP 范围与量化验收标准（v1.4 更新）

MVP 只做一件事并做到顺手：

- **范围**：单/多屏文字框选 + 前置 OCR 检测；文本搜索（浏览器/AI 搜索可配）；图片搜索（AI 联网检索）；翻译（云端 + 本地可选）；解答（快速/深度可切）；首启引导与设置；托盘常驻。
- **验收**：
  1. `Ctrl+Q` 注册成功；被占用时 100% 给出可操作提示；
  2. 1080p 与 4K、双屏混合 DPI 下框选坐标误差 ≤ 2px；
  3. 整屏文字检测 ≤ 1.2s（4K 双屏，后台，不阻塞选框）；选区 OCR ≤ 800ms；
  4. 有文字/无文字两种情况下，动作菜单分支正确；
  5. 100 张典型截图（网页/聊天/文档/代码/深色模式）OCR 字符准确率 ≥ 95%；
  6. 文本搜索：浏览器 2s 内打开；AI 搜索 3s 内出摘要与 3 条来源；
  7. 图片搜索：快速模式 10s 内给出带来源的答案，且标注「AI 识别」；
  8. 翻译：云端 200 字 ≤ 1.5s；本地 1.8B 模型（Q4）≤ 8s（CPU，首次加载另计）；断网时可切换本地模式并正常翻译；
  9. 快速/深度切换后，响应时延与输出长度差异符合定义；
  10. 首次启动引导可在 3 分钟内完成；无网络/Key 错误时可跳过并进入受限模式；本地模型下载支持断点续传与校验；
  11. 冷启动 ≤ 1.5s；空闲内存 ≤ 120MB；热键 → 选框 ≤ 250ms；空闲 CPU < 0.5%；
  12. 托盘常驻、单实例；开机自启可开关；退出后 `Ctrl+Q` 热键释放；
  13. 设置中可改动作菜单组成/顺序/默认动作、提示词、8+ 快捷键、主题与模型绑定；配置可导入/导出/重置；
  14. 安装包 ≤ 60MB（含模型）；断网时 OCR 可用并明确提示云端不可用；无未捕获 panic。

## 8. 可行性结论与建议

### 8.1 结论矩阵

| 维度 | 结论 | 核心依据 |
| --- | --- | --- |
| 技术 | ✅ 可行 | 全链路均有成熟开源组件与商业 API；难点集中在 DPI/多屏/前置 OCR/热键等可验证细节 |
| 经济 | ✅ 可行 | BYOK 零服务端成本；单次 ¥0.001–0.01（翻译接近免费），深度/搜索场景约 ¥0.03–0.05；个人开发现金成本近似为 0 |
| 操作 | ✅ 可行 | 「Ctrl+Q → 框选 → 选动作」三步；有文字/无文字自适应菜单；托盘常驻 |
| 进度 | ✅ 可控 | MVP 6–7 周全职 / 约 17 周业余；v1.0 全职 11–12 周 / 业余约 6–7 个月 |
| 风险 | ⚠️ 中等 | 兼容性、`Ctrl+Q` 占用、图片搜索可信度、本地模型资源/许可、引导与下载体验、隐私、模型幻觉；均有明确缓解手段 |
| 竞争 | ✅ 有空间 | 较 OCR-Assistant 有搜索/快深/引导与许可优势；较 Snow Shot/eSearch 有「框选即问 + 双搜索 + 高度自定义」差异；需尽快发布占位 |

**最终结论：可行，建议立项。** 先完成 1–2 周技术验证（重点验证前置 OCR 与 `Ctrl+Q`），再决定框架细节与 MVP 范围；不建议一上来追求大而全。

### 8.2 建议的下一步（按顺序）

1. **确认开发栈熟悉度**：若你熟悉 .NET，C# WinUI 3 是同样可行的路径；若愿意投入 Rust，Tauri 2 的体积与跨平台优势更明显。这个决定会改变 3.3 节的最终选型，但不影响任何其他结论。
2. **选定翻译方案并准备账号**：LLM API Key（DeepSeek 等）用于云端翻译/问答；如需离线，再决定安装本地模型（HY-MT1.5-1.8B 为首选，TranslateGemma 4B 备选），并准备一台 16GB 内存的测试机。
3. **设计首启引导与自定义范围**：按 2.4 节的 6 步结构出可点击原型，明确每步字段、跳过/重开逻辑、错误提示与下载进度交互；同时按 2.5 定下 v1.0 的自定义范围与设置页信息架构。
4. **执行 1–2 周 Spike**：最小闭环 = `Ctrl+Q` → 冻结 → 前置 OCR → 框选 → BitBlt 裁剪 → 选区 OCR → 文本搜索 / 翻译（云端 + 本地各跑通一次）/ 图片搜索各跑通一次；同时打通「引导页配置 → 连接测试 → 本地模型下载」一条链路，记录各项指标（见 0 节）。
5. **按 MVP 范围实现并内部试用**：先自用 2 周，收集真实场景（尤其是混合 DPI、深色模式、小字号、无文字截图），再决定是否开源发布。
6. **开源前完成**：许可证与 NOTICE、隐私声明（含上传说明）、README 与首启引导、`Ctrl+Q` 冲突说明、GitHub Actions 打包。
7. **v0.2 起评估反查图片与内置结果页**：如果用户调研显示「浏览器跳转」或「AI 搜索摘要」仍不够，再投入 SerpApi Lens / 更深的检索链路。

### 8.3 需要你确认的关键决策点（v1.4 更新）

| 决策点 | 选项 | 影响 |
| --- | --- | --- |
| 开发语言 | Rust（Tauri）/ C#（WinUI 3） | 影响 3.3 最终选型与学习成本 |
| 默认模型 | DeepSeek（便宜、有视觉、有搜索）/ OpenAI（质量高、贵）/ 本地 Ollama（隐私） | 影响默认成本与效果；建议 DeepSeek 起步 |
| 默认热键 | 接受 `Ctrl+Q` 的全局占用 / 改用 `Ctrl+Shift+Q` 等 | 影响日常快捷键习惯；建议首启提供一键改键 |
| 首启引导 | 强制完成全部配置 / 允许跳过进入受限模式（推荐） | 影响首次体验与上手门槛；建议允许跳过 |
| 自定义程度 | 基础（热键/主题/模型绑定）/ 完整（+动作菜单、提示词、配置导入导出，推荐） | 影响 v1.0 工期与设置页复杂度 |
| 框选后默认动作 | 不自动执行（推荐）/ 自动执行最近一次动作 | 影响流畅度与误操作；建议默认不自动 |
| 本地翻译默认档 | 轻量档（约 100–300MB）/ 质量档（约 1.2GB）/ 不预装、按需下载（推荐） | 影响安装包体积、首次下载时长与低配机器体验 |
| 图片搜索主路径 | AI 视觉 + 联网搜索（推荐）/ 反查图片（SerpApi Lens，需付费与额外 Key） | 影响 P0 范围与成本 |
| 翻译默认后端 | 云端通用 LLM（DeepSeek）/ 云端专用翻译模型（Qwen-MT）/ 本地翻译小模型（HY-MT1.5-1.8B） | 影响成本、速度与隐私；建议默认云端 + 可选本地 |
| 快速/深度默认 | 默认快速，按住 Shift 深度 / 默认深度 | 影响默认响应速度与质量 |
| 首次使用是否允许免 Key 体验 | 否（BYOK）/ 是（内置试用额度，需服务端） | 后者需要后端与成本控制，当前不建议 |
