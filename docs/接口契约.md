## 1 通用约定

1. **调用方式**：前端统一通过 `@tauri-apps/api/core` 的 `invoke(command, args)`；参数对象使用 **camelCase** 键，Rust 侧命令参数使用 **snake_case**，由 Tauri 自动映射。
   - 示例：`invoke("selection_commit", { session, rectPhys })` ↔ `fn selection_commit(session: String, rect_phys: RectPhys, ...)`。
2. **返回**：所有命令返回 `Promise<T>`；失败时 reject，reject 的值为 `AppError`（JSON 对象，字段见 §8），**不是**字符串。
3. **事件**：前端 `listen(name, cb)` 订阅，载荷均为 JSON 对象；事件名全部为 `域:动作` 形式（例如 `overlay:ready`）。**注意**：Tauri 2 的 `Emitter::emit` 只允许字母数字与 `-`、`/`、`:`、`_`，**不允许 `.`**，因此事件名不能使用点分形式（早期草稿的 `overlay.ready` 写法已废弃）。
4. **命名**：`SessionId` / `TaskId` / `DownloadId` 均为 **UUID v4 小写字符串**（前端类型 `string`）。
5. **坐标**：所有 `rectPhys` 均为**物理像素**、以虚拟桌面左上角为原点的坐标系（可为负值）；前端 CSS 像素 = 物理像素 / `dpr`。前端**不得**自行换算后回传逻辑坐标。
6. **模式**：`Mode` 仅 `"quick" | "deep"` 两档。
7. **无密钥穿越边界**：任何命令的入参/出参、事件载荷中**不得**出现明文 API Key；`ConfigView` 只回掩码与 `hasKey`。
8. **骨架模式（skeleton）**：`advanced.skeletonMode` 是**开发者配置**（默认 `false`，v1.0.1 起**不在用户界面出现**，只在配置文件/环境调试时手动开启）。置 `true` 时外部能力（捕获/OCR/LLM/搜索/翻译/下载）使用按 §12 描述的确定性占位实现，事件流与真实实现一致，用于联调与排查；前端不得依赖真实网络。**v1.0.0 起不再有「更新」相关骨架行为**（自动更新已移除）。
9. **不收集任何用户信息**：v1.0.1 起产品**无遥测、无崩溃上报、无使用统计、无更新检查**；配置中不再有 `advanced.telemetry` 字段（Schema v6 迁移主动删除），任何命令/事件载荷也不得包含此类上报数据。唯一的外发请求只来自用户主动触发的云端动作（文本/图片 → 用户自配服务商）与用户主动的模型/组件下载。
9. **契约消费方**：`src/shared/contract/`（前端类型与名称常量）与 `src-tauri/src/contract/`（Rust 结构）必须逐字段对应本文。

## 2 窗口与前端路由

| WindowLabel | 路由 URL | 用途 | 创建方 |
| --- | --- | --- | --- |
| `main` | `index.html?window=main` | 设置页 + 首启引导（单窗口内路由） | `tauri.conf.json` 静态创建，`visible: false` |
| `overlay` | `index.html?window=overlay` | 冻结层 + 选框 + 动作菜单（覆盖虚拟桌面） | Rust 按需创建，复用 |
| `result` | `index.html?window=result` | 结果窗（流式输出、来源、追问） | Rust 按需创建，复用 |

- 前端入口读取 `new URLSearchParams(location.search).get("window")`；缺省（浏览器直接预览）为 `main`。
- 浏览器预览（无 Tauri）时使用 mock 后端，见 §14；支持 `?window=overlay` / `?window=result` 单独预览。
- 窗口动作命令见 `window_show` / `window_hide`（脚手架扩展）。

窗口行为约定：

| 窗口 | 装饰 | 透明 | 置顶 | 任务栏 | 尺寸 | 显示时机 |
| --- | --- | --- | --- | --- | --- | --- |
| `main` | **无（v1.0.1 起自绘标题栏）** | 否 | 否 | 显示 | 980×720（最小 820×600） | 托盘/设置/引导触发 |
| `overlay` | 无 | 是 | 是 | 隐藏 | 虚拟桌面矩形（物理像素） | `capture_freeze` |
| `result` | 无 | 是 | 是 | 隐藏 | 460×420 起，可缩放 | `menu_execute` 后由前端 `window_show` 或后端直接显示 |

**主窗口行为（v1.0.1）**：

- 无 Windows 系统标题栏；前端自绘标题栏提供拖拽移动、最小化、最大化/还原、关闭，以及八个方向的缩放手柄
  （最大化时隐藏手柄）。标题栏使用 Tauri 的 `data-tauri-drag-region` 与 `startResizeDragging`；
- **关闭按钮 / Alt+F4 = 隐藏到托盘（不退出应用）**：后端拦截 `CloseRequested` 并 `hide()`，与 `window_hide("main")` 语义一致；
  真正退出走托盘「退出」/`app_quit`；
- **托盘左键单击 = 直接打开设置**（右键才显示菜单）；托盘菜单「重新运行引导」仍可用；

**契约 v4 配置语义（追加需求：本地 GPU 推理，v5 继续沿用）**


| 字段 | 取值 | 默认 | 说明 |
| --- | --- | --- | --- |
| `local.device` | `"auto" \| "cpu" \| "gpu"` | `"auto"` | `auto` = 优先 GPU，不可用（无后端 / 无设备 / 显存不足）自动回退 CPU；`cpu` = 强制 CPU；`gpu` = 要求 GPU，仍不可用时回退 CPU 并在 `engine:status.fallbackReason` 说明 |
| `local.gpuBackend` | `"auto" \| "vulkan" \| "cuda"` | `"auto"` | **`auto` 的解析顺序为 Vulkan → CUDA → CPU**。Vulkan 跨厂商（AMD / Intel / NVIDIA 均可用）、依赖最小、无需额外 runtime，是默认 GPU 组件；CUDA 仅作为 NVIDIA 用户的可选组件 |
| `local.gpuLayers` | `u32`，`[0,512]` | `99` | offload 到 GPU 的层数；**99 = 全部**，`0` = 不 offload。`device=cpu` 时实际恒为 0（`effective_gpu_layers`） |

> 后端解析顺序固定：`gpuBackend=auto` → Vulkan → CUDA → CPU；`vulkan` → Vulkan → CPU（不回退 CUDA）；
> `cuda` → CUDA → Vulkan → CPU；`device=cpu` → 只用 CPU。设备判定**只认** `llama-server --list-devices`
> 的输出（不把 `nvidia-smi` 当判据，AMD/Intel 走同一路径）。

> **`GpuBackend` vs `LocalBackend`（契约 v4）**：配置里的 `GpuBackend = auto | vulkan | cuda` 表达**用户意图**
> （`auto` 按 Vulkan → CUDA → CPU 解析；CPU 不是可配置值，而是回退结果）；`LocalBackend = vulkan | cuda | cpu`
> 表达**实际使用的后端**，用于 `GpuDevice.backend` / `GpuBackendStatus.backend` / `BackendInfo.backend` /
> `EngineStatusPayload.backend`。`GpuProbeResult.recommended` 仍为 `GpuBackend`（只会是 Vulkan/CUDA）。
> `gpuLayers = 0` 表示不 offload（等价 `-ngl 0`），`device=cpu` 时实际层数恒为 0。

`resources/models.manifest.json` 的每个条目新增 `vramMB`（推理时显存预算，MB；与 `minRamMB` 并列），
用于 GPU 预算判定（`need = vramMB + 512 MiB`）。当前清单值：`qwen2.5-0.5b-instruct-q4`=**700**、
`hy-mt-1.8b-q4`=**1600**、`qwen3-4b-q4`=**3200**、`opus-mt-zh-en`=**0**（Ct2 非 GPU 路径）；
研究中的 1.5B=1300 仅作参考，当前清单无该条目。

### 4.3 约束（后端校验，非法即 `SA-5001`）

- `schemaVersion` 单调递增，迁移链 **`1 → 2 → 3 → 4 → 5 → 6`**（读取时依次补齐默认值，未知字段原样保留；
  v4→v5 例外：主动删除 `advanced.updateChannel` 并把 `advanced.skeletonMode` 置为 `false`；
  v5→v6 例外：主动删除 `advanced.telemetry`）。
- `providers[].baseUrl` 仅允许 `https://` 或 `http://127.0.0.1[:port]`；**不得**含用户信息（`user:pass@`）。
- `providers[].id` 唯一，仅 `[a-z0-9-_]{1,32}`。
- `modes.deepBudget`：`search ∈ [0,5]`、`fetch ∈ [0,5]`、`maxTokens ∈ [128,8192]`。
- `ui.resultWindow.opacity ∈ [0.3,1.0]`；`history.maxEntries ∈ [0,100000]`；`local.port ∈ [1024,65535]`。
- 契约 v4：`local.gpuLayers ∈ [0,512]`（99 = 全部，0 = 不 offload）；`local.model` 非空；
  `local.idleUnloadSec ∈ [0,2592000]`（0 = 常驻，上限 30 天）。
- 契约 v4：`local.device` / `local.gpuBackend` 枚举值非法由 serde 直接拒绝（命令边界返回 `SA-5001`）。
- 契约 v5：`providers[].kind` 枚举值非法由 serde 直接拒绝（`SA-5001`）；配置文件不再有 `advanced.updateChannel`。
- 契约 v6：配置文件不再有 `advanced.telemetry`（v5→v6 迁移主动删除）；`advanced.skeletonMode` 仅为开发者配置，不在用户 UI 暴露。
- `actions.menu.text/image` 每个 `ActionId` 至多出现一次；`defaultAction` 必须属于某个菜单。
- `hotkeys.*` 允许空串（表示未绑定），非空必须匹配 `^(Ctrl|Alt|Shift|Win)(\+(Ctrl|Alt|Shift|Win))*\+[A-Z0-9]$`（大小写不敏感，后端规范化为 `Ctrl+Q` 形式）。
- 配置落盘为**原子写**（`*.tmp` → rename），保留上一份有效备份 `config.json.bak`。

| `config_get` | 读取当前生效配置 → `ConfigView` |
| `config_patch` | 入参为 `DeepPartial<Config>`；深度合并 → 校验 → 原子持久化 → 广播 `config:changed` → 返回新 `ConfigView`。校验失败**不修改**任何状态 |

热生效分类（后端负责，`config:changed` 的 `changedKeys` 用点分路径，如 `ui.theme`、`hotkeys.capture`）：
即时：`ui.*`、`actions.*`、`search.*`、`translate.*`（非 local engine）、`privacy.*`；重新注册：`hotkeys.*`、`app.autostart`；重启引擎：`local.*`、`translate.backend`；需重启应用：`advanced.proxy`（标注，不强制）。

契约 v4 对 §5 的增量：

- `RunActionOptions.cover?: boolean | null`（默认 `null`）——覆盖式翻译开关；`translate_cover` 使用结构化入参（见 §6）时该字段仅作兼容保留。
- `TaskStartedPayload.parent?: TaskId | null`（`#[serde(default)]`）——**父任务**：追问 / 重答时指向上一轮任务，首轮为 `null`；前端结果窗据此区分线程首轮与追问。

会话状态机（后端强制，非法转移返回 `SA-1099`）：

```
idle → freezing → selecting → menu → executing → showingResult → idle
             ↘ 取消 → error → idle（enter_error：不可恢复的会话级异常）
```

规则：
- 同一时刻**仅一个活动会话**；新 `capture_freeze` 自动作废旧会话（旧 `ocr_session_id` 作废、旧任务取消）。
- `selection_commit` 只在 `selecting` 态合法；`menu_execute` 在 `menu` **或 `showingResult`** 态合法（后者用于结果窗「重答」：以同 action/mode 重跑，旧任务取消）；`task_followup` 只在 `showingResult` 态合法。
- `result_close` / `capture_cancel` 在任意非 idle 态合法，释放图像、取消任务、回到 `idle`。
- **契约 v4（连续提问）**：任务失败改为 `executing → showingResult`（`task_failed`），错误通过 `task:error`
  内联展示在对应轮次，之后仍可追问 / 重答；`error` 阶段**仍可到达**（`enter_error`：不可恢复的会话级异常），
  并可从 `error` 经 `result_close` / `capture_cancel` 回到 `idle`。
- **契约 v4（F1 修复）**：`task_followup` 按**当前活动会话** + `session.task_ids.last()` 定位上下文；入参 `task`
  仅作校验，任务已完成后从 `TaskStore` 移除也不再必然返回 `SA-1099`（原实现必失败，已修复并加回归测试）。
- **契约 v4（清空线程）**：结果窗「清空线程」= **结束本次对话**，前端调用既有 `result_close`（后端清空会话
  内存线程 `TurnStore` 并隐藏结果窗/覆盖层）；**不新增契约命令**，下次框选即新会话、线程重新开始。

## 7 事件表

> 事件名采用 `域:动作`（冒号）形式，见 §1 第 3 条；Tauri 2 会拒绝含 `.` 的事件名。
> 事件发送方：均来自 Rust（`AppHandle::emit`）；前端不得发送同名事件给后端（如需交互走命令）。

| 事件 | 载荷 | 触发时机 |
| --- | --- | --- |
| `overlay:ready` | `{ session, virtualRect: RectPhys, dpr: number, frame: FrozenFrameMeta }` | overlay 窗口就绪、可绘制选框 |
| `overlay:selection` | `{ session, rectPhys: RectPhys }` | 选区变化（节流 ≤ 30Hz） |
| `ocr:status` | `{ session, state: "scanning" \| "done" \| "failed", boxes?: OcrBox[] }` | 前置 OCR 状态变化 |

| `task:delta` | `{ task, kind: StreamKind, chunk: string }` | 流式增量 |
| `task:done` | `TaskDonePayload`（`{ task, usage, latencyMs, engine, sources }`） | 任务完成 |
| `task:error` | `{ task, code: string, message: string, retryable: boolean, fallback: string[] }` | 任务失败 |
| `download:progress` | `{ model, loaded: number, total: number, speedBps: number }` | 下载进度（节流 200ms） |
| `download:state` | `{ model, state: DownloadState }` | 下载状态变化 |
| `config:changed` | `{ config: ConfigView, changedKeys: string[] }` | 配置热生效 |
| `tray:action` | `{ id: string }` | 托盘菜单动作（`openSettings`/`rerunOnboarding`/`togglePause`/`quit`/`capture`） |
| `engine:status` | `{ local: EngineStatus, device?: LocalDevice \| null, backend?: LocalBackend \| null, fallbackReason?: string \| null, offloadLayers?: number \| null, deviceName?: string \| null, port?: number \| null }` | 本地推理进程状态（契约 v4 扩展：设备 / 后端 / 回退原因 / offload 层数 / 设备名 / 端口；`local` 旧字段保留） |
| `translate:progress` *(契约 v4)* | `{ session, done: number, total: number }` | 覆盖翻译批处理进度（每批后推送，节流） |
| `translate:ready` *(契约 v4)* | `{ session, blocks: CoveredBlock[], engine: string }` | 覆盖翻译完成（事件给 overlay；`translate_cover` 命令同时返回 `CoverResult` 给调用方） |

> **契约 v5 事件总数为 15 个**：删除 `update:status`（自动更新已移除，[ADR-0008](adr/0008-remove-auto-update.md)）；
> 其余事件名与载荷形状不变。

```ts
export type EngineStatus = "stopped" | "starting" | "ready" | "failed";

/** 契约 v4：`engine:status` 载荷（追加可选字段，旧字段 `local` 保留） */
export interface EngineStatusPayload {
  local: EngineStatus;
  device?: LocalDevice | null;        // 实际计算设备（解析结果）
  backend?: LocalBackend | null;      // 实际后端（含 CPU）
  fallbackReason?: string | null;     // 如「Vulkan 后端未安装，已回退 CPU」
  offloadLayers?: number | null;      // 实际 offload 到 GPU 的层数
  deviceName?: string | null;         // 如 "AMD Radeon RX 7800 XT"
  port?: number | null;               // 监听端口
}

/** 契约 v4 */
export interface TranslateProgressPayload { session: SessionId; done: number; total: number }
export interface TranslateReadyPayload { session: SessionId; blocks: CoveredBlock[]; engine: string }
```

事件发送方：均来自 Rust（`AppHandle::emit`）。前端**不得**发送同名事件给后端（如需交互走命令）。

## 12 骨架模式（skeleton）行为规范

`advanced.skeletonMode = true`（**开发者配置：默认 `false`，v1.0.1 起不在用户界面出现**，见 §4.1）时，以下行为**必须**可确定性复现，
便于前端联调与排查「行为是否来自真实后端」：

| 能力 | 行为 |
| --- | --- |
| 捕获 | 不调用 Win32；用主显示器逻辑尺寸 × `dpr` 合成 `FrozenFrameMeta { width, height, dataUrl: null }`；`overlay:ready` 正常发出（`frame.dataUrl === null`，前端渲染占位背景） |
| 前置 OCR | 150ms 后 `ocr:status(scanning)` → 400ms 后 `done`；`boxes` 为单条覆盖选区的占位框；`hasText = true`；`preview = "【骨架模式】本地 OCR 未接入，此为占位识别文本。"` |
| 文本搜索（browser） | 不打开浏览器；任务直接成功，结果文本说明「骨架模式：将打开浏览器搜索 “<query>”」 |
| 文本搜索（ai）/ 解答 / 追问 | `task:started` 后以 25–40ms/块流式输出固定占位回答，`kind="text"`；`task:done` 含 `usage {inputTokens:120,outputTokens:60,cachedInputTokens:0,costEstimate:0.0,currency:"CNY"}`、`latencyMs` 为真实耗时、`engine="skeleton"` |
| 图片搜索 | 同上，附 2 条占位 `sources` |
| 翻译 | 流式输出 `【骨架模式译文】` + 原文 |
| 下载 | 未开始下载时为 `idle`（v6）；若清单文件存在则按占位进度（每 100ms 4%，到 100% 后 `installed`，写入空的 `models/<id>/.installed`）；不存在则 `download:state(failed)` |
| 引擎状态 | `engine:status(local: "stopped")`，不启动进程 |
| `local_gpu_probe` *(契约 v4)* | **真实探测**（子进程 `llama-server --list-devices`，不受 `skeletonMode` 影响）：干净环境（无后端组件/无驱动）返回 `useable=false` + `issue` 可操作原因（「未检测到可用 GPU 后端，将使用 CPU」），不伪造设备 |
| `local_engine_status/start/stop` *(契约 v4)* | 真实引擎监督者（本批已落地）；骨架模式不伪造 `ready`：无可用后端/模型时返回 `SA-4001`/`SA-4002` 可操作错误 |
| `backends_list/download/cancel/remove` *(契约 v4)* | 清单与安装状态真实读取；下载走真实 Range/SHA256/解压（未开始时 `idle`，开始后 `queued`/`downloading`），骨架预览不联网 |
| `translate_cover` *(契约 v4)* | 真实链路统一走 `AppState::gateway_for`（skeleton → 本地引擎 `ensure_ready` → 云端有密钥走真实 SSE）；未配置云端/本地翻译链路时返回确定性占位译文（`"【骨架模式译文】" + source`，`engine="skeleton"`），并推送 `translate:progress` / `translate:ready`；**失败块保留原文且 `failed=true`，不伪造成功** |
| 更新 | **已移除**：v1.0.0 无自动更新命令/事件/配置；骨架模式也没有更新占位行为 |
| 外部打开 | `open_external` 仅打印日志，不实际打开 |
| 凭据 | 内存 map，进程退出即丢 |

实现位置：各 `services/*` 内部的 `Skeleton*` 变体 + `platform::capture::SkeletonCapturer`；由 `AppState.settings.skeleton_mode` 决定分支。
v1.0.1 的真实能力（BitBlt 捕获、RapidOCR ONNX、云端网关、Credential Manager、历史持久化）已接入，骨架模式仅保留为开发者调试分支、**不在用户界面暴露**。

**契约 v4 · 网关选择策略（`AppState::gateway_for`，所有 LLM 动作共用）**：

| 条件 | 行为 |
| --- | --- |
| `advanced.skeletonMode = true` | 直接 `SkeletonLlmGateway`（确定性占位，`engine="skeleton"`） |
| 路由 `engine = "local"` | 先 `LocalEngine::ensure_ready`（Vulkan → CUDA → CPU 回退），就绪后走 `http://127.0.0.1:<port>` 的 OpenAI 兼容端点（**base_url 不含 `/v1`**，网关拼接 `/v1/chat/completions`） |
| 云端供应商 | **已配置密钥** → 真实流式 SSE 网关；**无密钥** → 回退骨架网关并 `tracing::warn` 告警（**不伪造真实结果**；覆盖翻译此时 `engine="skeleton"`） |

> 该策略保证「本地优先可离线、云端需 Key、骨架仅占位」的边界一致；`menu_execute` / `task_followup` /
> `translate_cover` 均经 `gateway_for` 选择网关，不在各命令内重复分支。

| 命令注册 | `commands/mod.rs` 汇总 `tauri::generate_handler![...]`；每个命令 `pub async fn xxx(app: AppHandle, state: State<'_, AppState>, ...) -> Result<T, AppError>` |
| 事件发送 | `events/mod.rs` 提供 `emit_overlay_ready(...)` 等强类型助手，内部 `app.emit(EVENT_OVERLAY_READY, payload)`；`EVENT_*` 常量与 §7 一致 |
| 时间 | `chrono::DateTime<Utc>` 序列化为 RFC3339 字符串；目录/日志用本地时区展示 |
| 值类型 | `SessionId`/`TaskId`/`DownloadId` 用 `#[serde(transparent)] pub struct XxxId(pub String)`，`Display`/`From<String>` 齐全 |
| 错误 | 命令返回 `Result<T, AppError>`；内部错误用 `thiserror` 的 `AppError`/`ServiceError`，转换时补全 `code/message/fallback` |
| 日志 | `tracing`；**禁止**记录 OCR 文本原文、密钥、完整 URL 查询串（可记录 host） |

## 16 兼容与版本策略

- `IPC_CONTRACT_VERSION = 1`，出现在 `Stats.contractVersion`；破坏性变更需递增，并在 `docs/接口契约.md` 修订记录中说明。
- 新增可选字段：前端必须容忍未知字段；后端必须提供默认值（`#[serde(default)]`）。
- 新增命令/事件：只增不改；删除需走两个版本弃用期，并在托盘/设置页提示。
