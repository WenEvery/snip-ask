## 1 脚手架目标与非目标

**目标**

1. 把《概要设计说明书》的 M01–M20 模块**一一映射**到代码目录，边界清晰、可独立演进。
2. 锁定前后端 IPC 契约（**38 命令 / 16 事件** / 错误码 / 配置 Schema **v4**），并用 TS 类型与 Rust `contract` 模块双向约束。
3. 跑通「热键 → 冻结 → 框选 → 菜单 → 流式结果」的空壳闭环（骨架模式下用确定性占位实现），使前后端与 UI 可并行开发、可手动验收。
4. 把不可逆的横切决策提前落地：分层依赖方向、数据目录、配置迁移与原子写、密钥边界、日志脱敏、单实例/托盘/自启、本地模型目录、**GPU 后端解析顺序（Vulkan → CUDA → CPU）与本地引擎进程模型**。
5. 交付可用的工程底座：pnpm 脚本、TS 类型检查、CI（Windows runner 上 cargo fmt/clippy/test + Web 构建）、Apache-2.0 + NOTICE、开发指南与 ADR。

**非目标（本阶段不做）**

- 真实 BitBlt/WGC 捕获、RapidOCR/ONNX 推理（仍为 trait 桩 + TODO，见 §9）；云端 LLM 已接入真实 SSE 网关，但仍缺
  DeepSeek Search/Fetch 工具客户端与 Qwen-MT 专用参数。
- 安装包签名、自动更新通道、多语言 UI 全量翻译（仅预留）。
- 长截图/录屏/标注等非范围能力。
- 实时穿透式覆盖翻译（研究 §2.3 已论证高风险）；本批只做**冻结帧覆盖层**形态。

**前端规则**

- 只做渲染与交互：不直接访问网络、不读取密钥、不写配置文件；所有能力经 `ipc.invoke`。
- 所有跨窗口状态来自后端事件或命令返回值，**不使用 localStorage 存业务数据**（仅 mock 模式例外）。
- 窗口按 `?window=` 决定渲染内容；`main` 窗口内部用轻量路由（`main` / `settings` / `onboarding`）切换，不引入 react-router。
- 单文件 ≤ 300 行，超出拆子组件；CSS 用原生 CSS + token，不引入运行时 CSS-in-JS。
- TS 严格模式：`strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes` 关闭（便于与 Rust Option 对应），`noImplicitOverride`、`noUnusedLocals` 开启。
- mock 后端必须与契约 §12 行为一致，保证「无 Rust 环境也能完整走 UI 流程」。
- **覆盖翻译（契约 v4）**：`translationLayout.ts` 必须是**零依赖纯函数**（`node --test` 直接跑 TS 测试），
  Canvas 渲染与 dpr 换算只在 `TranslationOverlay.tsx` 做一次；overlay 的 `translating → covered` 只是**前端子阶段**，
  后端会话始终保持 `showingResult`（有意偏差，见契约 §6 第 38 行注释），避免破坏已冻结的会话状态机。
- **连续提问（契约 v4）**：结果窗以 `turns[]` 线程模型渲染，`task:started.parent` 区分首轮/追问；流式期间禁用追问输入。

**依赖方向（单向，CI 用 clippy/评审保证）**

```
commands → services → domain
    │           │
    │           └→ platform (trait)
    └→ app/state, events
domain 不得依赖 services/commands/platform（纯逻辑）
platform 不得依赖 services/commands（只被 services 调用）
contract 不得依赖其余任何模块（被 commands/events/services 依赖）
```

- `domain` 内禁止 `tauri`、文件/网络 IO、`std::process`；纯函数 + 结构体，全部可单测。
- `platform` 是唯一可以被 `unsafe` 与 `windows` crate 污染的地方；对外暴露 trait（`ScreenCapturer`/`HotkeyRegistrar`/`CredentialStore`/`EngineProcess`）。
- Tauri 的 `AppHandle` 只出现在 `commands`/`app`/`events`；`services` 通过 `EventSink` trait 发事件，便于测试。

### 4.1 本地 GPU 模块（契约 v4，Vulkan 优先）

**分层**（自下而上，均保持单向依赖）：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| platform | `platform/gpu.rs` | 发现 `llama-server.exe`、执行 `--list-devices` / `--version` 子进程并解析；虚拟/软件适配器过滤；厂商归类；显存预算 `need = vramMB + 512 MiB`；`recommend_backend`（Vulkan 优先）；60s 缓存。**禁止 unsafe**，系统信息一律子进程获取 |
| services | `services/backend_manager.rs` | 后端组件清单（`resources/backends.manifest.json` + 安装状态合并）、Range 断点续传下载、SHA256 校验、`tar.exe -xf` 解压、`.installed` 标记、删除 |
| services | `services/local_engine.rs` | `plan_attempts`（回退链）+ `build_args`（**显式 `-ngl`** / `--device`）+ spawn + `/health` 等待 + 日志解析（offload 层数 / `using device Vulkan0`）+ 空闲卸载 + **按 PID/进程树**清理 |
| services | `services/local_gateway.rs` | OpenAI 兼容流式 SSE（`/v1/chat/completions`），本地与云端共用；429/5xx 退避、取消、usage |
| commands | `commands/local.rs` | 薄命令：`local_gpu_probe` / `local_engine_*` / `backends_*` |

**Vulkan 优先原则（本批核心约束，详见 [ADR-0006](adr/0006-vulkan-first-gpu-inference.md)）**：

- 解析顺序：`gpuBackend=auto` → **Vulkan → CUDA → CPU**；`vulkan` → Vulkan → CPU（不回退 CUDA）；
  `cuda` → CUDA → Vulkan → CPU；`device=cpu` → 只用 CPU。
- 理由：Vulkan 跨厂商（AMD Radeon / Intel Arc / NVIDIA 全支持）、依赖最小、无需额外 runtime DLL；
  CUDA 仅 NVIDIA、需额外 CUDA runtime，故只作**可选组件**。体积以 `resources/backends.manifest.json` 为准：
  本批 llama.cpp `b12128` 构建 Vulkan **37,684,327 B**、CUDA 288,918,265 B + cudart 391,443,627 B、CPU 24,730,477 B；
  研究期（2.28 构建）估算为 Vulkan ≈55.8 MB / CUDA + runtime ≈0.9 GB。
- **AMD 可用性是验收项**：探测/启动逻辑不得把 `nvidia-smi` 当可用判据；`nvidia-smi` 只作补充展示（可选、失败静默）。
- 目录布局：`<backends_root>/{vulkan,cuda,cpu}/llama-server.exe`；查找优先级
  `SNIP_ASK_BACKENDS_DIR`（开发/验证钩子）→ `<data_dir>/backends/<variant>/` → `<resource_dir>/backends/<variant>/`。
- 运行参数：`-ngl <gpuLayers|99>`（CPU `-ngl 0 -t <threads>`）、`--device Vulkan0|CUDA0`、`--host 127.0.0.1 --port <p>`；
  端口在 `39281..=39289` 内探测；`/health` 200 → ready（超时 20s）；日志写 `<data_dir>/logs/engine-<timestamp>.log`。
- **主安装包只带 CPU 后端**（体积门禁 ≤25 MiB）；Vulkan 按需下载为默认 GPU 组件，CUDA 为可选组件。

## 5 运行时视图

### 5.1 窗口与进程

- 单进程；本地推理以 **sidecar 子进程**接入：`services/local_engine.rs` 监督 `llama-server.exe`
  （spawn → `/health` → 日志解析 → 空闲卸载 → 按 PID/进程树回收），API 走 `http://127.0.0.1:<port>`，
  与云端共用 OpenAI 兼容流式网关 `services/local_gateway.rs`。
- 窗口：`main`（静态、隐藏、设置/引导）· `overlay`（惰性、按虚拟桌面矩形）· `result`（惰性、流式）。
- 单实例：`tauri-plugin-single-instance`，第二实例唤起已有实例并聚焦/提示后退出。
- 托盘：Tauri 原生 `TrayIcon`（非 Web 实现），菜单项：开始框选 / 设置 / 重新引导 / 暂停热键 / 退出。

### 5.2 线程模型

| 线程/任务 | 职责 | 约束 |
| --- | --- | --- |
| 主线程 | Tauri 事件循环、窗口操作、托盘 | 不阻塞；重活进 tokio/blocking |
| tokio runtime | 命令异步、流式任务、下载、定时器 | 每个任务登记 `TaskId`，可取消（`CancellationToken` 等价物用 `AtomicBool`+任务表） |
| OCR worker | 前置整屏 det（单 worker 串行） | 新会话作废旧 `ocr_session_id`；不阻塞选框 |
| 引擎监督者 | 本地 `llama-server` 子进程 spawn/健康检查/日志解析/空闲卸载 | 启动失败按 Vulkan → CUDA → CPU 回退；进程清理**只按 PID/进程树** |
| GPU 探测 | `--list-devices` 子进程 + 60s 缓存 | 在 blocking pool 执行（`spawn_blocking`），不阻塞主线程 |
| blocking pool | SQLite、文件、哈希校验、解压（`tar.exe`） | 统一 `spawn_blocking` |

### 5.3 会话状态机（实现于 `domain::session`）

```
Idle → Freezing → Selecting → Menu → Executing → ShowingResult → Idle
          │           │          │        │
          └───────────┴──────────┴────────┴→ Error → Idle（取消后回 idle）
```

- `SessionStore` 持有 `Option<Session>`，`Session { id, phase, frame, ocr_session_id, selection, task_ids }`。
- 非法转移返回 `SA-1099`；新会话自动取消旧会话（旧任务 `task_cancel` → 不再推送事件）。
- **契约 v4（连续提问）**：任务失败改为 `Executing → ShowingResult`（`SessionStore::task_failed`，错误通过
  `task:error` 内联展示），失败后仍可追问/重答；`Error` 阶段仍可经 `enter_error` 到达（不可恢复的会话级异常），
  并可从 `error` 经 `result_close` / `capture_cancel` 回到 `Idle`。
- 结果窗关闭（`result_close`）必须释放 `frame`、取消活动任务、回到 Idle，并触发本地引擎空闲卸载计时；
  **契约 v4** 起同时清空会话内存线程（`TurnStore::clear`）——结果窗「清空线程」= 结束本次对话，复用该命令。
- **覆盖翻译**：`translate_cover` 不推进后端会话阶段（仅允许 `Menu` / `ShowingResult`，保持原阶段），
  overlay 的 `translating → covered` 只是前端子阶段。

## 8 横切约定

- **错误**：命令边界统一 `AppError { code, message, detail, retryable, fallback[], context }`；错误码见契约 §8.2；前端 toast 统一处理。
- **日志**：`tracing` + `tracing-appender`；级别 `error/warn/info/debug`；禁止记录 OCR 原文、密钥、完整查询串；日志初始化早于配置加载失败分支。
- **配置热生效**：`config:changed { config, changedKeys[] }`；设置页只重渲染受影响分组；热键/自启类改动由后端重新注册。
- **密钥**：仅 `CredentialService` 访问；请求前取用、用完即弃；`ConfigView` 仅掩码。
- **网络**：真实实现只允许 HTTPS（本地引擎 `http://127.0.0.1`）；超时/重试策略（429/5xx/超时，指数退避 ≤2 次）集中在校验网关，不散落。
- **隐私**：文本/图像上传开关同时控制动作可用性与实际请求；`localOnly` 时云端动作 `enabled=false` 并给 `disabledReason`。
- **可测性**：`domain` 全部纯逻辑单测；services 依赖 trait 注入，可用 fake 引擎测降级链。

### 9.1 P0 Spike 实测实现边界（2026-11-04/05）

> 来源：`docs/技术验证清单.md` P0（S-01 ~ S-08）首轮 spike；逐项证据见 `docs/spikes/`，复跑脚本见 `scripts/spikes/`。
> 达标项按此边界实施；FAILED/BLOCKED 项（S-03 选区 OCR、S-05 本地翻译、S-06 图片搜索）需先完成技术方案决策。

- **坐标 / overlay**：单个 overlay 窗口覆盖虚拟桌面物理外接矩形（本机 (-1080,-470) 3640×1920），按
  `PhysicalSize/Position` 设置并以 `inner_position()` 校正 client 原点（无边框阴影 inset 实测 (11,2)px，已用
  `.shadow(false)` + 校正消除）。跨屏窗口在 Windows 下只有一个 DPI（按最大重叠显示器，本机 1.5），**前端必须用
  该窗口的 `devicePixelRatio` 统一换算**，逐屏 dpr 混用会产生数百 px 偏移；100% 副屏上的 UI 会偏小（坐标精度不受影响），
  若要各屏 UI 等大需「每屏一个 overlay」。显示器热插拔/分辨率变化目前靠每次 `capture_freeze` 幂等重对齐兜底。
- **OCR**（2026-11-05 已按 S-02/S-03 决策落地）：det 耗时由「降采样后的像素面积」决定，而非屏幕数量。
  实现采用**双约束像素预算**：`scale = min(detMaxEdge/max(w,h), sqrt(3.0Mpx/(w×h)))`、绝不放大
  （`services/ocr_service.rs::det_input_size`，默认 `DET_PIXEL_BUDGET=3_000_000`；低配 profile 建议 2.5Mpx）。
  实测 P95：双 4K 7680×2160→3200×900 **743ms**；单 4K 3840×2160→2309×1299 **794ms**（旧长边口径 3200×1800
  为 1682ms，超 1.2s）；主屏 2560×1440→2309×1299 **761ms**。ONNX Runtime `intra_op` 6–8 线程最优。
  选区 OCR 采用**整屏 det 缓存 → 选区过滤 + rec-only**（`OcrPipeline`：det 缓存按 `ocr_session_id`，
  帧局部↔绝对物理坐标平移；缓存缺失/无命中回退选区 det+rec），实测该口径 P95 **596ms**（目标 800ms），
  已落地 `OcrEngine::{detect, recognize, detect_and_recognize}` 与 `commands/{capture,selection}.rs` 接线；
  真实 ONNX 引擎实现仍为 `TODO(real)`（当前为骨架引擎，pipeline/时序/坐标口径已按真实引擎设计）。
- **翻译**（2026-11-05 实测结论）：云端 DeepSeek `deepseek-flash` 默认 thinking 时 TTFT P95 **4591ms**（快速模式
  首字 1.5s 不达标），**必须显式传 `thinking:{"type":"disabled"}`**（TTFT P95 **865ms** 达标，总耗时 P95 1755ms
  略超 1.5s）；`reasoning_effort/effort=low` 无效。HY-MT1.5-1.8B Q4 纯 CPU（16 线程，`-ngl 0`）≈17.6 tok/s，
  200 字 P50 11.76s / P95 21.84s、常驻 2.1GiB → **CPU 上 8s 阈值不可达**；因此引导页提供三档可选：
  **云端（推荐）/ 极小本地模型 / 普通本地模型（质量优先但慢）**，并显式提示性能与隐私/成本权衡。
  本地极小档已定为 **Qwen2.5-0.5B-Instruct Q4 + 精简提示词**（`resources/prompts/translate_minimal.md`，实测 P95 3.21s、
  常驻 ≈0.55GiB；质量一般，长文建议云端）；普通档仍为 HY-MT1.5-1.8B。提示词按 `action_router::translate_prompt_key`
  路由（本地极小模型 → `translate_minimal`，其余 → `translate`）；提示词维护注释头由 `prompt_engine` 渲染前剔除。
  OPUS-MT 因官方无 Ct2 产物暂不可下载（清单 `urls` 空、`verified=false`）。
- **下载**：`reqwest` + HTTP Range 断点续传/镜像回退/流式 SHA256/大小校验已实现（`.partial` 保留，中断恢复 100%）；

  `qwen2.5-0.5b-instruct-q4` 491,400,032 B / sha256 已核验）中 opus-mt 仍缺官方 Ct2 产物（`urls` 空）。

- **热键**：OS 级探测通过「临时注册 + 立即注销」实现（无泄漏）；暂停时**保留 `togglePause`、释放其余热键**，退出/暂停

### 9.3 追加需求实现边界（契约 v4，2026-11-05）

> 来源：[`docs/追加需求可行性研究.md`](追加需求可行性研究.md) + 实施规范（`.verify/plan/spec.md`）。
> 本批由 Agent Teams 并行落地并完成全量门禁；**最终通过/失败矩阵与原始输出以 `.verify/verify-<时间戳>/SUMMARY.md` 为准**，
> 真机证据在 `.verify/evidence/`（gitignored，本地证据不入库）。

- **需求一 · 本地 GPU 推理（Vulkan 优先）**：
  - 配置 v4（`local.device` / `gpuBackend` / `gpuLayers`，迁移链 1→2→3→4，`gpuLayers ∈ [0,512]`）；
    探测只认 `llama-server --list-devices`（本机实测 `Vulkan0: NVIDIA GeForce RTX 4060 Laptop GPU (7956 MiB, 7180 MiB free)`），
    `nvidia-smi` 仅作补充展示、失败静默；缓存 60s。
  - 引擎监督者：`auto` → **Vulkan → CUDA → CPU**；显式 `-ngl`/`--device Vulkan0|CUDA0`；`/health` 20s；
    日志 offload 行解析；按 PID/进程树清理；空闲卸载 `idleUnloadSec`（0=常驻）。
  - 分发：主安装包只带 CPU 后端；**Vulkan 为默认 GPU 组件按需下载**（AMD/Intel/NVIDIA 通用）；
    CUDA（含 runtime）为 NVIDIA 可选组件。体积以 `resources/backends.manifest.json` 为准
    （b12128：Vulkan 37,684,327 B / CUDA 288,918,265 B + cudart 391,443,627 B / CPU 24,730,477 B；
    研究期估算为 Vulkan ≈55.8 MB、CUDA + runtime ≈0.9 GB）。
  - **真机验证结果（2026-11-05，NVIDIA RTX 4060 Laptop，证据 `.verify/evidence/`）**：
    `local_gpu_probe` → `useable=true`、`recommended="vulkan"`、预算 `{requiredMb:2112, availableMb:7180, fits:true}`；
    仅 CPU 后端时 `useable=false` + `issue="未检测到可用 GPU 后端，将使用 CPU"`；CUDA 组件在本机 `--list-devices`
    无输出 → `available=false`（可选组件未生效，符合预期）。真实 Vulkan 引擎（`-ngl 99 --device Vulkan0`，1.8B Q4）：
    `/health` 就绪 **2188 ms**、日志 `offloaded 33/33 layers to GPU` + `using device Vulkan0`、
    真实 `/v1/chat/completions` 流式输出 **90 ms**、`nvidia-smi` 佐证 **3477 MiB**、`taskkill /PID /T /F` 后无残留；
    CPU 回退（`-ngl 0`）同一请求 **482 ms** → 约 **5.4×** 加速差异（单次短请求）。后端组件真实下载：
    llama.cpp 官方 `b12128` Vulkan 包 **37,684,327 B**、SHA256 校验一致（`hashSkipped=false`）、
    跨进程 Range 续传（20,540,416 → 37,684,327）、解压后官方 exe 复测 `Vulkan0`。
  - **如实标注**：AMD 真机**未测**（本机无 AMD 卡）。兼容性论证为「Vulkan 路径无 NVIDIA 专属依赖」
    （不以 `nvidia-smi` 为判据、不依赖 CUDA DLL、`--device Vulkan0` 由 llama.cpp 自身枚举），
    不等价于 AMD 实机验证；AMD 实机列入遗留验证项。
  - 与 S-13 的关系：8GB 机型显存/内存降档提示仍是产品缺口（S-13 IN PROGRESS），本批只做显存预算提示（`GpuBudget`）。
- **需求二 · 覆盖式翻译（冻结帧覆盖层）**：
  - 只做「冻结帧 Canvas 覆盖」形态；**不实时穿透、不修改目标应用**（研究 §2.3 已排除 B/C 方案）。
  - 前端 `translationLayout.ts` 纯函数：OCR 行→段块合并（研究实测 2288→1552 块，−32.2%）、字号 0.60–1.00×源行高
    （5% 步长，P50≈0.80）、自动换行、溢出降级小气泡（不截断）、深/浅底字色与对比度衬底、`clampRect`。
  - 后端 `translate_cover`：**不推进后端会话阶段**（仅接受 `menu` / `showingResult` 并保持原阶段，
    `translating → covered` 只是前端子阶段）；10 块/批、**缓存键 `session:sha1(规范化原文+目标语言+模型)` /
    LRU 512 / 按会话隔离**（新框选不命中旧会话）；真实链路统一 `AppState::gateway_for`
    （skeleton → 本地 `ensure_ready` → 云端有密钥），失败块保留原文 `failed=true`（不伪造成功）；
    `translate:progress` / `translate:ready`；`engine` 如实（`skeleton` / 供应商 id / `local`）。
  - 浏览器 mock 演示证据（`.verify/evidence/overlay-cover/`，**非生产链路**）：`engine="skeleton"`（确定性占位译文），
    冻结帧为 mock 中生成的**真实位图**、OCR 行框为真实四行框 → 覆盖模式 Canvas 采样 `opaque=46964/50400`（非空画布，
    模糊+遮罩+译文生效）、切回原文 `opaque=0`；三态切换/ESC 两段语义正确、控制台 0 异常；7 张截图 + `demo-log.json`。
    **仍不能替代**真实捕获/真实 OCR/真实翻译质量的生产验收。
  - 边界：DRM/全屏独占/无 `dataUrl` → 明确降级提示，不能覆盖（S-09 实测结论）。
- **需求三 · 连续提问（多轮追问）**：
  - **F1 修复**：`task_followup` 按当前会话 + `session.task_ids.last()` 定位，不再因任务移出 `TaskStore` 必然 `SA-1099`。
  - `TurnStore` 记录（原始问题 + 完整回答 + engine），追问注入「选区 + 最近 N 轮问答（截断）」；
    `TaskStartedPayload.parent` 区分首轮/追问/重答；失败改为 `executing → showingResult`（`task_failed`），
    `error` 仍可经 `enter_error` 到达；失败后仍可追问/重答。`result_close` 同时清空 `TurnStore`。
  - 结果窗 `turns[]` 线程：历史折叠、仅最后一条流式、错误内联、流式禁输入、重答清空线程、清空线程。
  - mock 追问守卫与真实后端一致。**未做**：`messages` 表持久化 / 历史恢复 / token 预算（完整版范围）。
- **本批明确未覆盖**：真实 BitBlt/WGC 捕获与 RapidOCR（仍 `TODO(real)`，与三项需求的覆盖翻译前置相关）；
