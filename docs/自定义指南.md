## 1 先读：本软件不自动更新

v1.0.0 已彻底移除自动更新：没有 `tauri-plugin-updater`、没有更新检查、不联网查询版本、
配置里没有更新通道字段（v4 的 `advanced.updateChannel` 已在 schema v5 迁移中删除）；
**v1.0.1 起不收集任何用户信息**（无遥测、无崩溃上报、无使用统计；v5 的 `advanced.telemetry` 已在 schema v6 迁移中删除）。
应用内「设置 → 自定义与关于」只有版本信息与目录入口，**没有任何“检查更新”行为**。

升级只有两种方式：

| 方式 | 做法 | 数据影响 |
| --- | --- | --- |
| **覆盖安装新版安装包** | 下载新版 `SnipAsk_<版本>_x64-setup.exe`（或内置 OCR 模型版）→ 直接双击安装（同用户级安装） | 保留 `%APPDATA%\SnipAsk`（配置/提示词/历史）与 Windows 凭据；只在升级跨 schema 版本时自动迁移配置（v1.0.0 → v1.0.1 为 v5 → v6，自动删除遥测字段） |
| **自行源码构建** | 见 §10，改用你自己的代码/资源后构建安装包 | 同上 |

> 卸载会删除程序文件，但**保留** `%APPDATA%\SnipAsk` 与 `%LOCALAPPDATA%\SnipAsk`（模型/缓存）。
> 覆盖安装前仍建议备份 `config.json` 与 `prompts\`（见 §11）。
> **降级注意**：旧版本程序不识别 schema 5 的 `config.json`，回滚到 v0.x 前请先备份配置；
> 回滚后若配置加载失败，删除 `config.json` 会回到默认配置（历史库不受影响）。

## 2 自定义入口一览

| 入口 | 位置 | 适合改什么 |
| --- | --- | --- |
| 设置页「自定义与关于」 | 应用主窗口 → 设置 → 自定义与关于 | 查看版本 / 安装包类型（内置 OCR 模型 / 在线下载）/ 文字识别就绪、一键打开配置/提示词/模型/日志/后端/安装文档目录；无自动更新说明 |
| 设置页其他分组 | 核心 / 外观 / AI 服务 / **搜索** / 翻译 / **隐私** / 动作与热键 / 高级 | 常用偏好（v1.0.1 起搜索与隐私为独立分组） |
| 窗口与托盘 | 标题栏按钮 / 托盘图标 | 最小化、最大化、关闭到托盘；托盘左键打开设置、右键菜单可重新运行引导 |
| 配置文件 | `%APPDATA%\SnipAsk\config.json` | 全部偏好与阈值（改前退出应用，避免被内存中的配置覆盖） |
| 提示词覆盖目录 | `%APPDATA%\SnipAsk\prompts\*.md` | 6 个提示词模板（用户 > 内置，即时生效） |
| 环境变量（调试钩子） | 启动应用前设置 | 指定 GGUF、后端目录、OCR 资产目录、日志级别 |
| 源码构建 | 仓库 `scripts\` | 改代码、改内置资源、构建两个安装包（在线安装版 / 内置 OCR 模型版） |

「设置 → 自定义与关于」的目录按钮最终调用契约命令 `open_path(kind)`，白名单与打开内容：

| `kind` | 打开的目录 |
| --- | --- |
| `config` / `data` | `%APPDATA%\SnipAsk`（配置、提示词、日志、历史库同级；不存在会自动创建） |
| `prompts` | `%APPDATA%\SnipAsk\prompts` |
| `models` | `%LOCALAPPDATA%\SnipAsk\models`（本地模型与 OCR 模型） |
| `logs` | `%APPDATA%\SnipAsk\logs` |
| `backends` | 本地推理后端根目录（`%APPDATA%\SnipAsk\backends`，见 §7） |
| `docs` | 安装目录 `docs\`（自定义指南/README/许可/安全与隐私说明；**仅安装版存在**，开发模式直接看仓库 `docs/`） |

非法 `kind` 返回 `SA-5001`；`docs` 缺失返回可操作的 `SA-5003`。
便携模式（程序目录存在 `portable.flag`）下，上述数据目录改为程序目录旁 `data\`。

## 3 提示词覆盖（最常改）

### 3.1 文件与位置

把与内置同名的 `.md` 文件放进 `%APPDATA%\SnipAsk\prompts\`，**用户文件优先于内置**，下次动作立即生效（无需重启）：

| 文件 | 用于 | 可用变量 |
| --- | --- | --- |
| `text_search.md` | AI 文本搜索 | `{text}` `{lang}` `{mode}` |
| `image_search.md` | 图片搜索（视觉识别 + 检索 + 摘要） | `{lang}` `{mode}` |
| `translate.md` | 云端 / 本地普通模型翻译 | `{text}` `{targetLang}` `{sourceLang}` `{glossary}` |
| `translate_minimal.md` | **仅本地极小模型**（Qwen2.5-0.5B 档）翻译 | 同 `translate.md` |
| `answer.md` | 看图解答 | `{text}` `{lang}` `{mode}` |
| `followup.md` | 结果窗追问 | `{question}` `{context}` |

变量取值：`text` 为 OCR/选区文本，`lang` 为界面语言（`zh-CN`/`en-US`），`mode` 为 `quick`/`deep`，
`targetLang` 默认 `zh-CHS`（BCP-47 / ISO 639-1 均可，如 `zh-CHS`、`en`、`ja`），`sourceLang` 缺省 `auto`，
`glossary` 为渲染后的术语表文本，`question` 为用户追问，`context` 为「选区 + 最近若干轮问答」摘要。

### 3.2 规则（必须知道）

1. **维护注释头会被剔除**：文件开头以 `#` 开头的行与空行不会发给模型；从第一个非 `#` 行起才是正文。
   可放心用 `#` 写自己的备注。
2. **已知变量不能删**：渲染后若仍残留任一已知变量（如 `{text}`），返回 `SA-5001` 并提示缺哪个变量。
3. **未知花括号原样保留**：例如 `{"a": 1}` 这种 JSON 片段不会被当作变量。
4. **翻译提示词按模型路由**：`translate.backend=local` 且 `local.model` 属于极小模型档
   （`qwen2.5-0.5b-instruct-q4` / `qwen2.5-1.5b-instruct-q4`）时用 `translate_minimal.md`，
   其余情况用 `translate.md`；两个文件都可覆盖。
5. 提示词改动不影响内置文件；删除用户文件即恢复内置模板。

### 3.3 示例：把翻译改成「只给译文、保留代码块、语气口语化」

`%APPDATA%\SnipAsk\prompts\translate.md`：

```markdown
# 我的自定义翻译提示词（这一行是注释，不会发给模型）
你是翻译引擎。把下面的文本翻译成 {targetLang}。

要求：
1. 只输出译文，不要解释、不要原文对照。
2. 保留换行、列表、编号、URL、邮箱与代码块原样。
3. 术语表：{glossary}（表中词必须使用指定译法，空表则按领域惯例）。
4. 语气自然口语化，不要书面腔。

待翻译文本（源语言：{sourceLang}）：
{text}
```

> 改完在同一个框选内容上重跑「翻译」即可验证；失败时看 `%APPDATA%\SnipAsk\logs\` 的错误与字段名。

## 4 术语表（`translate.glossary`）

配置字段 `translate.glossary` 是 `[{ "from": "原文", "to": "译文" }]` 数组。
对 LLM 翻译会渲染成 `原文 => 译文; 原文2 => 译文2` 填进 `{glossary}`；
对 DashScope Qwen-MT（`providers[].kind = "qwenMt"`）会转成原生 `translation_options.terms`。

| 改法 | 说明 |
| --- | --- |
| 设置页 → 翻译 → 术语表 | 逐条增删（推荐） |
| 直接改 `config.json` | 修改前退出应用；保存后重启生效 |

示例（产品名/技术名词不翻译或固定译法）：

```json
"translate": {
  "backend": "cloud",
  "providerId": "deepseek",
  "model": "qwen-mt-lite",
  "targetLang": "zh-CHS",
  "glossary": [
    { "from": "SnipAsk", "to": "SnipAsk" },
    { "from": "API", "to": "接口" },
    { "from": "prompt", "to": "提示词" }
  ]
}
```

> 如实说明：术语命中受模型能力影响，S-14 实测云端术语 100% 命中；本地普通模型格式保持并非 100%，
> 需要强一致时优先云端，或在自定义提示词里再次强调。

## 5 配置字段速查（Schema v6）

完整默认值见 [`接口契约.md` §4.1](接口契约.md)；这里只列**你大概率会改**的字段。
修改方式：设置页（推荐）、`config_patch`（热生效、原子写）、或退出应用后直接编辑 `config.json`。
`schemaVersion` 必须为 **6**；非法值返回 `SA-5001`，不会写入部分配置。
从 v1.0.0（schema 5）升级时自动迁移：删除 `advanced.telemetry`，其余配置保留。

### 5.2 `providers[]`（AI 供应商）

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一，仅 `[a-z0-9-_]{1,32}`；凭据按该 id 存放 |
| `name` | 界面显示名 |
| `baseUrl` | 仅允许 `https://…` 或 `http://127.0.0.1[:port]`；不得含 `user:pass@` |
| `model` | 模型名（原样传给供应商） |
| `kind` | 契约 v5 新增：`openAiCompatible`（默认，OpenAI 兼容 Chat Completions）或 `qwenMt`（DashScope Qwen-MT 原生翻译） |
| `caps` | `vision` / `search` / `thinking` / `translate`，决定哪些动作可用 |
| `temperature` | `[0,2]`，默认 `0.2` |
| `maxTokens` | `[1,131072]`，默认 `1024` |
| `enabled` | 是否启用（禁用后不参与网关选择） |

默认三条：`deepseek`（启用）、`dashscope`（`qwenMt`，默认禁用，配 DashScope Key 后启用）、
`generic-openai`（OpenAI 兼容，默认禁用）。

### 5.3 `translate` / `local` / `ocr` / `privacy`

| 字段 | 取值 / 默认 | 说明 |
| --- | --- | --- |
| `translate.backend` | `cloud` / `local` | 翻译走云端还是本地引擎 |

| `privacy.allowTextUpload` | `true` | 允许文本上传云端 |
| `privacy.allowImageUpload` | `true` | 允许图像上传云端 |
| `privacy.localOnly` | `false` | `true` 时禁用全部云端动作 |

### 5.4 改坏了怎么办

1. 退出应用，删除 `%APPDATA%\SnipAsk\config.json` → 下次启动写回默认配置（schema 5）。
2. 或用上一份有效备份 `config.json.bak` 覆盖回 `config.json`。
3. 配置是**原子写**（`*.tmp` → rename）且每次写入前校验，正常使用不会写坏；
   手工编辑后若格式/取值非法，启动时加载失败会记录日志并回退到默认配置。

## 6 本地翻译模型替换

### 6.1 内置清单与下载位置

`resources/models.manifest.json`（编译内嵌）是模型清单的来源，`local.model` 填清单里的 `id`。
应用内下载的 GGUF 落在 `%LOCALAPPDATA%\SnipAsk\models\<id>\<模型文件名>`（同目录 `.installed` 为安装标记）；
在线安装版的文字识别模型统一在 `%LOCALAPPDATA%\SnipAsk\models\ocr\`。
**下载状态（v1.0.1）**：未开始下载时显示「未下载」（`idle`），点击下载后才进入排队/下载/校验；
下载中可取消（保留断点，可恢复）；失败可重试。

| 清单 id | 类型 | 大小 | 说明 |
| --- | --- | --- | --- |
| `qwen2.5-0.5b-instruct-q4` | GGUF | 491,400,032 B | 极小档（本地翻译最快，质量一般，配 `translate_minimal.md`） |
| `hy-mt-1.8b-q4` | GGUF | 1,133,080,512 B | 默认本地翻译模型（质量优先，纯 CPU 较慢） |
| `qwen3-4b-q4` | GGUF | 2,497,280,256 B | 更大模型（显存/内存需求高，8GB 机器不建议） |
| `opus-mt-zh-en` | Ct2 | 314,572,800 B | 预留条目（当前无可用官方产物，`urls` 为空） |

### 6.2 换成任意 llama.cpp 兼容 GGUF（调试钩子）

不想走清单/下载流程时，用环境变量直接指向本机 GGUF（仅调试用，产品不暴露）：

```powershell
$env:SNIP_ASK_MODEL_PATH = "D:\models\my-model.Q4_K_M.gguf"
pnpm dev        # 或启动已安装的 snip-ask.exe（从同一终端继承环境变量）
```

启动后 `local.model` 仍按配置展示，但引擎实际使用该文件；换模型后建议：
`local.device=auto`、`local.gpuLayers=99`（显存不足改为 8–24）。**兼容性**：需要是 llama.cpp 能加载的
GGUF 架构（Qwen/Llama/Mistral 等主流架构均可）；不兼容的模型引擎会启动失败并在 `engine:status` 给出原因。

### 6.3 替换后端（llama-server）

后端目录布局：

```text
<backends_root>\
├── vulkan\llama-server.exe   (+ 依赖 DLL；AMD / Intel / NVIDIA 通用)
├── cuda\llama-server.exe     (+ cudart64_12 / cublas64_12 / cublasLt64_12.dll；仅 NVIDIA)
└── cpu\llama-server.exe      (随主安装包分发)
```

`<backends_root>` 查找优先级：

1. 环境变量 `SNIP_ASK_BACKENDS_DIR`（**调试钩子**，指向含 `vulkan/`、`cuda/`、`cpu/` 的目录）；
2. `%APPDATA%\SnipAsk\backends\`（应用内「下载 GPU 组件」的安装位置）；
3. `<安装目录>\resources\backends\`（随包分发的 CPU 后端）。

把任意官方/第三方 Windows llama.cpp 构建按上述目录放好即可替换（版本不同参数兼容性请自测）；
旧的 `llama-server` 进程只会按 PID/进程树回收，不会误杀其它同名进程。

## 7 接本地 Ollama / llama-server / 自建网关

只要对方提供 **OpenAI 兼容** 的 `/v1/chat/completions`，就能作为供应商接入（校验仅允许
`https://` 或 `http://127.0.0.1[:port]`，因此本机服务可直接用 `127.0.0.1`）。

### 7.1 接 Ollama（默认 11434）

设置页 → AI 服务 → 新增供应商：

| 字段 | 值 |
| --- | --- |
| `id` | `ollama` |
| `name` | `本地 Ollama` |
| `baseUrl` | `http://127.0.0.1:11434` |
| `model` | 已拉取的模型名，如 `qwen2.5:7b` |
| `kind` | `openAiCompatible` |
| `caps` | 按能力勾选（`vision` / `search` / `thinking` / `translate`） |
| `enabled` | `true` |

API Key 可留空（Ollama 默认不校验）；保存后点「测试连接」走 `GET {baseUrl}/models` 验证可达。
本机回环地址（`127.0.0.1`）的请求**不会走系统代理**，因此本地服务无需额外配置代理例外。

### 7.2 接本机 llama-server / 其它网关

`baseUrl` 填 `http://127.0.0.1:<port>`（llama-server 默认 8080 端口），`model` 随意填（llama-server 忽略模型名）。
OneAPI / New API / LiteLLM 等网关若对外暴露 https 域名，按普通 OpenAI 兼容供应商接入即可。

> 注意：`kind="qwenMt"` 只用于 DashScope 原生翻译端点；普通网关翻译请用 `openAiCompatible` +
> `translate.backend="cloud"` + 对应 `providerId`。

## 8 双版本安装包与 OCR 资产

### 8.1 内置 OCR 模型版 / 在线安装版 差异

| | **在线安装版** | **内置 OCR 模型版** |
| --- | --- | --- |
| 安装包文件名 | `SnipAsk_<版本>_x64-setup.exe` | `SnipAsk_<版本>_x64-full-setup.exe` |
| ONNX Runtime（`onnxruntime.dll`） | 内置 | 内置 |
| 文字识别模型（det/rec/cls + 字典） | **不内置**，首次使用文字识别时下载（约 16 MB） | **内置**，离线开箱即用 |
| 安装包体积门禁 | ≤ 25 MiB | ≤ 60 MiB |
| `Stats.edition` | `slim` | `full` |
| 适合 | 网络可用、想要小安装包 | 离线/内网/不想下载模型 |

> 开发态（`pnpm dev` / `pnpm build` 未注入 `SNIP_ASK_EDITION`）时 `edition = "dev"`。
>「设置 → 自定义与关于」会显示**安装包类型（已内置文字识别模型 / 首次使用时下载）**与文字识别就绪状态。

### 8.2 运行期 OCR 资产与解析顺序

固定文件名（5 个）：

| 文件 | 字节数（本机开发缓存实测） | 说明 |
| --- | --- | --- |
| `onnxruntime.dll` | 19,288,888 | ONNX Runtime 1.31.1（两个版本都内置） |
| `ch_PP-OCRv4_det_infer.onnx` | 4,745,517 | 文本检测 |
| `ch_PP-OCRv4_rec_infer.onnx` | 10,857,958 | 文本识别 |
| `ch_ppocr_mobile_v2.0_cls_infer.onnx` | 585,532 | 方向分类 |
| `ppocr_keys_v1.txt` | 26,250 | rec 字典（6,623 行，UTF-8） |

运行期解析顺序（引擎加载资产与 `ocr_status` 状态展示使用同一顺序）：

1. **随包资源** `<安装目录>\resources\ocr\`（内置 OCR 模型版含模型；在线安装版只有 `onnxruntime.dll`）；
2. **数据目录** `%LOCALAPPDATA%\SnipAsk\models\ocr\`（在线安装版首次下载到这里）；
3. **开发钩子** `SNIP_ASK_OCR_DIR`（指向一个含上述文件的目录，便于内网/离线验证）。

启动时应用会把解析到的 `onnxruntime.dll` 写入 `ORT_DYLIB_PATH` 供 `ort`（load-dynamic）使用。

### 8.3 手动放置模型（离线/内网）

在线安装版无法联网下载时：从可联网机器取得 4 个模型/字典文件，按**固定文件名**放进
`%LOCALAPPDATA%\SnipAsk\models\ocr\`，重启应用后「设置 → 自定义与关于」或 `ocr_status` 应显示
`ready=true`、`missing=[]`。文件不匹配（文件名/大小/SHA256）时 `ocr_status.missing` 会列出缺哪一项，
并给出可操作提示。

SHA256 与下载 URL 以 `resources/models.manifest.json` 中 `role=ocr` 的 4 条条目为准
（id：`ocr-det` / `ocr-rec` / `ocr-cls` / `ocr-dict`）。

## 9 行为与界面的深度自定义

### 9.1 常见组合

| 想要 | 改什么 |
| --- | --- |
| 换框选热键 | `hotkeys.capture`（如 `Ctrl+Alt+A`，冲突时先用 `hotkey_probe` 探测） |
| 只要翻译与解答，不要搜索 | `actions.menu.text = ["translate","answer","copy"]` |
| 默认走深度模式 | `actions.defaultMode = "deep"`，或各 `modes.*` 分别设 `deep` |
| 完全离线 | `privacy.localOnly = true` + `translate.backend = "local"` + 下载本地模型与 GPU/CPU 后端 |
| 结果窗固定位置/更透明 | `ui.resultWindow.position = "fixed"`、`opacity` |
| 旧机器强制 CPU | `local.device = "cpu"`（`gpuLayers` 实际恒为 0） |
| 显存紧张 | `local.gpuLayers = 8~24`，或 `local.device = "cpu"` |
| 长文本翻译更稳 | `modes.translate = "deep"`、`modes.deepBudget.maxTokens` 提高到 2048 |

### 9.2 配置热生效

| 改动 | 生效方式 |
| --- | --- |
| `ui.*`、`actions.*`、`search.*`、`translate.*`（非本地引擎）、`privacy.*` | 立即 |
| `hotkeys.*`、`app.autostart` | 后端重新注册 |
| `local.*`、`translate.backend` | 重启本地引擎 |
| `advanced.proxy` | 建议重启应用 |

### 9.3 开发者配置：骨架模式（`advanced.skeletonMode`）

`advanced.skeletonMode` 默认 **`false`**，v1.0.1 起**不在用户界面出现**，仅供开发/排查时手动编辑配置文件开启：
开启后捕获/文字识别/LLM/搜索/翻译都切到确定性占位实现（不联网、不读密钥），事件流与正常实现一致，
用于联调或确认「行为来自后端还是本地模拟」。**日常使用请保持 `false`**。

### 9.4 历史与数据

- 历史消息写入 `%APPDATA%\SnipAsk\history.db`（SQLite，`messages` 表）；`history.enabled=false` 时不写。
- 主窗口可浏览历史会话与完整问答线程（`history_list` / `history_thread`）；
  「清空历史」= `history_clear`（传 `session` 清单个，不传清全部）。
- 日志在 `%APPDATA%\SnipAsk\logs\`，**不含**识别原文、密钥与完整查询串；
  调日志级别：`$env:RUST_LOG = "snip_ask_lib=debug,info"`。

### 9.5 窗口、托盘与隐私

- 主窗口无系统标题栏，自绘标题栏可拖拽移动、最小化、最大化/还原、关闭，并支持八向缩放；
- **关闭按钮 / `Alt+F4` = 隐藏到托盘**（不退出），框选热键继续可用；彻底退出用托盘「退出」；
- 托盘左键打开设置，右键菜单可开始框选 / 重新运行引导 / 暂停热键 / 退出；
- 设置页独立分组：核心 / 外观 / AI 服务 / 搜索 / 翻译 / 隐私 / 动作与热键 / 高级 / 自定义与关于；
  上传开关与「只在本机处理」在「隐私」分组；
- **不收集任何用户信息**：无遥测、无崩溃上报、无使用统计、无更新检查；配置中也没有遥测字段（v6）。

## 10 构建你自己的版本

### 10.1 环境要求

| 工具 | 版本 | 说明 |
| --- | --- | --- |
| Windows | 10（1903+）/ 11，x64 | 目标平台 |
| Node.js | ≥ 20（推荐 22 LTS） | 前端构建与单测 |
| pnpm | ≥ 9（仓库按 11 校验） | 包管理 |
| Rust | stable ≥ 1.77 + MSVC Build Tools 2022 | 桌面构建（含「使用 C++ 的桌面开发」工作负载） |
| WebView2 Runtime | Win11 自带 | Windows 10 由安装器安装 |

### 10.2 常用命令

```powershell
pnpm install
pnpm typecheck       # tsc --noEmit
pnpm test            # 前端纯逻辑单测
pnpm build:web       # 类型检查 + vite build → dist/
pnpm dev             # tauri dev（需 Rust）
pnpm build           # 生成开发版 NSIS 安装包（edition=dev）
```

### 10.3 构建两个安装包（在线安装版 / 内置 OCR 模型版）

```powershell
# 1) 准备 OCR 资产到 src-tauri/resources/ocr/（优先用本机缓存，其次按 manifest 下载，强校验 SHA256）
powershell -ExecutionPolicy Bypass -File scripts\fetch-ocr-assets.ps1

# 2) 构建并归档（默认 both；含体积门禁 + 真实安装/启动/卸载冒烟）
powershell -ExecutionPolicy Bypass -File scripts\build-installers.ps1
powershell -ExecutionPolicy Bypass -File scripts\build-installers.ps1 -Edition slim
powershell -ExecutionPolicy Bypass -File scripts\build-installers.ps1 -Edition full -SkipSmoke
```

| 参数 | 作用 |
| --- | --- |
| `-Edition slim\|full\|both` | 构建哪些版本（默认 `both`；`slim` = 在线安装版、`full` = 内置 OCR 模型版） |
| `-SkipFetch` | 跳过 OCR 资产准备（假设已就位） |
| `-SkipBuild` | 跳过编译，只对 `release/` 现有安装包做体积门禁与冒烟 |
| `-SkipSmoke` | 跳过真实安装冒烟（**最终交付不建议**） |
| `-AllowMissingDocs` | 开发期允许安装包内 `docs/` 资源缺失（产物不可作为最终交付） |

产物：`release\SnipAsk_<版本>_x64-setup.exe`（在线安装版）、`release\SnipAsk_<版本>_x64-full-setup.exe`（内置 OCR 模型版），
并生成 `release\SHA256SUMS.txt`；体积门禁 **在线安装版 ≤ 25 MiB、内置 OCR 模型版 ≤ 60 MiB**，超限退出码 1。
脚本会在编译期注入 `SNIP_ASK_EDITION=slim|full`（`Stats.edition` 来源），因此两个版本**必须分别编译**
（脚本内部先 `cargo clean -p snip-ask` 保证 `option_env!` 重新求值）。

### 10.4 安装包内 `docs/`

安装目录会随附 `docs\`：`README.md`、`自定义指南.md`、`LICENSE`、`NOTICE`、`SECURITY.md`、`PRIVACY.md`，
供应用内 `open_path("docs")` 打开。改文档后重新构建即可随包更新。

### 10.5 分发注意事项

- 许可证：Apache-2.0。分发修改版需保留 `LICENSE` 与 `NOTICE`，并在修改过的文件上标注改动；
- 未签名：当前构建**未做代码签名**，他人下载后 SmartScreen 可能提示「未知发布者」；
- OCR/推理模型：模型与运行时有其各自许可，随包分发时请遵守 `NOTICE` 与模型卡条款；
- 不引入自动更新：这是 v1.0.0 的明确产品决策（见 [ADR-0008](adr/0008-remove-auto-update.md)）；
  如需自行分发升级，覆盖安装即可（§1）。

## 12 如实说明的限制

- **不收集任何用户信息**：无遥测、无崩溃上报、无使用统计、无更新检查。
- **无自动更新、无代码签名**：升级靠手动覆盖安装；SmartScreen 提示属预期。
- **AMD / Intel 真机 GPU 未在本机实测**：Vulkan 路径按「无 NVIDIA 专属依赖」论证（不依赖 CUDA DLL、
  不以 `nvidia-smi` 为判据），兼容性需你自行验证；本机（RTX 4060 Laptop）已实测 Vulkan 真实推理。
- **Qwen-MT**：本机无 DashScope Key，仅做协议级/单元测试验收，真实翻译未在本批验收；接入时请自备 Key
  并启用 `dashscope` 供应商（`kind="qwenMt"`）。
- **受保护内容**：DRM / 全屏独占可能黑屏（Windows 截图限制），返回 `SA-1001` 并提示，不做绕过。
- **本地小模型质量/格式**：极小档（0.5B）响应快但质量一般；本地模型实测可能出现提示词残留/格式保持问题
  （S-14 与 E2E：1.5B 本地译文含 1 行 `Term List…` 提示词残留），长文/专业内容或强格式要求建议云端。
- **窗口行为**：关闭/`Alt+F4` 为隐藏到托盘（不是退出），首次使用请留意托盘图标。
- 界面文案目前以中文为主（`en-US` 为预留），多语言 UI 未全量翻译。
