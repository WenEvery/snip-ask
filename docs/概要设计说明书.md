## 1 引言

### 1.1 编写目的

为「框选 AI」v1.0 提供实现层面的总体设计依据：明确系统分层、模块边界、关键流程、接口契约、数据结构、异常与降级策略、性能预算与部署方式，使开发、测试与后续维护对系统有一致理解。

### 1.2 适用范围

- 适用于 Windows 桌面端（安装版与便携版）的客户端开发。
- 覆盖 MVP 与 v1.0 范围；P2 能力（插件、公式、跨平台）仅预留扩展点，不展开设计。
- 云端服务不在本项目范围内：所有 AI 能力均为 **BYOK**，由用户自备 API Key 直连供应商。

### 1.3 术语与缩写

| 术语 | 说明 |
| --- | --- |
| 冻结层（Freeze） | 热键触发时对虚拟桌面拍照，并以静止画面覆盖屏幕的透明置顶层 |
| 前置 OCR | 冻结后立即在后台执行的整屏文字检测，用于决定动作菜单分支 |
| 选区（Selection） | 用户在冻结层上拖拽出的矩形，内部统一换算为物理像素坐标 |
| 动作（Action） | 框选后可执行的能力：文本搜索、图片搜索、翻译、解答、复制文字等 |
| 快 / 深（Mode） | AI 请求的两档参数集：快速 = 关思考、短输出；深度 = 开思考、多步检索 |
| 会话（Session） | 一次「热键 → 框选 → 动作」的生命周期，用 `session_id` 标识 |
| 任务（Task） | 一次具体的 AI/搜索/翻译请求，用 `task_id` 标识，可流式输出、可取消 |
| BYOK | Bring Your Own Key，用户自备模型/搜索服务密钥 |
| WGC | Windows Graphics Capture，Win10 1903+ 屏幕捕获 API |

## 2 总体设计

### 2.1 设计目标

| 目标 | 量化指标 |
| --- | --- |
| 轻 | 主安装包 ≤ 25MB（不含模型）；模型按需下载；不引入 Electron 级运行时 |
| 快 | 冷启动 ≤ 1.5s；常驻召出 ≤ 200ms；热键 → 选框 ≤ 250ms；动作菜单 ≤ 100ms |
| 稳 | 托盘常驻 + 单实例；空闲 CPU < 0.5%、内存 ≤ 120MB；异常可恢复、可降级 |
| 自定义 | 动作菜单、提示词、≥8 项快捷键、主题外观、模型绑定、配置导入/导出 |
| 开 | Apache-2.0；BYOK；无服务端；不收集截图与遥测 |
| 可选离线 | 本地 OCR + 本地翻译模型，断网可识别、可翻译 |

### 2.2 设计原则

1. **分层隔离**：UI（WebView）只负责渲染与交互；捕获、OCR、网络、密钥、推理全部在 Rust 侧，减少攻击面与跨进程开销。
2. **事件驱动**：前端与后端通过「命令 + 事件」通信；长任务（AI 流式、下载）以事件推送进度，避免轮询。
3. **能力路由**：动作不直接绑定供应商，而是由「能力（vision / search / translate / ocr）+ 配置」决定实际引擎，便于换供应商与降级。
4. **懒加载**：窗口、WebView、本地推理进程、历史库均按需创建；空闲时卸载重资源。
5. **可降级**：任何外部依赖失败都有明确回退路径（云 → 本地 → 浏览器 → 仅 OCR），并向用户说明。
6. **默认安全**：密钥只进 Windows 凭据管理器；HTTPS（本地回环除外）；配置导出不含密钥；无遥测。
7. **可测试**：坐标换算、动作路由、提示词构建、费用估算、配置迁移等纯逻辑与平台层解耦，可单元测试。

### 2.3 系统架构

```text
┌─────────────────────────────────────────────────────────────────────┐
│                          表现层（WebView2）                         │
│  冻结层/选框层 · 动作菜单 · 结果窗 · 设置页 · 首启引导 · 主题系统    │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ Tauri IPC（命令 / 事件）
┌──────────────────────────────┴──────────────────────────────────────┐
│                        应用层（Rust 服务）                          │
│  应用生命周期 · 会话状态机 · 动作路由 · 配置中心 · 引导服务         │
│  托盘/自启 · 热键 · 历史/用量 · 错误与降级 · 事件总线               │
└──────────────────────────────┬──────────────────────────────────────┘
┌──────────────────────────────┴──────────────────────────────────────┐
│                        能力层（引擎与平台）                         │
│  捕获/冻结 · 坐标换算 · 前置 OCR · 图像处理 · LLM 网关              │
│  搜索网关 · 翻译引擎 · 本地模型下载/校验 · 本地推理管理             │
│  凭据存储 · 配置持久化 · 日志/更新                                  │
└──────────────────────────────┬──────────────────────────────────────┘
┌──────────────────────────────┴──────────────────────────────────────┐
│                    外部依赖 / 操作系统能力                          │
│  Win32（热键、窗口、BitBlt/WGC、Credential Manager、自启注册）      │
│  ONNX Runtime（OCR） · llama.cpp/Ollama（本地 LLM）                 │
│  HTTPS：OpenAI 兼容 API / DeepSeek Search / Qwen-MT                 │
└─────────────────────────────────────────────────────────────────────┘
```

分层职责：

| 层 | 职责 | 不做什么 |
| --- | --- | --- |
| 表现层 | 渲染冻结画面、绘制选框与菜单、流式 Markdown、设置与引导表单 | 不做捕获、不碰密钥、不发网络请求 |
| 应用层 | 维护会话状态机、编排动作、选择引擎、管理配置与任务、统一错误提示 | 不直接调用 Win32 细节 |
| 能力层 | 捕获、OCR、推理、下载、存储、更新的具体实现 | 不感知 UI 布局 |
| 外部 | 操作系统 API、推理运行时、模型供应商 | — |

### 2.4 技术选型

| 领域 | 选型 | 理由 |
| --- | --- | --- |
| 桌面框架 | Tauri 2（Rust + WebView2） | 安装包小、复用系统 WebView2、前端可快速实现流式 Markdown 与主题 |
| 语言/运行时 | Rust 2021 + async（tokio） | 与 Win32/ONNX/llama.cpp 集成好，内存与启动可控；无 GC |
| 前端 | React 18 + TypeScript + Vite（+ Tailwind 或 CSS 变量） | 生态成熟；主题与自定义成本低 |
| 屏幕捕获 | GDI `BitBlt`（兜底）+ WGC（增强） | 兼容性与性能平衡；Magpie 的对比结论 |
| OCR | RapidOCR（PP-OCR ONNX）+ ONNX Runtime | 中文本地识别成熟、体积可控、Apache-2.0 |
| 本地翻译 | llama.cpp（GGUF）或复用本机 Ollama；低配可选 CTranslate2 | 统一 OpenAI 兼容接口，接入成本低 |
| 云端 AI | OpenAI 兼容协议（默认 DeepSeek flash，可换 Qwen-MT 等） | 换供应商只改配置；流式与工具调用统一 |
| 搜索 | 浏览器跳转 / DeepSeek Search + Fetch | 零成本与高质量联网两条路径 |
| 存储 | JSON 配置 + SQLite（历史/用量，可选关闭） | 轻量、可迁移、可导出 |
| 密钥 | Windows Credential Manager | 系统级加密存储，不入配置文件 |
| 打包/更新 | NSIS 安装器 + `tauri-plugin-updater`（签名） | 用户级安装、签名更新、可静默升级 |

### 2.5 运行环境

- 操作系统：Windows 10 1809（Build 17763）及以上 / Windows 11；x64（ARM64 后续）。
- 依赖：Microsoft Edge WebView2 Runtime（Win11 自带；Win10 由安装器检测并引导安装）。
- 硬件建议：4GB 内存起；本地翻译模型建议 8–16GB；GPU 可选（llama.cpp CUDA/Vulkan 加速）。
- 磁盘：主程序 + OCR 模型 ≤ 60MB；本地翻译模型按需 0.1–8GB；历史与缓存 < 100MB。

### 2.6 部署视图

```text
安装包（NSIS，用户级）
  ├─ 主程序（Tauri 应用）
  ├─ OCR 运行时与模型（随包）
  ├─ llama.cpp 运行时（随包，约数 MB）
  └─ 可选：开机自启注册项（默认不勾选）

首次运行
  → 单实例检测 → 托盘启动 → 6 步引导（可跳过）
  → 按引导配置：AI Key / 翻译方式（可选本地模型下载）/ 快深默认 / 外观 / 热键
  → 完成后进入托盘常驻

按需资源（不随包）
  ├─ 本地翻译模型（GGUF/CT2，下载到 %LOCALAPPDATA%\SnipAsk\models）
  └─ 历史/缓存（SQLite、日志）
```

便携版：程序目录下放 `portable.flag` 时，配置与数据写入程序目录旁 `data\`，仍触发首启引导。

### 2.7 关键设计决策（ADR 摘要）

| # | 决策 | 备选 | 取舍理由 |
| --- | --- | --- | --- |
| D1 | 单进程 + 可选 sidecar 推理 | 全部进程内 | 推理崩溃隔离；不拖慢 UI；本地模型可热重启 |
| D2 | 一个覆盖虚拟桌面的冻结层 | 每显示器一个窗口 | 多屏/混合 DPI 坐标统一，交互简单 |
| D3 | 整屏只做文字检测，选区再做识别 | 整屏全量 OCR 复用 | 4K 双屏全量识别 2–5s，无法接受 |
| D4 | 动作按能力路由 | 按供应商写死 | 支持多供应商、快/深、降级与自定义 |
| D5 | 前端不接触密钥与网络 | 前端直连 API | 防泄露、统一超时/重试/费用统计 |
| D6 | 配置分组 + Schema 版本化 | 平铺 KV | 支持迁移、导入导出、向导复用 |
| D7 | 图片搜索走「视觉 + 联网搜索」 | 反查图搜 API | 截图理解场景命中率更高；反查留 P2 |
| D8 | 本地翻译模型不预装 | 随包分发 | 控制安装包 ≤ 25MB；按需下载 |

### 3.3 会话状态机

```text
Idle
  │ 热键/托盘「开始框选」
  ▼
Freezing（捕获 + 显示冻结层；同时启动前置 OCR）
  │ 覆盖层就绪
  ▼
Selecting（拖拽/微调；可取消）
  │ 抬起/回车
  ▼
Menu（按文字存在性展示动作；可重选/取消）
  │ 选择动作
  ▼
Executing（任务运行、流式输出；可取消）
  │ 完成 / 失败
  ▼
ShowingResult（结果窗；可追问、重答、重新框选）
  │ 关闭结果窗 / 新会话
  ▼
Idle

异常：任一步失败 → Error 态（展示原因与降级入口）→ Idle
```

约束：

- 同一时刻只允许一个活动会话；新会话自动取消旧会话。
- 前置 OCR 有独立 `ocr_session_id`，用户重选时复用缓存、仅按新选区过滤。
- 结果窗关闭后释放图像与流式连接；本地推理进程按空闲策略卸载。

## 4 关键流程设计

### 4.1 启动与托盘常驻

1. 解析命令行与 `portable.flag`，确定数据目录。
2. `single-instance` 插件检测；已有实例则唤起其设置/托盘提示后退出。
3. 加载配置（含 Schema 迁移）、初始化日志、读取凭据状态（不读取密钥明文到日志）。
4. 创建托盘图标与菜单（设置、重新引导、暂停热键、退出）。
5. 注册全局热键；失败则托盘气泡提示 + 打开设置的热键页。
6. 创建隐藏主窗口（承载设置/引导/结果窗），按需显示；不预创建冻结层。
7. 若配置了本地翻译且启用「常驻预热」，后台异步启动推理进程；否则首次使用时启动。
8. 空闲后再检查更新（稳定/预览通道），不阻塞启动。

### 4.2 框选主流程（时序）

```text

  │───────────────►│ 创建 session          │                       │
  │                │── capture.freeze ────►│ BitBlt/WGC 截取虚拟桌面 │
  │                │                       │── 返回 FrozenFrame ──►│
  │                │── showOverlay(frame) ─►│ 创建/复用覆盖窗口      │
  │◄── overlay.ready（含虚拟桌面矩形/DPR）  │                       │
  │                │── preOcr.start(frame)─►│ 降采样 det（后台）     │
  │ 用户拖拽        │                       │                       │
  │── selection ──►│ 坐标换算(物理像素)     │                       │
  │                │── filterBoxes ───────►│ 命中文字？             │
  │                │◄── presence ──────────│                       │
  │◄── menu.items（文本/图像动作）          │                       │
  │ 点击动作        │                       │                       │
  │───────────────►│ run_action(session, action, mode)             │
  │                │── actionRouter ──────►│ 解析引擎 + 降级链      │
  │                │                       │── LLM/Search/Translate ► 云端
  │◄── task.delta（流式）                  │                       │
  │◄── task.done（usage/latency）          │                       │
  │ 关闭结果窗      │                       │                       │
  │───────────────►│ release(session)      │ 释放图像、停止流、按需卸载│
```

### 4.3 前置 OCR 与文字判定

- **输入**：冻结快照（物理像素）、当前选区。
- **预扫描**：长边降采样至约 2560–3200px，仅跑检测（det），在后台线程执行；同时预热 ONNX 会话。
- **命中过滤**：取检测框中心/交集落在选区内、置信度 ≥ 阈值、覆盖面积占比 ≥ 阈值的行框；达到阈值判为「有文字」。
- **选区识别**：对选区原图（必要时 2× 放大）跑 det + rec，得到文本行、置信度、行框；返回可编辑文本。
- **缓存策略**：`ocr_session_id` 内缓存整屏检测结果；用户重选只重过滤，不重复推理；切换主题/翻页需重新捕获。
- **取消**：新会话或取消时作废旧 `ocr_session_id`，结果丢弃。

### 4.4 文本搜索

1. 取 OCR 文本（允许编辑）→ 生成搜索词（可配置模板/提示词）。
2. 按 `search.mode`：
   - `browser`：拼 URL（Bing/Google/百度/DuckDuckGo/自定义），打开系统默认浏览器；不产生 API 费用。
   - `ai`：调 DeepSeek Search（`/v1/tools/search`，`count`、`need_content`）→ 取 `summary/snippet/url` → LLM 生成「结论 + 来源列表」；深度模式追加 Fetch 前 N 篇。
3. 结果窗展示结论与来源；失败时自动回退浏览器搜索并提示。

### 4.5 图片搜索

1. 兼容路径：选区图（可选压缩/降采样，长边 ≤ 1600px）→ 视觉模型。
2. 视觉模型输出结构化结果：识别内容、1–3 个检索词、置信度、可选 `site:`/`lang:` 运算符。
3. 搜索网关执行检索（快速 1 次；深度 2–3 次 + 抓取），汇总为「识别结果 / 搜索结论 / 来源」。
4. 若视觉识别置信度低：优先展示识别标签与「在浏览器以图搜图」入口，不强行给结论。
5. 失败回退：仅展示视觉识别结果 + 可复制文本。

### 4.6 翻译

1. 输入：OCR 文本（可选）或图片（P2 图片翻译）。
2. 按 `translate.backend` 选择：
   - **云端**：通用 LLM（提示词约束「只输出译文、保留格式、术语表」）或专用翻译模型（Qwen-MT，`translation_options` 指定源/目标语言）。
   - **本地**：llama.cpp/Ollama（GGUF 模型，流式）；低配降级 CTranslate2（OPUS-MT/NLLB，非流式）。
3. 切分与流式：按段落/句切分，逐段请求并拼接；结果窗支持原文/译文对照（P1）。
4. 回退链：本地失败 → 云端 → 提示；云端失败 → 本地（若已下载）→ 提示。

### 4.7 解答与追问

- 输入：OCR 文本 + 可选原图（是否上传受隐私开关控制）。
- 模式：快速（关思考、短输出）/ 深度（开思考、多步检索、输出 ≤ 1500 字）。
- 追问：在结果窗内追加消息，携带会话上下文（文本摘要 + 最近图像，受开关约束）。
- 输出标注：结果窗固定展示「AI 生成」与所用引擎、耗时。

### 4.8 首启引导

- 触发：`onboarding.completed == false`，或用户从托盘/设置重开。
- 六步：欢迎语言 → AI 服务（URL/Key/测试连接）→ 翻译方式（云/本地 + 模型下载）→ 快/深默认 → 外观与热键 → 隐私与完成。
- 数据：每步校验并即时保存草稿；最终写入配置并置 `onboarding.version`。
- 跳过：进入受限模式（仅本地 OCR + 浏览器搜索 + 已就绪的本地翻译），设置页可补齐。
- 安装器联动：NSIS「完成后运行」自动拉起；便携版首启同样触发。

### 4.9 本地模型下载与切换

1. 读取模型清单（内置 manifest + 远端 manifest，签名校验可选）。
2. 选择模型 → 检查磁盘（大小 + 20%）与内存 → 创建下载任务。
3. 下载：HTTP Range 断点续传，HuggingFace/ModelScope 镜像回退，失败重试 3 次。
4. 校验：SHA256 与文件大小；失败删除重试。
5. 安装：写入 `models/<id>/`，更新配置与清单状态；启动/重启推理进程并试译一句。
6. 删除/切换：停止进程 → 删除或改配置 → 重启 → 通知 UI。

### 4.10 配置变更与热生效

- 变更经 `ConfigPatch` 校验（类型、范围、URL 白名单）。
- 热生效分类：
  - 即时：外观、提示词、动作菜单、搜索模式、快/深默认。
  - 重新注册：热键、开机自启。
  - 需重启引擎：切换本地模型、修改本地引擎端口/路径。
  - 需重启应用（极少）：数据目录迁移。
- 全部变更广播 `config.changed`，前端只重渲染受影响区域。

### 5.3 外部 AI 接口约定

**LLM（OpenAI 兼容）**

```http
POST {baseUrl}/v1/chat/completions
Authorization: Bearer <key>
Content-Type: application/json

{
  "model": "deepseek-flash",
  "messages": [{"role":"system","content":"..."},{"role":"user","content":"..."}],
  "stream": true,
  "temperature": 0.2,
  "max_tokens": 512,
  "tools": [ /* 可选：搜索/抓取工具 */ ]
}
```

- 流式解析 `data:` 行；`[DONE]` 结束。
- 思考开关：支持时传 `thinking: {"type":"disabled"}`（参数名以供应商文档为准；不支持则忽略）。
- 多模态：`content` 数组含 `{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}`。
- 失败重试：仅对 429/5xx/超时重试，指数退避（最多 2 次）；401/402 不重试。

**DeepSeek Search / Fetch**

```http
POST https://api.deepseek.com/v1/tools/search
{ "query": "...", "count": 5, "need_content": false, "ori_question": "..." }

POST https://api.deepseek.com/v1/tools/fetch
{ "url": "https://..." }
```

- 结果字段：`title/url/snippet/summary/content/site_name/date/authority`。
- 计费按成功请求；失败/空结果不计费（用于费用估算）。

**Qwen-MT（专用翻译，OpenAI 兼容）**

```http
POST {baseUrl}/v1/chat/completions
{ "model": "qwen-mt-lite", "messages": [...], "translation_options": {"source_lang":"auto","target_lang":"English"} }
```

### 5.4 本地推理接口

- **llama.cpp / Ollama**：统一作为 OpenAI 兼容端点（`http://127.0.0.1:<port>/v1/chat/completions`），由引擎管理器拉起与健康检查。
- **CTranslate2（低配兜底）**：进程内 FFI（`ct2rs`）或独立 worker，非流式，按句返回。
- 端口策略：优先固定端口段（如 39281–39289）探测空闲；仅绑定 `127.0.0.1`。

### 5.5 接口错误约定

统一错误结构：


| --- | --- | --- |
| 捕获/UI | SA-10xx | SA-1001 捕获失败、SA-1002 覆盖层创建失败、SA-1003 热键冲突 |

```sql
);

CREATE TABLE tasks(
  id TEXT PRIMARY KEY, session_id TEXT, action TEXT, mode TEXT,
```

- 显示为「本月估算花费」，粒度到动作类型。

## 7 异常处理与降级

### 7.1 错误处理策略

| 场景 | 策略 |
| --- | --- |
| 捕获失败/黑屏 | 提示原因（DRM/全屏/权限），提供 WGC 切换与重试 |
| 前置 OCR 超时 | 放弃预扫描，直接按选区识别；菜单先显示「识别中」 |
| 文字识别为空 | 自动切图像动作；提供「强制文本模式」 |
| 网络不可用 | 云端动作置灰并提示；可用本地 OCR/本地翻译与浏览器搜索 |
| 鉴权/额度 | 不重试；引导到设置页更换 Key/充值；保留本地能力 |
| 限流/超时 | 指数退避重试 2 次；仍失败则降级 |
| 本地模型缺失 | 引导下载；或切换云端；或使用低配模型 |
| 内存不足 | 拒绝加载大模型，推荐轻量档；释放缓存 |
| 下载失败/校验失败 | 自动重试 + 镜像回退；失败提示手动下载路径 |
| 配置非法 | 拒绝保存并定位字段；保留上一份有效配置备份 |

### 7.2 降级链

| 动作 | 主路径 | 降级 1 | 降级 2 | 最终 |
| --- | --- | --- | --- | --- |
| 文本搜索 | AI 搜索（DeepSeek） | 浏览器搜索 | — | 复制文本 |
| 图片搜索 | 视觉 + 联网 | 仅视觉识别 + 来源链接 | 浏览器以图搜图 | 复制识别文本 |
| 翻译 | 云端（LLM/Qwen-MT） | 本地模型（若已装） | 另一云端供应商 | 提示失败 |
| 解答 | 云端多模态 | 纯文本（无原图） | 本地模型（仅文本） | 提示失败 |

### 7.3 日志与诊断

- 分级：`error/warn/info/debug`；默认 `info`，不记录输入文本内容与密钥。
- 崩溃：托盘守护 + 再次启动检测未正常退出标记；生成脱敏诊断包（可选，用户确认后导出）。
- 无遥测；更新检查仅上报版本号（可关闭）。

## 8 性能与轻量化设计

### 8.1 性能预算

| 阶段 | 预算 | 手段 |
| --- | --- | --- |
| 冷启动 | ≤ 1.5s | 延迟创建 WebView/覆盖层；配置与日志并行；跳过更新检查到空闲期 |
| 常驻召出 | ≤ 200ms | 复用已加载窗口与 WebView；热键回调直通 |
| 捕获 + 冻结 | ≤ 150ms | BitBlt 整屏一次；编码/上传异步；复用缓冲区 |
| 动作菜单 | ≤ 100ms | 预扫描结果缓存；菜单纯前端渲染 |
| 前置 OCR 检测 | ≤ 1.2s（后台） | 降采样 det；单 worker；可取消 |
| 选区 OCR | ≤ 800ms | 小图 det+rec；2× 放大仅在检测失败时启用 |
| 首 token（快速） | ≤ 1.5s | 流式；关闭思考；短提示词；连接复用 |
| 本地翻译（1.8B Q4） | 3–8s（200 字，CPU） | GGUF 量化；可选 GPU；预热 |

### 8.2 内存与 CPU

- 空闲目标 ≤ 120MB：常驻仅托盘 + 隐藏窗口；不持有截图；OCR 会话结束即释放。
- 结果窗关闭释放流与图像；WebView 按需创建，空闲超时销毁（可配置）。
- 本地推理进程空闲 `idleUnloadSec` 后卸载；再次使用时冷启动并提示。
- 空闲 CPU < 0.5%：不用轮询；热键由系统回调；无定时器常驻（仅更新检查等低频任务）。

### 8.3 安装包体积

- 主包只带：Tauri 运行时、前端资源、OCR 运行时与模型（含 OCR 模型 ≤ 60MB；主包 ≤ 25MB 不含）。
- 翻译模型外置下载；llama.cpp 运行时随包（数 MB），GPU 后端按需下载（P2）。
- 资源压缩、去除 sourcemap、按需裁剪图标与语言。

### 8.4 轻量化验证方法

- 启动计时：`main()` → 托盘就绪；热键 → `overlay.ready`；由埋点（本地，不上传）记录。
- 内存：Windows 任务管理器 + 内置 `app_stats`；长时压测 8 小时。
- 安装包：CI 产物体积门禁（超过阈值告警）。

## 9 安全与隐私设计

### 9.1 密钥与配置

- 密钥仅保存于 Credential Manager，不进入配置文件、日志、崩溃报告。
- UI 仅显示掩码；粘贴后不可回显。
- 配置导出默认不含密钥；导入时校验 Schema 并提示覆盖范围。

### 9.2 网络与上传

- 仅允许 HTTPS；本地引擎允许 `http://127.0.0.1`。
- 上传策略：文本/图像分别有开关（默认开，首启说明）；关闭后对应动作禁用并解释。
- 图片压缩（长边 ≤ 1600px）后再上传，降低隐私暴露与费用。
- 不代理、不中转用户请求；直连供应商。

### 9.3 完整性

- 模型下载校验 SHA256；远端清单可选签名。
- 更新包签名校验（`tauri-plugin-updater` 公钥）。
- 本地推理端口仅绑定回环地址，随机端口 + 简单握手令牌（可选）。

### 9.4 隐私声明要点

- 截图/文本仅在用户触发动作时发送给其自选供应商；
- 本地模式不上传；
- 历史仅本地存储，可清空；
- 无遥测、无账号体系。
